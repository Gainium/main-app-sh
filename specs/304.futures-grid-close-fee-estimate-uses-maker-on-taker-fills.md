# 304 — A futures grid close with no observed fee is estimated at the maker rate even when it took liquidity

Bug spec (Definition / Evidence / Assumption). Follows spec 276.

## §1 Definition

### §1.1 Expected

When a futures grid position close (`profitAfterPositionClosed`) or a
liquidation (`processLiquidationOrder`) has no observed fee to book
(`closeLegFeeQuote`: the bot does not book observed fees, or
`observedFeeSplit` resolves none — no `feePaid`, or a fee in an asset off the
pair), the estimated fee is `price × qty × estimatedFeeRate(order, userFee)`:

- §1.1.1 the taker rate for a close that took liquidity — sent as MARKET, or
  a LIMIT that filled on arrival (`filledOnArrival`, spec 243), i.e.
  `tradedAsTaker`;
- §1.1.2 the maker rate for a resting LIMIT close.

### §1.2 Actual

The fallback always used `userFee.maker`, so a MARKET close (the default
close type of the grid TP/SL, `tpSlLimit`/`slLimit` off) or an on-arrival
LIMIT close booked (taker − maker) × notional too little fee and overstated
profit.

### §1.3 Unchanged

- A close whose observed fee resolves keeps booking that fee (spec 276 §1.1).
- A resting LIMIT close keeps the maker rate.
- The spec-276 form: the fee is subtracted from the notional PnL.

## §2 Evidence

- The close is sent as `MARKET` unless `tpSlLimit` (TP) / `slLimit` (SL) is
  set (`helper.ts`, the `closeByTp` order type); the stored order keeps
  `type: MARKET` (`placedOrderRecord`).
- Production grid-bot logs show the stop-fill path (`Stop order filled.
  Processing stop...`) running thousands of times a day.
- In the spec-303 prod set, Bybit linear closes whose fee had no asset
  divided by their notional match the account's taker rate exactly, and a
  running bot's unresolved close was a MARKET order: the fallback is reached
  on taker fills.

## §3 Assumption

The root cause is the hard-coded `.maker` in `closeLegFeeQuote`. Core already
has `estimatedFeeRate` (`placedOrderType.ts`), used for the same estimate by
the DCA/combo fee paths and by the spec-303 restatement; using it here makes
the live booking agree with that restatement.
