# 213 — a deal cancelled in start hides an entry the venue executed

Bug spec (SKILL.md Part 0). Scope: `src/bot/dca/dealOutcome.ts`,
`src/bot/dcaHelper.ts` (`announceLeftOpenPosition`,
`dealCloseEventDescription`), `src/bot/main.ts` (`_runUnknownOrderLadder`
write-off).

## §1 Definition

### §1.1 Expected

- §1.1.1 When a deal that is still in `start` is cancelled (bot stopped with
  `leave`, deal cancelled by hand), and its base order — or a replaced base
  order — already executed on the venue, the user is told a position was left
  open, with its size, exactly as for a deal that had booked its base.
- §1.1.2 When the unknown-order ladder gives up on an order the venue
  acknowledged and whose row records its full size executed, the row says it
  filled.

### §1.2 Actual

- §1.2.1 The left-open warning and the deal event key off `deal.size`, which is
  0 until the base order is booked. A start deal whose fill was missed is
  reported as a bare `Deal cancelled, id: …`, no warning, while the position
  stays on the venue with no take profit and no stop loss.
- §1.2.2 The ladder's write-off stamps CANCELED over whatever the row said,
  including an acknowledged order with `executedQty === origQty` and a row
  already FILLED.

## §2 Evidence

- Production, Kraken linear futures, DCA bots stopped with `leave` while
  their deals sat in start: deal events read `Deal cancelled, id: …` with no
  position named; the deals were stored `canceled`, size 0; the venue position
  afterwards held the full base-order sizes. The one deal of the same session
  that had booked its base produced the full "position left open" warning.
- One base-order row was stored `CANCELED` with `executedQty` equal to
  `origQty` and a real venue id, written by the ladder's DB branch
  (`Order found in DB in handle unknow order … set to CANCELED`).

## §3 Assumption (root cause, hypothesis)

`deal.size` is not where an unbooked entry lives — the entry rows are. Summing
the executed quantity of the deal's acknowledged `dealStart` rows, for a deal
with no booked level, gives the position left behind. The write-off is a
status decision that ignored the row's own quantities.

## §4 Requirements

- §4.1 `unbookedEntryQty(levelsComplete, rows)`: sum of `executedQty` over
  `dealStart` rows with a real venue id; 0 once a level is booked.
- §4.2 The cancel event and the `leave` warning use `deal.size`, or §4.1 when
  that is 0; the order rows are read only in that case.
- §4.3 `writeOffStatus(row)`: FILLED stays FILLED; an acknowledged row with
  `executedQty >= origQty > 0` is FILLED; everything else CANCELED (as before).
- §4.4 `'-1'` rows never count and never promote — their quantities are not
  evidence of a trade.
