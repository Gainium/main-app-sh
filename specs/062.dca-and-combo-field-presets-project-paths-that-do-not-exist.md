# 062 — DCA and combo field presets project paths that do not exist

Same defect as [061](061.grid-bot-field-presets-project-paths-that-do-not-exist.md),
on the presets that spec deliberately left out of scope (§4.2): `bots.dca`,
`bots.combo` and `deals.dca` / `deals.combo`.

## §1 Definition

`GET /api/v2/bots/dca`, `/bots/combo`, `/deals/dca`, `/deals/combo` and
`/deals/terminal` turn the requested preset into a MongoDB projection verbatim
(`parseFieldsParam` → `buildProjection` → `<db>.readData`, wired by
`fieldSelectionMiddlewares` at `core/src/server/v2/api.ts:254`, `:357`, `:463`,
`:634`). A projected path that does not exist on the stored document is simply
absent from the response — no error, no warning.

### §1.1 Expected

- `fields=standard` on a DCA or combo bot returns its **creation and update
  timestamps**, the way the `bots.grid` preset does since 061.
- `fields=extended` additionally returns the settings it names: the **stop
  loss**, the **trailing configuration** and the **safety-order count** — the
  values a caller needs in order to read a bot, adjust a few and create the
  adjusted copy through `POST /api/v2/bots/dca` (`api.ts:2229`) or
  `/bots/combo` (`api.ts:2327`).
- `fields=extended` on a deal returns its **safety order size** and **safety
  order count**.

### §1.2 Actual

`fields=standard` returns **no timestamps at all** for every DCA and combo bot.
`fields=extended` additionally resolves **none** of `settings.stopLoss`,
`settings.trailingDeviation`, `settings.maxSafetyTradesCount` — three of the
four settings it claims — so the only setting a caller gets back is
`settings.baseOrderSize`. On a deal, `fields=extended` resolves neither
`settings.safetyOrderSize` nor `settings.maxSafetyTradesCount`.

Because `POST /api/v2/bots/dca` merges the request body over
`DCA_FORM_DEFAULTS` (`botDefaults.ts:70`), every settings field the caller
could not read back arrives as **undefined** and is silently replaced by the
platform default: `useSl: false`, `slPerc: '-10'`, `trailingTp: false`,
`trailingTpPerc: '0.3'`, `trailingSl: false`, `ordersCount: 5`,
`activeOrdersCount: 1`. A read-modify-create round trip therefore disarms the
source bot's stop loss and trailing exits and resets its safety-order ladder,
with no error to the caller — the same mechanism as 061, on a much larger
fleet.

Every count above is a full-collection aggregation, not a sample: one pass per
collection summing `{$type: "$<path>"} != "missing"` over every document.

`settings.name`, `settings.pair`, `settings.baseOrderSize`, `profit.*`,
`deals.*`, `cost`, `profitToday` and `dealsStatsForBot` resolve on every
document; `workingTimeNumber` (41 414 / 46 049) and `statusReason`
(10 256 / 46 049) resolve on some. Both spellings are correct — an optional
field that is absent because it does not apply is not this defect. The rest of
each preset is fine.

`settings.trailingTp` (25 541 / 46 049) and `settings.trailingSl`
(25 444 / 46 049) are *optional booleans*, absent on bots predating the
feature. That is not the same defect: an absent optional boolean means `false`,
which is exactly what `DCA_FORM_DEFAULTS` supplies on the way back in, so the
round trip is still lossless. `settings.stopLoss` and friends are absent on
**every** document because no such path has ever existed.

### §2.2 The read path reproduces it against real documents

`tests/scratch/bug829-repro.ts` (main-app, private repo) inserts a DCA bot, a
combo bot and a DCA deal built from `DCA_FORM_DEFAULTS` / `COMBO_FORM_DEFAULTS`
through the real mongoose models, then calls the exact chain the handlers use
(`parseFieldsParam(preset, endpoint)` → `buildProjection` → `<db>.readData`)
against local Mongo. Observed before the change:

```
--- bots.dca   fields=standard ---
  settings in resp: {"name":"Repro DCA","pair":["BTC_USDT"]}
  UNRESOLVED      : createdAt, updatedAt

--- bots.dca   fields=extended ---
  settings in resp: {"name":"Repro DCA","pair":["BTC_USDT"],"baseOrderSize":"10"}
  UNRESOLVED      : createdAt, updatedAt, settings.stopLoss,
                    settings.trailingDeviation, settings.maxSafetyTradesCount
```

### §2.3 The names the schema actually uses

`DCABotSettings` (`core/types.ts:757`) declares no `stopLoss`, no
`trailingDeviation` and no `maxSafetyTradesCount`. The stop loss is
`useSl: boolean` + `slPerc: string`; the trailing take profit is
`trailingTp: boolean` + `trailingTpPerc: string`, with `trailingSl: boolean`
for the trailing stop loss; the safety-order ladder is `ordersCount: number`
(maximum safety trades) + `activeOrdersCount: number` (how many rest on the
book at once). `bot/utils.ts:1161` confirms the pairing — `trailingTpPerc` is
required only when `trailingTp` is set, and `trailingSl` is validated
separately at `:1071`.

### §2.4 What the evidence does NOT establish

No production request log exists for the v2 API, so no caller was observed
performing the round trip. What is proven is what 061 proved for grid: the
presets do not return the fields they name.

## §3 Assumption

*Hypothesis, not fact.* The five names were written from an imagined bot shape
when the v2 field-selection feature was first authored (`f036f2d`, 2026-02-17,
"wip: api v2") and never compared to a stored document — the same authoring
mistake 061 found in the grid presets, in the same commit. The fix is to name
the paths the schema uses, pairing each value with the boolean that governs it
so the round trip is lossless. No behaviour outside `fieldConfig.ts` changes.

## §4 Scope

### §4.1 In scope

`DCA_BOT_STANDARD_FIELDS`, `COMBO_BOT_STANDARD_FIELDS`,
`DCA_BOT_EXTENDED_FIELDS`, `COMBO_BOT_EXTENDED_FIELDS` and
`DCA_DEAL_EXTENDED_FIELDS` (which `COMBO_DEAL_EXTENDED_FIELDS` aliases), plus
the hand-maintained preset prose in `openapi-v2.yaml`.

### §4.2 Out of scope

`GET /api/v2/bots/:botType/details` resolves `fields` against the `bots.dca`
config for **every** non-hedge bot type (`api.ts:1240`, comment "field presets
are the same across all bot types"). Since 061 that is no longer true: a grid
bot fetched through `/details` is projected with DCA paths and returns none of
its grid definition. Separate defect, separate fix — tracked on its own.

## §5 Contract

`/api/v2/*` is the public `api.gainium.io` contract (root Danger List #2). The
change is **additive on the wire**: every name removed from a preset is a path
that resolved on zero documents, so no consumer can be reading it today; the
names added resolve on every stored document. `fields=full` and explicit
comma-separated field lists do not go through the preset table and are
unaffected.
