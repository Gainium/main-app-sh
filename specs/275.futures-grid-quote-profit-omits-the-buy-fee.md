# 275 — A futures grid's quote profit omits the buy fee

Bug spec.

## §1 Definition

### §1.1 Expected

A futures grid bot whose profit is kept in the quote asset (USDⓈ-M; coin-M
bots carry `profitCurrency: 'quote'` too) subtracts the trading fee of every
grid fill from `profit.total` and `profit.freeTotal`: the sell fill's fee and
the buy fill's fee. The running `cummulativeProfitQuote` written on each
transaction row follows the same total.

### §1.2 Actual

`createTransaction` books a BUY fill's fee in base (`comBase`, the qty × rate
estimate or the observed fee converted to base) and leaves `comQuote` at 0.
That is the shape `orderFee.ts` documents and the rest of the path relies on.
Spot paths convert the buy fee to quote before the totals are updated; the
futures branch (`this.profitBase || this.futures`) converts only a sell's fee
(to base). The quote totals then subtract `comQuote`, so a buy leg's fee was
subtracted as 0 and stayed in `profit.total`, `profit.freeTotal` and the
row's `cummulativeProfitQuote`.

### §1.3 Unchanged

The USD figure (`totalUsd` / `freeTotalUsd`) already used
`comQuote === 0 ? comBase * price : comQuote` and is unchanged. The row's
`feeBase` / `feeQuote` and the `feePaid` ledger keep their shape (a buy's fee
in base only), so nothing that reads them changes.

Out of scope: base-profit totals (they subtract `comBase`, which both sides
carry on futures); spot bots; the fee booked by the position close
(`profitAfterPositionClosed`), which is a separate mechanism.

## §2 Evidence

Production, Bybit USDⓈ-M, NEUTRAL futures grid, one round trip (identifiers
withheld, because this file is public):

- SELL 15 @ 0.07581, venue fee 0.00022743 quote. Row: `feeQuote` 0.00022743.
- BUY 15 @ 0.07498, venue fee 0.00022494 quote (`feeSide: quote`). Row:
  `feeQuote` 0, `feeBase` 0.003 (= 0.00022494 / 0.07498), `profitQuote`
  0.01245.
- `profit.total` = `freeTotal` = 0.01222257 = 0.01245 − 0.00022743: the buy's
  fee is missing. `totalUsd` takes both out.
- The BUY row's `cummulativeProfitQuote` is the previous row's plus exactly
  `profitQuote`; the same step holds on most recent futures BUY rows.

The test harness reproduces 0.01222257 exactly from those two fills.

## §3 Assumption (root cause)

The quote-total update reads `comQuote` directly, and on a futures BUY leg it
is 0 by construction. Converting the base-held fee at the fill price — the
conversion `totalQuote` already makes — for futures bots only is the fix;
spot paths already hold a non-zero `comQuote` on both sides, so they are not
changed.

## §4 Fix

`feeQuoteInProfit = this.futures && comQuote === 0 ? comBase * price : comQuote`,
used in place of `comQuote` in the quote branch of `profit.total`,
`profit.freeTotal` and the row's `cummulativeProfitQuote`.

Past totals are restated by the parent repo's one-off
`scripts/restateFuturesGridBuyFees.ts` (dry run by default): it subtracts
Σ feeBase × priceBuy over the pre-fix BUY rows described in §1.2. It is a
delta, not a rebuild, because `profit.total` also carries close legs booked
without rows.

## Invariants

- A futures quote-profit BUY row whose running cumulative stepped by exactly
  its `profitQuote` while it carries a base fee: the buy fee was left in the
  total. Pack: parent repo `specs/invariants/grid.invariants.json`,
  `grid.futures-buy-fee-left-in-quote-profit` (observe).

## §5 Tests

`src/bot/gridFuturesBuyFeeProfit.spec.ts` — §1.1 totals and cumulative take
out both fees; §1.3 USD, row fee fields and `feePaid` unchanged; both with
and without the observed-fee flag.
