# 147 — the self-hosted API serves the broker-codes feed

Bug spec.

## 1. Definition

### 1.1 Expected
`GET /broker-codes` on this server returns the `brokerCodes` collection as a
JSON array of `{ exchange, code, zone? }`, the same shape the hosted API
returns:

- §1.1.1 without `?v=2`, only rows with no `zone`;
- §1.1.2 with `?v=2`, every row, zoned ones included;
- §1.1.3 when the read fails, an empty array with status 400.

The dashboard's Hyperliquid wallet setup reads this route from its own
`VITE_API_ENDPOINT`. When the account needs builder-fee approval, it picks the
`hyperliquid` row's `code` as the builder address and asks the wallet to sign
`approveBuilderFee`.

### 1.2 Actual
This server never registered the route. The request falls through to the
GraphQL middleware mounted at `/`, which answers `400 {"errors":[…CSRF…]}`.
That body is not an array, so the dashboard's lookup throws inside its
`.catch`, resolves to `undefined`, and stops the setup with "could not reach
its server". The wallet is never asked to approve the fee.

## 2. Evidence

- Code: `src/server/index.ts` has no `/broker-codes` handler (absent since the
  first public commit). The hosted API defines it in the private parent
  repository's own server, which self-hosted images do not run. The
  self-hosted compose `api` service runs `npm run server`, which is this
  server.
- The data is present on a self-hosted instance: `updateBrokerCodes` in
  `src/utils/cron/exchange.ts` copies the hosted feed (`?v=2`) into
  `brokerCodes`, including both `hyperliquid` rows.
- Runtime: this server built and started locally, `GET /broker-codes` returns
  `400 {"errors":[{"message":"This operation has been blocked as a potential
  Cross-Site Request Forgery …"}]}`.
- Onset: the dashboard used to treat a missing builder address as success, so
  it skipped the approval without saying so. Since it started failing loudly
  on a missing address, setup on self-hosted stops at this step.

## 3. Assumption (hypothesis)
Registering the route here, before the GraphQL catch-all and reading the
`brokerCodes` rows the cron already maintains, is enough for the setup to get
a builder address. The hosted API is unaffected because it runs its own server
entry, not this file.
