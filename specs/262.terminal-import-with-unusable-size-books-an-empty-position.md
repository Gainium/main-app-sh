# 262 — A terminal "import position" deal with an unusable size books an empty position

Bug spec (Definition / Evidence / Assumption).

## §1 Definition

§1.1 A terminal deal of type *import* adopts a position the user already holds. It places no
entry order: `getBaseOrder` writes a synthetic base order row (`orderId: '-1'`, status
`FILLED`) whose quantity is the user's configured size (`baseOrderSize`, in base or quote)
converted at the configured entry price (`baseOrderPrice`) and rounded down to the pair's
quantity step, through `getSmartSellOrderQty`. `startDeal` then books the deal from that row.

§1.2 Actual: when the size and price give no usable quantity, the row is still written as
FILLED and the deal is still started:

- §1.2.1 a quote size below one quantity step at that price rounds down to `0`;
- §1.2.2 an entry price of `0` on an inverse (COIN-M) pair divides by zero; the rounding turns
  the resulting `Infinity` into `NaN`.

On futures, `getAvgPrice` folds the entries through `calculateAbstractPosition`, which divides
by the running quantity: a first entry of 0 makes the average `0 / 0 = NaN`, and every later
fill carries that NaN on. `startDeal` writes it to `displayAvg`, mongoose refuses the save
(`Cast to Number failed for value "NaN" at path "displayAvg"`), and the deal stays in `start`
in the database while the worker holds it as `open` and arms take profits for a position of 0.
Every worker restart replays `startDeal` on the FILLED row and fails the same way. The
stuck-start sweep cannot retire it either: its cancel is a save of the same document.

§1.3 Expected:

- §1.3.1 An import whose configured size and price do not give a finite quantity above zero,
  at a finite price above zero, is refused before any order row is written. The user is told
  why in a bot message, and the deal created for it is retired instead of left in `start`.
- §1.3.2 A deal already holding such a synthetic row (written before this fix) is retired when
  the engine next replays it, rather than opened.
- §1.3.3 The futures average of a deal ignores entry rows whose quantity is not a finite number
  above zero: such a row moved nothing. An average that still comes out non-finite is reported
  as `0`, as the spot branch already does; `startDeal` then falls back for `displayAvg` exactly
  as it already does for `avgPrice`.

§1.4 Unchanged: imports whose size and price give a real quantity (same row, same sizing, same
averages), every other deal type, and the averages of every deal whose entries all moved
something (skipping a zero-quantity row does not change a finite fold).

## §2 Evidence

- Runtime: repeated `Error saving deal … CastError … at path "displayAvg"` warnings, every one
  on a futures terminal import deal. Each deal's base order row is `orderId -1`, `FILLED`, with
  `origQty`/`executedQty` `"0"` (linear, quote size 10 at ~77k, step 0.001) or `"NaN"` (inverse,
  price `"0"`).
- On a live account a deal of this shape arms take profits for a position the account does not
  hold.
- Code: `getSmartSellOrderQty` computes the size from settings only and rounds down;
  `getBaseOrder`'s import branch never checks the result; `getAvgPrice`'s futures branch has no
  NaN guard while its spot branch does.

## §3 Assumption

The quantity in the synthetic row is the only source of the NaN: with it guarded at the import
branch and skipped in the futures fold, `getAvgPrice` returns finite values for every deal of
this shape, and the save goes through.

## §4 Tests

`src/bot/dca/importEntry.spec.ts` (pure predicate) and
`src/bot/dca/importEntry.harness.spec.ts` (real `dcaHelper` on a fake base):

- §1.2.1 / §1.3.1 linear import, quote size below one step: no order built, user told.
- §1.2.2 / §1.3.1 inverse import, price 0: no order built, user told.
- §1.4 linear import with a usable size: same synthetic row as before.
- §1.3.2 `startDeal` on a stored 0-quantity import row retires the deal and does not open it.
- §1.3.3 futures average skips a 0 row and stays finite; a usable fold is unchanged.

## Invariants

`dcadeals` in `start` or `open` for a terminal import whose base order row moved nothing (no
`dealStart` row with an executed quantity above zero): pack
`main-app specs/invariants/deals.invariants.json`, id `deals.import-empty-entry`.
