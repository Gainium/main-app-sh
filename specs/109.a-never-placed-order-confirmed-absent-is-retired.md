# 109 — A never-placed order the venue confirms absent is retired, not held forever

A placement the venue refused, but whose outcome the engine read as ambiguous,
is kept as `status: NEW`, `orderId: '-1'` for the reconcile path to settle. On
KuCoin the reconcile could never settle it: KuCoin's lookup answer for a
missing order, `validation.queryOrder.orderNotExist | 400100`, matched none of
the definitive not-found wordings, so every reconcile asked again and logged
"Cannot get order". And where a venue's answer WAS definitive, the reconcile
only quarantined the order — it stopped asking but kept it in memory as
resting. A never-placed take-profit held that way is a deal that believes it
has an exit it does not have.

## §1 Definition

### §1.1 Expected

- **§1.1.1** `isDefinitiveOrderNotFound` reads KuCoin `queryOrder.orderNotExist`
  as a definitive not-found.
- **§1.1.2** About an order handed to the venue seconds ago (the placement
  ladder's `justPlaced`, and the fee-sizing fallback after an ambiguous
  attempt) that answer is NOT trusted, exactly as Hyperliquid's `unknownOid`
  is not: the full ladder runs and the order is held for reconcile.
- **§1.1.3** A reconcile that gets a definitive not-found for an order that
  never received an exchange id (`orderId: '-1'`) and is past the quarantine
  age floor (`BOT_ORDER_QUARANTINE_MIN_AGE_MS`, 24h) retires it: `CANCELED` in
  the database, removed from the bot's order map.
- **§1.1.4** An order that HAS an exchange id is never retired this way; it is
  quarantined as before.
