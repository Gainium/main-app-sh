# 247 — The hourly stuck-start sweep scans every DCA deal

Bug spec (see `.claude/skills/gainium-dev-flow`, Part 0).

## §1 Definition

### §1.1 Expected

`closeOldStartDeals` reads its DCA candidates with `oldStartDcaDealsFilter`
(`src/bot/dca/oldStartDealsFilter.ts`): `status: 'start'`, `createTime` older
than a day, minus terminal limit-entry deals (spec 121). Only a handful of deals
are ever in `start`, so the read should walk only those.

### §1.2 Actual

No `dcadeals` index can serve the query: every declared index leads with
`userId`, and the sweep has no `userId`. Every run reads the whole collection.

## §2 Evidence

- Production explain, read-only (2026-11-21, two runs): `COLLSCAN`, ~2.66M
  documents examined, 14 returned, 1.2–1.4 s. 27–30 deals in `start` in total.
  `createTime` is stored as an epoch number, which the filter also uses.
- Local Mongo, with the indexes `syncIndexes()` builds from this schema
  (200k seeded deals): `IXSCAN` on `createTime_1`, 26 keys/docs examined, 23
  returned, the same ids as a forced `$natural` scan.
- Production cron log shows the sweep runs hourly
  (`Closing old start deals | found 14 DCA deals to close`).
- The mongo-index monitor has reported the shape
  `{$nor, createTime:{$lt}, status}` on `dcadeals` as a COLLSCAN since 2026-08-11.

## §3 Assumption

The collection lacks an index whose leading key the sweep's predicate can bound.
A partial index `{createTime: 1}` with `partialFilterExpression {status:'start'}`
is eligible for this query (its `status: 'start'` equality implies the filter),
bounds `createTime: {$lt}`, and holds only deals in `start`.

## §4 Requirements

- §4.1 `dcaDeal` declares `{createTime: 1}` partial on `{status: 'start'}`.
- §4.2 The sweep's filter is unchanged — which deals it selects stays exactly
  the same (spec 121's `$nor` stays).
- §4.3 On a real Mongo with the indexes `syncIndexes()` builds, the sweep's
  query plans as `IXSCAN` on that index and returns the same deals as a forced
  `$natural` scan.

## Invariants

None. This is a query-plan change; it leaves no wrong state in data.
