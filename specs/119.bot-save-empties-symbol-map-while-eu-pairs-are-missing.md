# 119 — A bot save can empty its `symbol` map while OKX Europe pairs are missing

Bug spec (Definition / Evidence / Assumption), plus plan and blast radius.

## §1 Definition

- **Expected.** A bot's `symbol` map always covers the pairs in its
  `settings.pair`. A bot list containing one inconsistent bot still renders.
- **Actual.** A multi-pair okxLinear bot trading OKX Europe X-Perps
  (`*-USD_UM_XPERP`) was saved while those pairs were absent from the `pairs`
  collection. The save persisted an empty `symbol` map next to a full
  `settings.pair`. The V2 bot list transform (`transformDcaBotToBot`) reads
  `symbol[0].value` unguarded, so the whole Trading Bots page crashed with
  `Cannot read properties of undefined (reading 'value')`.

## §2 Save path (`changeDCABot` / `changeComboBot`)

§2.1 A pair in the new `settings.pair` that the `pairs` collection does not
return keeps the entry the bot already had for it.
§2.2 An empty map is never written; `symbol` is left as stored.
§2.3 Unchanged: a pair removed from the bot leaves the map; a newly added pair
that is known nowhere is not invented.

## §3 Global pairs sync (`updateExchangeInfo`)

The global sync reconciles `pairs` for an exchange id against the public
instrument feed. OKX Europe docs (`source: 'my'`) share the `okx` / `okxLinear`
ids (and their paper twins) but are owned by `reconcileEuPairs`; the public
feed never lists them. §3.1 The global sync must neither delete, update nor
shadow `source: 'my'` docs. Global docs are still created, updated and pruned
as before.

## Evidence

- The affected bot read back through the dashboard GraphQL with a full
  `settings.pair` and `symbol: []`; the V2 page error boundary showed
  the stack `transformDcaBotToBot → useStableBotTransforms → TradingBots`.
- `updateExchangeInfo` read `{ exchange: provider }`, which includes the EU
  docs; each run put every EU X-Perp doc into `deleteSet`, and the EU refresher
  re-created all of them on its next run.

## Assumption (root cause)

Two mechanisms combine: (a) the global sync deletes EU pairs every run
(regression from the EU pair universe landing on shared exchange ids), and
(b) the save path rebuilds `symbol` only from what the `pairs` collection
returns, with no floor — so a save inside the gap wipes the map. (c) The V2
transform then turns one bad bot into a page-wide crash.

## Plan

1. V2 (`main-dash-sh` `types/dcaBot.ts`): when `symbol` is empty and
   `settings.pair` is not, rebuild a display copy with the existing
   `extractPairAssets` (already X-Perp aware). Display object only.
2. `bot/index.ts`: `keepStoredSymbols` merges stored entries for pairs the
   lookup missed; skip `$set.symbol` when the map is empty.
3. `utils/cron/exchange.ts`: global read becomes
   `{ exchange, source: { $ne: 'my' } }`.

Repairing already-emptied bots is a data operation outside this change.

### Blast radius

- `changeDCABotPairs` funnels into `changeDCABot`; hedge bots call both change
  methods — all gain the floor, none change which pairs are traded.
- The sync change touches only `okx`/`okxLinear`/paper twins (the only ids with
  `source: 'my'` docs). A global pair that was previously shadowed by an EU doc
  of the same name gets its own global doc on the next run, which is correct.
- `core/` is shared: `pairs` is read by legacy dashboards directly; no schema
  or field change is made.
- V2 change is confined to the list/drawer view model.
