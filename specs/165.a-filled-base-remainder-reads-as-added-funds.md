# 165 — A filled base-order remainder reads as added funds

Bug spec (Definition / Evidence / Assumption). Extends spec `111`.

## §1 Definition

- **§1.1** When a LIMIT base order fills only in part, spec `111` rests the
  unfilled rest as a LIMIT add-funds order marked `baseRemainder` on its
  `pendingAddFunds` entry. When that order fills, the fill path removes the
  pending entry and appends a plain `{ price, qty }` to `deal.funds`. The
  marker is lost, so nothing left on the deal says this fill was the base
  order's rest.
- **§1.2** The dashboard labels every filled add-funds order "Add funds
  order". A deal whose base order filled in two parts therefore shows funds
  the user never added; the exchange shows one base order's worth of coins.

## §2 Evidence

- A part-filled base order (a small fraction of the requested quantity),
  settled and opened on what filled, followed by the remainder placed as a
  `D-ROA-…` order for exactly `origQty − executedQty` of the base order at the
  same price. Once it filled, the deal's orders read "DCA order (Add funds
  order)" for it and `deal.funds` holds `{ price, qty }` with no marker.

## §3 Assumption (root cause)

- **§3.1** `updateDeal`'s add-funds fill branch already knows the fill is a
  base remainder (`baseRemainderFill`, used to arm the next position entry),
  but does not write it onto the `funds` entry it appends.

## §4 Change

- **§4.1** The `funds` entry booked for a base-remainder fill carries
  `id` (the add-funds entry id, i.e. the order's `addFundsId`) and
  `baseRemainder: true`. Every other add-funds fill is booked exactly as
  before, `{ price, qty }`.
- **§4.2 Contract (additive only, Danger List #3/#12).** The Mongo
  `filledFunds` sub-schema and the GraphQL `dealFunds` type gain optional
  `id: String` and `baseRemainder: Boolean`. No existing field changes.
- **§4.3 Unchanged.** Placement, sizing, re-placement and accounting of the
  remainder; the deal's size, cost, average, balances and level counters
  (spec `111` §5.1). Only the record of what the fill was.
- **§4.4** The dashboard labels an add-funds order "Base order (remainder)"
  when its `addFundsId` matches a `funds` or `pendingAddFunds` entry marked
  `baseRemainder`. Fills booked before §4.1 carry no marker; the dashboard
  recognises those from the deal's own orders (the rest of a part-filled base
  order, re-placed in a chain at the unfilled quantity).

## §5 Tests

`src/bot/dca/addFundsFillLostUpdate.harness.spec.ts` (`spec 165`): a remainder
fill books `{ price, qty, id, baseRemainder: true }`; a user's own add-funds
fill still books `{ price, qty }` only; balances are identical either way.
