# 140 — Combo take profit / stop loss reads each deal's own price

Bug spec.

## §1 Definition

- §1.1 **Expected.** On a combo bot, a deal's take profit and stop loss
  (`dealsForStopLossCombo`) trigger only when **that deal's own symbol**
  crosses the deal's level. A tick on one symbol never closes a deal on
  another symbol.
- §1.2 **Actual.** `unrealizedProfit()` reads one price, the last price of
  `settings.pair[0]`, and compares every deal in `dealsForStopLossCombo` to it.
  On a multi-coin combo bot, a deal on a coin priced well below `pair[0]` sees a
  "last price" far above its take profit (long), so it is market-closed seconds
  after opening, usually below entry. A deal on a coin priced above `pair[0]`
  sees its stop loss hit at once in the same way.
- §1.3 **Expected.** The price-extremum gate that decides when a tick runs
  `unrealizedProfit()` and `checkDCALevel()` (`highestLow` / `lowestHigh`) is
  keyed by the symbol of the deals that set each level, like the DCA-bot
  branch of `checkDealsPriceExtremum()` already is.
- §1.4 **Actual.** The combo branch writes one entry under `settings.pair[0]`
  from the levels of every deal on every symbol. Ticks on other symbols never
  pass the gate. Ticks on `pair[0]` pass it when they cross another coin's
  level.
- §1.5 **Unchanged.** On a single-coin combo bot every deal's symbol is
  `pair[0]`, so the price read and the gate key are the same as before. The
  take profit / stop loss levels themselves (`getDealStopLossPriceCombo`) are
  not touched.

## §2 Evidence

- §2.1 Worker log lines from a long multi-coin combo bot:
  `closing by take profit. TP set: 0.0093…, TP last : 0.3115` and
  `TP set: 0.0296…, TP last : 0.3069`. Each deal's coin was trading at its own
  TP level's order of magnitude (about 0.009 and 0.029). The 0.31 "last" price
  belongs to a different coin.
- §2.2 The bot's closed deals, read back through GraphQL, all have
  `closeTrigger: tp`. Each closed 8–37 s after opening, most at a loss.
- §2.3 Code path: `comboHelper.ts` `unrealizedProfit()` takes
  `const symbol = this.data?.settings?.pair?.[0]` and uses
  `getLastStreamData(symbol)` for every deal in the loop.
  `dcaHelper.ts` `checkDealsPriceExtremum()` combo branch sets
  `highestLow` / `lowestHigh` under `this.data?.settings.pair[0]`.

## §3 Assumption

- §3.1 (hypothesis) The single `pair[0]` price read in `unrealizedProfit()` is
  the cause of §1.2. A test with two deals on symbols whose prices are an order
  of magnitude apart fails today because the cheaper deal's take profit fires on
  the other symbol's price.
- §3.2 (hypothesis) The `pair[0]`-keyed extremum in §1.4 is a second instance of
  the same mistake. A test fails today because no gate entry exists for the
  second symbol.

## §4 Required behaviour

- §4.1 `unrealizedProfit()` evaluates each deal against the last price of
  `deal.symbol.symbol`. The last-filled-order refresh is applied per symbol. A
  deal whose symbol has no price yet is skipped.
- §4.2 The combo branch of `checkDealsPriceExtremum()` writes one
  `highestLow` / `lowestHigh` entry per deal symbol, computed only from that
  symbol's deals. Symbols with no levels have no entry, so the gate's
  defaults (never fire) apply.
