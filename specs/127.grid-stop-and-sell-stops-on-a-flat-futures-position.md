# 127 — A grid "stop and sell" stops the bot even when the position is already flat

Bug spec.

## §1 Definition

### §1.1 Expected

When a futures grid bot's take profit (or stop loss) fires with the
`stopAndSell` action, the bot cancels its grid, closes whatever position is
left, and STOPS. If there is no position left to close, there is nothing to
sell — the bot still stops.

### §1.2 Actual

`closeBotByTp` builds the closing order only for a futures position with
`qty !== 0`, and its call to `stop(true)` sits inside
`if (payload.grid && payload.additional)`. A futures bot whose position is
already flat when that check runs builds no closing order, so it never reaches
`stop()`. By then the branch has set `blockLimit = true` and cancelled every
grid order, so the bot is left `open`, with no resting orders, no position and
nothing that will ever place one again. Its `levels.active` counters still
describe the grid it cancelled.

The spot branch already handles the equivalent case (nothing worth selling →
`stop(true)`); the futures branch has no counterpart.

### §1.3 How the position gets to be flat

The value check that fires the take profit runs on a price tick. A grid order
filling at that same moment (on a neutral grid, the sell that closes the last
long leg) is processed while `closeBotByTp` awaits `cancelAllOrder`, and
`profitAfterPositionClosed` / `resetPosition` zero the position before the
close order is built.

## §2 Evidence

Production, paper Binance USDⓈ-M, neutral futures grid, `tpSlCondition:
valueChanged`, `tpSlAction: stopAndSell`, 2026-10-03 (identifiers withheld —
this file is public):

- `04:05:39.282Z` "Position unPnL 1.25%, in settings 1.25%, TP trigger".
- `04:05:39.286Z` a grid SELL `FILLED` is processed (the order that flattened
  the position).
- `04:05:39.29–.6Z` every resting grid order `CANCELED`.
- No `GRID-TP` order, no "Stop order filled", no stop. The bot document
  afterwards: `status: open`, `position.qty: 0`, `levels.active` 11/10, and the
  orders collection holds zero `NEW`/`PARTIALLY_FILLED` rows for it. The
  dashboard shows "21 active orders" from `levels.active` and a chart with no
  order lines, because there are none.
- Of all open grid bots, this is the only one whose `levels.active` claims
  resting orders while the orders collection has none.

## §3 Assumption (hypothesis)

The stop is gated on having built a closing order. Stopping whenever the
`stopAndSell` branch does not hand off to a pending (not yet `FILLED`) close
order, which keeps its existing early return and re-check timers, makes the
flat-position case stop like every other case.

## §4 Required behaviour

### §4.1 Flat futures position stops the bot

`stopAndSell` on a futures grid whose position is flat places no order and
calls `stop(true)` exactly once. (Take profit and stop loss alike.)

### §4.2 Unchanged: an open position is closed, then the bot stops

A futures grid with an open position still sends one reduce-only close order
for the whole position; when it comes back `FILLED` the bot stops once.

### §4.3 Unchanged: a pending close order does not stop the bot

When the close order comes back not `FILLED`, the method returns without
stopping (the reposition / market-timeout timers own that close).

### §4.4 Unchanged: spot

A spot grid sells `sellBaseAmount()` and stops once.
