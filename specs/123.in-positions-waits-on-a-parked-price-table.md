# 123 — The dashboard's USD valuation waits on a parked price-table fetch

Bug spec, landing in existing code (`Exchange.getAllPrices` in
`src/exchange/exchange.ts`, `priceBalancesUsd` in `src/utils/user.ts`).

## §1 Definition

### §1.1 Expected

- **§1.1.1** Valuing balances in USD for a dashboard read (`priceBalancesUsd`:
  the "In positions" figure, `getBalances(includeUsdValues)`) answers promptly
  whenever ANY good price table for the exchange has been seen before. It never
  waits on the connector for that.
- **§1.1.2** The figure is still valued at current prices: a table younger
  than the cache period (1 minute) is used as-is; an older one is used for this
  answer while a refresh runs in the background, so the next read is current.
- **§1.1.3** Only when no good table has ever been stored for the exchange
  does the dashboard read wait on a live fetch.
- **§1.1.4** Unchanged: `getAllPrices()` itself. Bot callers keep the
  1-minute cache, the single-flight live fetch and its retry ladder.
- **§1.1.5** A background refresh joins the existing single-flight
  (`fetchAllPricesOnce`), so repeated dashboard reads during a stall add no
  connector calls beyond the one already running.

### §1.2 Actual (before)

- **§1.2.1** `priceBalancesUsd` calls `getAllPrices()`. Once the `allPrice`
  field is older than a minute it is deleted (or has already been dropped by
  its `hExpire`), and the read goes to the connector and waits.
- **§1.2.2** On Binance the connector parks `latestPrices` until the next
  minute when the read weight is used up, sometimes for a second full minute.
  The dashboard request waits the whole time and the client gives up at 30s.

## §2 Evidence

- **§2.1** Prod `Gainium-main-app` SlowGraphQL, 2026-09-26 → 2026-10-01:
  16 slow `dashboardInPositions` lines across 7 accounts, worst 113s; 7 of
  them over the 30s client ceiling. Completion times bunch at :00–:03 seconds
  past the minute (minute-quantized, not ragged), e.g. `08:04:01.768Z
  ms=40694` on 2026-10-01.
- **§2.2** Same window on the connectors (log time is UTC):
  `.110 8:03:35 Binance request must sleep for 24.774s. Method: latestPrices`,
  `.108 8:03:41 … 18.777s`, then `.110 8:04:00 … 60.001s`. The 40.7s request
  started at 08:03:21 and ended right after the first sleep released.
- **§2.3** `src/exchange/exchange.ts` `getAllPrices`: expired entry → `hDel`
  → recurse → miss → `fetchAllPricesOnce(apiCall('prices'))`; the field is
  written with `hExpire` 60s, so no copy outlives that minute.

## §3 Assumption (hypothesis)

The slow `dashboardInPositions` calls are the `priceBalancesUsd` →
`getAllPrices` live fetch waiting on a parked Binance `latestPrices`, because
the only stored table expires after 60s and nothing keeps a last-good copy for
a caller that would accept one. A test where the 1-minute cache is gone, a
last-good table exists, and the connector never answers must return the
last-good table immediately; before the fix it waits on the connector.

## §4 Scope notes

- Paper exchanges inherit the default (no stale copy; same as before).
- The last-good copy lives in its own Redis hash `allPriceLast` with no
  expiry, so nothing that reads `allPrice` changes.
