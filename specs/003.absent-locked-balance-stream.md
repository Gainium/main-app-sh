# 003 — A balance stream event without `locked` must not zero the stored hold

Bug spec. Plan: `plans/003.absent-locked-balance-stream.md`. Pairs with
`websocket-connector-sh` spec 002 (Kraken spot v2 `balances`).

## §1 Definition
- §1.1 Expected: when a venue's stream reports a balance total but no hold
  figure, the stored `balances.locked` keeps the value the last REST refresh
  wrote; only `free` follows the stream. The dashboard can tell how fresh a
  balance row is.
- §1.2 Actual: `processBalanceUpdate` writes `locked: normalizeLocked(parseFloat(d.locked))`
  on every event, which is `0` when `d.locked` is absent. With Kraken spot v2
  events (connector ≥ 1.14.11) that would overstate "available" on every tick
  and undo the REST hold within seconds. `getBalances` exposes no `updated`.

## §2 Evidence
- `core/src/utils/user.ts` lines ~211–248 (both write branches).
- Connector spec 002 §4.2: Kraken spot v2 `balances` carries no hold field.

## §3 Assumption
Zeroing comes from `parseFloat(undefined)` → `NaN` → `normalizeLocked` → `0`;
the spec test `balanceWrite.spec.ts` fails on a helper that follows that
rule and passes on one that omits the field.

## §4 Required behaviour
- §4.1 `AssetBalance.locked` is optional.
- §4.2 On update, `locked` is set only when the event carries it; on insert it
  defaults to 0 when absent (`core/src/utils/balanceWrite.ts`).
- §4.3 `getBalances` returns `updated` (ISO) per row; for a summed asset the
  oldest row's time.
