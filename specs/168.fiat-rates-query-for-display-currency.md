# 168 — Fiat rates query for the dashboard's display currency

Feature spec (small addition next to existing behaviour).

## §1 Behaviour

- **§1.1** A signed-in client can read the latest cached fiat rates through
  GraphQL `getFiatRates`, returning `[{ asset, usdRate }]` where 1 unit of
  `asset` = `usdRate` USD — the same rates the portfolio snapshot already uses
  to value fiat collateral (`rates.fiatRates`, refreshed by the `saveRate` cron
  from Kraken: EUR, GBP, AUD, CHF, JPY, CAD).
- **§1.2** It exists so the dashboard can convert its USD figures into a chosen
  fiat with real rates. Until now it multiplied by a hardcoded table (e.g.
  EUR 0.85, JPY 110) that was years out of date.
- **§1.3** Read-only and additive: no existing query, field or stored document
  changes. `getUsdRate` is unchanged.

## §2 Which entries are returned

- **§2.1** No rate document, or one without `fiatRates` → an empty list (status
  OK), never an error the client must special-case.
- **§2.2** Valid entries are returned unchanged, in stored order.
- **§2.3** An entry with no asset or a non-positive / non-numeric rate is
  dropped: a client dividing by it would show 0 or Infinity. The portfolio
  snapshot's `fiatRateEntries` applies the same rule and now shares the helper.

## §3 Open questions

- **§3.1** Historical conversion (portfolio chart over time at each day's rate)
  is out of scope; clients convert at the latest rate.
