# 141 — `startDeal` webhook carries the deal's own size, take profit and stop loss

Feature spec. Tests: `src/bot/signalDealOverrides.spec.ts`.

## §1 Problem

Signal indicators usually emit an entry together with its exits: an entry,
a stop and a target computed from the same bar. A bot can only open a deal
from such a signal with the bot's own base order, TP and SL. Honouring the
signal's exits takes a second and third alert (`closeDeal`, `closeDealSl`)
and a bot configured to close by webhook.

## §2 Behaviour

### §2.1 Fields

A `startDeal` payload may carry any of these optional fields. Each one
replaces the bot's setting **for the deal it opens only**:

| Field | Meaning |
| --- | --- |
| `baseOrderSize` | base order size, in the bot's own base-order unit |
| `tpPerc` | take profit, % |
| `tpPrice` | take profit at this price |
| `slPerc` | stop loss, % (either sign = the same distance) |
| `slPrice` | stop loss at this price |

The bot's settings never change. The next deal opens with them again.

### §2.2 Validation — refused with HTTP 400, nothing dispatched

1. A field that is present must be a positive finite number, or a numeric
   string. An empty string, `NaN`, an unrendered template variable, zero,
   a negative number (other than `slPerc`) or a non-number is rejected.
   Opening without the exit the sender asked for is worse than not
   opening.
2. `tpPerc` together with `tpPrice` is rejected, and the same for `slPerc`
   with `slPrice`.
3. `tpPrice` / `slPrice` are rejected on anything but a DCA bot. Combo has
   no fixed-price exits, and a hedge bot opens two directions, so one price
   is always on the wrong side for one of them.

### §2.3 The deal

1. The take-profit fields replace the deal's whole TP setup with one target
   closed by price: TP on, multi-TP off, close condition = TP. `tpPrice`
   makes the TP a fixed price.
2. The stop-loss fields do the same for SL. `slPrice` makes the SL a fixed
   price, with trailing SL and move-SL off, since both re-derive the stop
   from a percentage. `slPerc` keeps them.
3. The values live in the deal's own settings snapshot, so DCA fills, a
   restart and a deal edit treat them like any deal-level setting. A
   record of what the signal overrode is kept on the deal.
4. A fixed TP/SL price on a regular (non-terminal) DCA deal is honoured
   only for a deal opened with that signal price. Other deals keep their
   current behaviour even when they carry the same flags.
5. `baseOrderSize` scales the base order only (safety orders keep their
   size). The balance and exchange-minimum re-checks of the existing
   new-deal size path apply. When the size cannot be applied, the deal
   opens at the configured size and a Deal event says why, as for any
   requested size. Unlike an approval hook's request, it is not held to the
   hook's multiplier bounds, because the sender chose it explicitly.
   The deal's nominal `baseOrderSize` setting is not rewritten, because
   take-profit sizing reads it.

### §2.4 Refusals at open time (bot error, deal not opened)

1. A `tpPrice` / `slPrice` on the wrong side of the current price: a long
   TP at or below it, a long SL at or above it, and the mirror for short.
2. TP/SL fields on a risk/reward bot, whose size is derived from its own
   stop.
3. A price on a multi-pair bot when the signal names no `symbol`.

### §2.5 Not applied

A signal that adds an entry to an existing single-position deal ignores
the fields (logged). The entry joins a position that already has its own
exits.

## §3 Open questions
