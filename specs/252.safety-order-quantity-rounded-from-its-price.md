# 252 — A safety order's quantity rounded from its price

Bug spec (Definition / Evidence / Assumption).

## §1 Definition

§1.1 When the venue lowers a pair's base-asset precision, `dcaHelper.afterUpdateExchangeInfo`
re-rounds every open deal's `currentOrders` and `initialOrders`. It wrote
`qty = round(price)` instead of `qty = round(qty)`, so every level's quantity became its price
(a 0.1323 ETH level at 3095.89 became 3095.89 ETH). The result was saved to the Redis deal
snapshot.

§1.2 A cold (service) restart restores a deal's ladder from that snapshot verbatim
(`loadOrders`, the `restoredFromRedis` loop), and the restart reconcile
(`getDiffForCheckOrders` → `placeOrders`) sends the missing levels. Every restart re-sent the
corrupted levels. The venue refused them (Bybit's 1080 ETH per-order cap); a venue with no cap
would size them against the balance only.

§1.3 Expected: the quantity keeps its own value, rounded to the new precision. A level whose
stored size is impossible for its own budget is never sent.

## §2 Behaviour after the fix

§2.1 `afterUpdateExchangeInfo` re-rounds `qty` from `qty` (both lists).
§2.2 Combo: a restored `dealRegular` level whose value (qty × price; contracts on coin-margined
futures) is outside [budget / F, budget × F] of its own `minigridBudget`, with
F = max(100, 10 × gridLevel), is re-sized from `createInitialDealOrders` for the same
`dcaLevel` and side. The stored price is kept (it pairs with what rests on the venue). A level
that the settings no longer produce is dropped. The user gets one bot warning. The repaired
ladder is what the next snapshot stores.
§2.3 A healthy restored ladder comes back untouched, with no message.
§2.4 The restart reconcile (`getDiffForCheckOrders`) refuses any `dealRegular` placement outside
§2.2's band, with a user-visible warning, and sends the rest.
§2.5 Levels raised to exchange minimums (≤ about gridLevel × the budget) are never out of band.
Grids without a `minigridBudget` (DCA ladders) and other order types are never touched.

## §3 Evidence

- Prod logs, Combo worker: `Send new order request CMB-RO-…, qty 3095.89, price 3095.89, side BUY`
  is refused with the 1080 ETH cap on every worker restart from the oldest rotated log
  (2026-10-02) to 2026-11-21. Each is logged between `Checking for existing deals` and
  `Found 1 open deals`, after `Found in redis 1 deals` (the snapshot restore path).
- The refused prices are the ladder the deal opened with (3508.67, 3302.28, 3095.89, …).
  Today's `createInitialDealOrders` gives 3095.88 for the same level, so the orders were not
  re-derived: they came from the snapshot.
- `createInitialDealOrders`, run on the deal's exact shape (including the corrupted size/cost
  totals), gives 0.1323 at 3095.88. It does not read `size`/`cost`.
- Harness §2.1 with the old line: quantities become exactly `[3095.89, 2889.5, 2683.11, …]`,
  matching prod.

## §4 Assumption

The venue lowered ETHUSDC's base precision while the deal was open. The only code path that
writes `qty` from `price` is §1.1 (`git log -S`: present since the first public release).

## Invariants

None added. The wrong state lives in the Redis deal snapshot, which the invariant sentinel does
not read, and every occurrence already logs a venue refusal at error level.
