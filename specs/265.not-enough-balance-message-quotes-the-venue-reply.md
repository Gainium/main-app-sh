# 265 — "Not enough balance" message drops the venue's own refusal

## 1. Definition

### 1.1 — expected

When the venue refuses an order for funds, the "Not enough balance" bot event
and bot message end with `, exchange reply - <the venue's refusal text>`.

### 1.2 — unchanged

Everything before it is unchanged: the prefix, side, price, order type,
balance total, free and required figures. The subType stays
`Not enough balance`.

### 1.3 — actual (before)

`handleOrderErrors` matched the venue's string (`matchesNotEnoughBalance`),
then built the message only from our stored balance row. When that row
disagreed with the venue's spendable figure, the message read "free X,
required Y" with X well above Y. Nothing in it said the exchange had refused,
or why.

## 2. Evidence

`handleOrderErrors` reaches the message branch only for a string that matched
a venue's funding-refusal wording, so `errorString` is the venue's reply. It
was read for that match and then discarded.

## 3. Assumption

Quoting the reply is enough for the user to see who refused the order. The
stored balance figures stay as they are. Making them agree with the venue is
a connector concern (exchange-connector-sh spec 051, websocket-connector-sh
spec 023).
