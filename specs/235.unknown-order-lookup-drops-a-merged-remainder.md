# 235 — an unknown-order lookup drops a merged market top-up

Bug spec. Touches the unknown-order ladder (`MainBot._runUnknownOrderLadder`),
next to spec `207` (venue fill size) and spec `088` (merged-row guard in
`fillPartiallyFilledOrder`).

## 1. Definition

### 1.1 Expected

When an entry order part-fills on the book and `buyRemainder` buys the rest at
market, the entry row holds the whole entry: `executedQty` = book fill +
remainder, the blended `price` and `cummulativeQuoteQty`, status `FILLED`. A
later venue lookup of that order cannot shrink it. The venue only knows the
book order.

### 1.2 Actual

The ladder's `request.status === ok` branch copies the venue's status onto
the row whenever the status differs. Since spec `207`, it also copies the
venue's `executedQty` and `cummulativeQuoteQty`. A venue that reports an ended
part-fill as CANCELED (KuCoin) therefore overwrites the merged row with the
book fill only: status CANCELED, `executedQty` the part fill. The ladder writes
that to Mongo and `deleteOrder`s the row from the map. The remainder is gone
from the books, and the deal later logs "has no base order on record".

### 1.3 Not changing

An order that was not topped up at market (not in `partiallyFilledFilledSet`)
still takes the venue's status and fill size exactly as spec `207` defines.
A merged row that the venue reports LARGER than the merge also takes the
venue's reading.

## 2. Evidence

Production, KuCoin spot KAS/USDT LONG DCA deal, 2026-11-01:

- 19:24:56.405 stream FILLED 173.5435 of 11278.9777 → `buyRemainder` sends a
  MARKET GA-BR for 11105.4342.
- 19:24:59.904 `Total order D-BO-K5IT… base: 11278.9777` (merged in memory).
- 19:25:00.927 `Real order D-BO-K5IT… status: CANCELED` → 19:25:00.928
  `Save order … with status CANCELED`.
- Mongo today (read-only): the D-BO row reads `CANCELED`, `executedQty
  173.5435`, `origQty 11278.9777`. The GA-BR row reads `FILLED 11105.4342`,
  which is exactly the difference.

## 3. Assumption (hypothesis)

Spec `088`'s guard (`partiallyFilledFilledSet.has` → keep the map row) exists
only in `fillPartiallyFilledOrder`. The ladder has no such guard. Giving it the
same guard (the row is in the set, is FILLED, and holds more than the venue
states) keeps the merged row and returns it as FILLED.

## 4. Requirements

- §4.1 A row in `partiallyFilledFilledSet` whose status is FILLED and whose
  `executedQty` exceeds the venue's converted `executedQty` (0 when the venue
  states none) is returned unchanged as FILLED. It is not written, not
  re-statused and not removed from the order map.
- §4.2 Every other row follows spec `207` unchanged, including a merged row
  the venue reports larger than the merge.

## 5. Invariant

`specs/invariants/deals.invariants.json` →
`orders.entry-row-lost-merged-remainder` (observe): an entry row short of its
`origQty` by exactly a FILLED same-side `br` order on the same deal.
