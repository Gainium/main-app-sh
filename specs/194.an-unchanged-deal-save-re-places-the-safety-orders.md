# 194 — An unchanged deal save re-places the safety orders

Bug spec. Follows spec 191 and the take-profit-only deal edit
(`isTpOnlyDealEdit`, `tpOnlyDealKeys` in `src/bot/dcaHelper.ts`).

## §1 Definition

### §1.1 Expected

- **§1.1.1** A DCA deal settings save whose patch equals the deal's effective
  settings (nothing changed — e.g. the same take-profit save sent twice)
  leaves every resting safety order on the book; at most the take profit is
  cancelled and re-placed.
- **§1.1.2** An edit that changes any non-take-profit setting (order count,
  step, sizes, stop loss, …) still cancels and re-places the whole ladder.

### §1.2 Actual

- **§1.2.1** `isTpOnlyDealEdit` required at least one changed key
  (`changed.length > 0`). An empty change set returned false, so
  `rebuildDealOrders` ran the full path: every safety order cancelled and
  placed again at the same price and size.

## §2 Evidence

- Production: two `updateDealSettings` calls on one open DCA deal, 52 s
  apart, with a byte-identical `{tpPerc, multiTp}` patch. The first took the
  take-profit-only path; after the second, the deal's three resting safety
  orders were cancelled and re-placed at the same prices within five seconds.
- The first call merges the patch into `deal.settings`, so for the second
  call every key compares equal to its effective value.

## §3 Assumption

Hypothesis: the `changed.length > 0` guard is the only reason the repeated
save misses the take-profit-only path. Dropping it makes an empty change set
take that path; §1.1.2 is unaffected because any changed non-take-profit key
still fails the `every` check. A deliberate full re-place stays available as
`restartDeal`, which calls `rebuildDealOrders` without `tpOnly`.

## §4 Fix

- **§4.1** `isTpOnlyDealEdit` returns `changed.every(k => tpOnlyDealKeys.has(k))`.

## §5 Tests

`src/bot/dca/tpOnlyDealEdit.harness.spec.ts`: "a patch that changes nothing
is take-profit only", "passes tpOnly for the same take-profit save sent
twice", "the repeated save cancels and places the take profit only"; the
spec 191 fixed-price and ladder-edit cases stay green.
