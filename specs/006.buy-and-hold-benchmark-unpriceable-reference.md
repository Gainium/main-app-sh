# 006 — Buy & hold benchmark books a failed price lookup as a real rate

Issue #637 (`paperBybit getLatestPrice may be failing on BTCUSDT`).

## §1 Definition

### §1.1 Expected

A bot's **Buy & Hold** ratio answers "what if I had just held the start asset
instead of trading?". Its reference pair (`stats.numerical.ratios.buyAndHold.symbol`)
and reference price (`.startPrice`) are pinned once, the first time the bot's
stats are seeded, and are never revisited afterwards.

When the platform can no longer price that reference pair, the benchmark is
**not computable**. Expected behaviour:

- §1.1.1 The last computable `result` / `perc` / chart point is **kept**; nothing
  is overwritten with a value derived from a missing price.
- §1.1.2 The bot does **not** ask the venue for a price for a pair the platform
  has no exchange info for — there is no price to get, and the request only
  produces a venue rejection.

### §1.2 Actual

`updateEquityStats` (`core/src/bot/dcaHelper.ts` ~20517) and `botUpdateStats`
(~21159) both do `bnhRate = await this.getLatestPrice(<reference pair>)` and use
the answer unconditionally. `getLatestPrice` is documented to return **0 on
error** (`core/src/bot/main.ts` ~4266). So when the reference pair cannot be
priced:

- §1.2.1 `bnh = (startBalance.asset / startPrice) * 0 = 0`, so
  `result = -startBalance.asset * usdRate` and
  `perc = result / startBalance.usd` ≈ **−100 %**, and stays there — the same
  number the bot would show if the reference asset had gone to zero, which is
  what makes it indistinguishable from a real reading.
- §1.2.2 The equity chart's `buyAndHold` series is written as `0 * 1 = 0` every
  tick, so the benchmark line on the bot's chart is flat zero.
- §1.2.3 Every stats tick issues one doomed venue request, and every rejection
  is logged as a bot warning (`Reason Not supported symbols Method
  getLatestPrice() Step Get latest price`) for the life of the bot.

## §2 Evidence

All read-only against production on 2026-09-04.

### §2.1 The reported bot

Paper DCA bot `6926c265aeee0f2e5dac9aa4` (`paperBybit`, 354 configured pairs):

```
stats.numerical.ratios.buyAndHold = {
  symbol: 'XIONUSDT', startPrice: 0.89,
  result: -114330.73529999999, perc: -1.0004602116973809
}
stats.numerical.general.startBalance = { asset: 114330.73529999999, usd: 114278.14 }
```

`result` is **exactly** `-startBalance.asset` (to the last digit) — the
signature of `bnh === 0`, i.e. `bnhRate === 0` with `usdRate === 1`. The last
six chart points all carry `buyAndHold: 0` while `equity` moves normally
(116841 → 117049 over 2026-08-30..09-04).

### §2.2 The failing symbol is real and non-empty — it is `XIONUSDT`

`XIONUSDT` is **not** among the bot's 354 configured pairs (all 354 are live on
Bybit spot) and has **no open deal**. It is the pair that was `settings.pair[0]`
when the stats were seeded; it has since been delisted and pruned out of
`settings.pair` by `checkSettingsPairs()` / the `pairsNotFound` branch
(`dcaHelper.ts` ~16755), while the pinned benchmark reference kept it.

Bybit rejects it, which is the reported message verbatim:

```

{"retCode":10001,"retMsg":"Not supported symbols", ...}
```

### §2.3 The platform has no exchange info for the reference pair

`db.pairs.findOne({exchange:'bybit', pair:'XIONUSDT'})` → `null`
(`SOLUSDT`/`bybit` → present). Same for `ACAUSDT`/`binance` (§2.5). So
`getExchangeInfo(pair)` — the existing "does the venue still list this?" gate,
used at `dcaHelper.ts` ~12820 — already answers correctly for these pairs.

### §2.4 The triage hypothesis is refuted

The brief proposed that a **nullish** symbol reaches `getLatestPrice`, that
`latestPrice(symbol || '', true)` then asks the venue for nothing, and that
`processError`'s `pair[0]` fallback laundered it into `BTCUSDT`. Refuted:

- An **empty** symbol does not produce this message. Live probe:
  `GET /v5/market/tickers?category=spot&symbol=` → `retCode: 0` with the full
  ticker list. Only a **non-empty, unlisted** symbol returns
  `retMsg: "Not supported symbols"`.
- The `symbol || ''` guard is not a recent addition — `git log -S` puts it in
  `0e08c6c` (initial public release, 2025-06-30), so it is in the deployed
  build and can be ruled out either way.
- The symbol is observed, not inferred: it is `XIONUSDT` (§2.2), a real
  non-empty string, and the bot's own `buyAndHold.symbol` holds it.

`BTCUSDT` in the admin attribution is a separate, already-known effect of the
pre-#624 `pair[0]` fallback: the running DCA worker (PID 1367631, started
11:29:27) predates deploy #172 (11:44), so it does not carry #624's fix.

Across 9 distinct users. A further, unambiguous subset: **4 open bots** have

buy-and-hold worth exactly zero USD while the bot is up.

Sampled references, each checked against its venue's public API today:

| bot's reference | recorded `perc` | venue price now vs `startPrice` | genuine B&H |
|---|---|---|---|
| `ACAUSDT` / binance | −1.0039 | 0.0018 vs 0.1069 | ≈ −98.3 % |
| `SIGNUSDT` / bitget | −1.0149 | 0.00894 vs 0.00932 | ≈ −4 % |
| `TRIAUSDT` / bitget | −1.0621 | 0.003744 vs 0.007488 | ≈ −50 % |

3 of 3 sampled are verifiably wrong, and by a wide margin in two of them. Note

i.e. the defect is "a failed lookup is booked as a rate", not merely "the pair

`XPLUSDT`/binance (−1.0327), `MIRAUSDT`/binance (−1.0735), `ALCHUSDT`/bitget,
`CLV-USDC`/paperCoinbase, `BDXNUSDT`/paperBinanceUsdm, `LUMIAUSDT`/paperBitget.

Not every one of the 105 is proven wrong — a reference asset that genuinely
went to zero produces the same reading, which is precisely the problem.

## §3 Assumption (hypothesis)

The root cause is that both benchmark sites treat `getLatestPrice`'s documented
**0-on-failure** return as a price. Delisting is only the most common way to
make the lookup fail; any failure produces the same −100 % benchmark, which is
why bots whose reference pair is still quoted publicly are also affected (§2.5).

The venue-request flood (§1.2.3) has the same origin — the reference pair is
pinned and never re-checked against the platform's own exchange info before
being priced.

Therefore:

- §3.1 A benchmark rate must be validated as a real, positive, finite number
  before any `result` / `perc` / chart value is derived from it, and the
  previous values kept when it is not.
- §3.2 The reference pair must be gated on `getExchangeInfo` before a price is
  requested, reusing the existing idiom at `dcaHelper.ts` ~12820.

## §4 Out of scope

- Re-pointing `buyAndHold.symbol` to a live pair. That would silently rebase a
  benchmark the user has been reading for months (the pinned `startPrice`
  belongs to the old pair), and is a product decision, not a bug fix.
- Backfilling the 105 bots that already hold a −100 % `result`/`perc`. They
  self-heal on the first tick after this fix only if their reference pair
  becomes priceable again; otherwise they keep the wrong stored value until an
  operator clears it. Flagged, not fixed here.
- `processError`'s `pair[0]` fallback (#624) and the admin bucket attribution
  (#636) — separate issues, and #624 already shipped.
