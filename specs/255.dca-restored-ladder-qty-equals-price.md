# 255 — A DCA deal restored with safety orders whose quantity is their price

Bug spec (Definition / Evidence / Assumption). Follows spec 252.

## §1 Definition

§1.1 Before spec 252, `dcaHelper.afterUpdateExchangeInfo` wrote `qty = round(price)` into every
open deal's `currentOrders` and `initialOrders` when a venue lowered a pair's base precision, and
saved the result to the Redis `deals` snapshot. The write is fixed by spec 252; snapshots written
before that fix keep the corrupted levels.

§1.2 A cold restart (`serviceRestart && !secondRestart`) restores a DCA deal's ladder from the
snapshot as stored (`loadOrders`, the `restoredFromRedis` loop, which only re-rounds `qty`), and
the restart reconcile places the missing levels. Spec 252 added a `repairRestoredLadder` hook
there but left it an identity for DCA, because a DCA level carries no `minigridBudget`. So a
corrupted DCA level is sent again on every restart: refused by the venue, or on a venue with no
per-order cap, sized only by the balance.

§1.3 Expected: such a level is re-sized to what the deal's own settings give it, the user is told
once, and every other restored ladder comes back exactly as stored.

## §2 Evidence

- Code: `loadOrders` restore loop → `repairRestoredLadder` (identity for DCA) →
  `createCurrentDealOrders(initialOrders)`; the DCA ladder builder numbers its levels with
  `levelNumber` / `number` (DCA levels have no `dcaLevel`).
- Runtime: the shared write and restore path ran in production for a Combo deal (spec 252 §3:
  `qty 3095.89, price 3095.89` re-sent on every restart). For the DCA worker, a search of its
  live and rotated logs for the per-order-cap refusal finds no hit today, so for DCA this is a
  safeguard for snapshots still carrying the shape, not a measured outage.
- Harness `src/bot/dca/restoredLadderRepair.harness.spec.ts` with the identity hook: the
  restored ladder keeps `qty = price` (red for §3.1, §3.2).

## §3 Behaviour after the fix

§3.1 On a cold restart, a restored `dealRegular` level is re-sized when BOTH hold:
(a) |qty − price| ≤ 0.5 (its quantity is its price rounded to some base precision — the only
shape the defect wrote), and (b) its value qty × price is more than 100× off the value of the
same level (same side, same `levelNumber ?? number`) in
`createInitialDealOrders(symbol, deal.initialPrice, id, deal)`. It takes the fresh quantity and
keeps its stored price. One user warning per deal names the levels.
§3.2 Levels that do not meet §3.1 are returned as the same objects.
§3.3 A restored ladder with no level meeting §3.1(a) is returned as stored, without building a
fresh ladder; one meeting (a) but not (b) is returned as stored, with no message.
§3.4 If the fresh ladder is empty or lacks the level, the stored level is kept as today.
§3.5 Combo keeps its own override (spec 252 §2.2); nothing here changes it.

## §4 Assumption (hypothesis)

The only producer of `qty ≈ price` on a DCA level is the pre-252 precision write; condition (a)
alone would also catch a cheap pair's healthy level, which condition (b) rules out.

## Invariants

None added. As in spec 252, the wrong state lives only in the Redis deal
snapshot, which the invariant sentinel does not read; the persisted deal and
its order rows are sized correctly. The repair itself posts a user notice and a
warning log line each time it fires, so the remaining corrupted snapshots show
up in the bot logs without a sentinel query.
