# 158 — A negative BNFCR balance is dropped from the account's USD value

Bug spec (Definition / Evidence / Assumption). Tests:
`src/utils/pegRates.spec.ts`.

## §1 Definition

On a Binance USDⓈ-M account in Multi-Assets mode, realized losses, fees and
funding settle into BNFCR (Binance Futures Credit, pegged 1:1 to USD). The
venue reports it as a negative `walletBalance`, and the connector stores it as
a balance row with a negative `free`.

**Expected.**

- §1.1 The portfolio snapshot (`userSnapshots`) values a BNFCR row at 1 USD per
  unit, so a negative BNFCR row lowers the account's `exchangesTotal.totalUsd`
  — the `balance` the dashboard shows as the account value and as the futures
  card's Wallet balance — and the user's `totalUsd`.
- §1.2 `priceBalancesUsd` (the balances table's USD values) prices BNFCR the
  same way, so the table and the snapshot agree.
- §1.3 Unchanged: every other asset is valued exactly as before, through the
  same rate table and the same order of lookups.
- §1.4 Unchanged: the bot engine's own `findUSDRate` calls (sizing, budget,
  monitor) do not see the BNFCR rate — it only lives in the two snapshot rate
  tables.

**Actual.** BNFCR has no market in any `getAllPrices` table, so `findUSDRate`
returns 0, the tokenized-stock fallback also returns 0, and the snapshot loop
skips the row (`if (amountUsd)`). The account value is the positive collateral
alone, overstated by the BNFCR debt; Equity, which the futures card derives
from it, is overstated by the same amount.

## §2 Evidence (prod, read-only)

- §2.1 A Multi-Assets USDⓈ-M account's stored balances: `USDC 22,624.98`,
  `BNB 0.69`, `BNFCR free -4,250.73` (updated minutes before the read).
- §2.2 That day's snapshot for the account: assets `USDC 22,610.80 USD` and
  `BNB 501.38 USD`, no BNFCR entry; `exchangesTotal.totalUsd` = 23,112.18 = their
  sum. The snapshot code ran and dropped the row; it did not fail.

## §3 Assumption (root cause)

The snapshot rate table has no entry that prices BNFCR, so the row's USD value
is 0 and the loop discards it. Adding a `BNFCRUSD = 1` entry under exchange
`all` — the mechanism the USDT→USD and fiat rates already use — makes
`findUSDRate('BNFCR', …)` return 1 through its existing `asset/USD` lookup.
