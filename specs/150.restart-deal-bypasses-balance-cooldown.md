# 150 — restart deal is answered by the not-enough-balance cooldown

Bug spec.

## 1. Definition

### 1.1 Expected
- §1.1.1 A user's **Restart deal** sends the deal's safety orders and take
  profit to the venue, even when an earlier insufficient-funds pause is armed
  for that symbol. If the user has added funds since, the orders are placed.
- §1.1.2 If the venue still refuses after the restart, the guard re-arms from
  the venue's own refusals, as it would on a first shortfall.
- §1.1.3 Automatic retries of unfunded orders keep their existing back-off.
  Nothing changes for an order that was not re-sent by a user action.
- §1.1.4 A refusal served from the local cooldown does not start the Coinbase /
  KuCoin / Bybit "not enough balance" retry loop. That loop waits out venue
  balance lag. A cached answer cannot change in a second.

### 1.2 Actual
`restartDeal` → `rebuildDealOrders` → `placeOrders` → `sendOrderToExchange`.
While `notEnoughBalance.thresholdPassed` is set and the counter for
`<symbol>@<side>` is at the threshold, `notEnoughBalanceBackoff.check` returns
`suppressed`. The order then gets a synthetic `Not enough balance` refusal
without a venue call, for up to `maxMs` (1 h). On Coinbase the retry loop
replays it five more times at exactly 1 s intervals. The user sees "Not enough
balance" next to a free balance far above the order's required amount.

## 2. Evidence
- Production log, Coinbase DCA bot, restart of a deal on a USDC pair: five
  `coinbase not enough balance, retry - N in 1000ms` lines for one safety
  order, 1.000 s apart. Then `Not enough balance ... free - 9826.24 USDC,
  required - 142.62`. Real venue refusals on the same bot earlier that day were
  about 1.45 s apart. The 1.000 s spacing is the sleep alone, with no venue
  round trip.
- Code: `src/bot/main.ts` `sendOrderToExchange` cooldown block, and the
  venue-retry branch that does not check `notEnoughBalanceShortCircuit`.

## 3. Assumption (hypothesis)
The cooldown key is per (bot, symbol, side) and is armed by earlier automatic
refusals. Nothing on the restart path clears it. The fix is to clear the
counter, the refused sizes and the cooldown for the deal's symbol (both sides)
at the start of `restartDeal`. The retry branch should also skip
short-circuited refusals.
