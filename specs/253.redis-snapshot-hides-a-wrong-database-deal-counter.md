# 253 — The Redis snapshot hides a wrong database deal counter

Bug spec. Extends `183` (a restart restores a stale deal counter).

## §1 Definition

### §1.1 Expected

- **§1.1.1** When a bot's data is loaded from the Redis `botData` snapshot, the
  load-time reconcile (`reconcileBotDeals`, spec 183) also compares the loaded
  deals against the bot's Mongo document's `deals`, and writes the loaded
  counter when the Mongo value differs, even if the snapshot already agrees.
- **§1.1.2** When the snapshot and Mongo both agree, nothing is written
  (spec 183 §1.1.3 is kept: a service restart does not write every bot).
- **§1.1.3** A failed Mongo read is not evidence of drift: the snapshot's
  counter decides, as before.
- **§1.1.4** A load from Mongo issues no extra read; spec 183 behaviour is
  unchanged.
- **§1.1.5** Not changed: bot credits (`botcosts`), and deals themselves.
  Only the `deals` counter on the bot document is corrected.

### §1.2 Actual

- **§1.2.1** `reconcileBotDeals` compares only against `this.data.deals`. On a
  cold restart that is the Redis snapshot's copy. A snapshot reading `{1,1}`
  over a Mongo document reading `{0,0}` matches the loaded deals, so the wrong
  database counter is never written and survives every restart.
- **§1.2.2** Consumers that read the Mongo counter act on the wrong value: the
  `bots.terminal-open-without-deal` invariant reports a terminal trade with a
  real open deal as one with no deal, and the bot list shows 0 deals.

## §2 Evidence

Production, one Kraken terminal `import` trade created 2026-09-26, read-only:

- `dcabots.deals` = `{all: 0, active: 0}`, `status: open`; `dcadeals` holds one
  `open` deal for that bot.
- DCA-bot log 2026-11-21 15:46:44: `Read bot data from redis`,
  `Found in redis 1 deals`, `Get deals count 1`, and no
  `Bot deals counter … does not match` line: the reconcile ran and found the
  snapshot counter equal to `{1,1}`.

## §3 Assumption (hypothesis)

The snapshot counter is `{1,1}` while Mongo is `{0,0}`; spec 183's reconcile
never looks at Mongo on the Redis path, so it never writes. Comparing against
Mongo's `deals` on that path writes `{1,1}`. How the two copies first diverged
in September is not established; the reconcile makes it self-heal regardless.

## §4 Solution

- **§4.1** `MainBot.loadData` records `dataFromRedis` when it takes the
  snapshot.
- **§4.2** `reconcileBotDeals`, when `dataFromRedis`, reads the bot document's
  `deals` (`_id` lookup, `deals` projection) and writes when either the
  snapshot or the Mongo counter differs from the loaded deals.

## Invariants

The main-app `bots.terminal-open-without-deal` invariant now skips bots that
have any `dcadeals` row (`botId_1`). The false positive this spec fixes is
recorded in its `fpCheck`. A counter that is wrong while a deal exists is
`bots.active-deal-counter-drift`'s concern.
