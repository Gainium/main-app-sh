# 135 — A neutral grid's value-changed TP/SL decides on `position.price` until its entry cache warms

Follow-up to spec `117`. `117` §4.4 made `tpSl()` value a NEUTRAL futures
grid's open position against the unpaired-fills entry through a per-position
cache, and specified that a position the cache was not computed for (restart,
settings change, a fill whose refresh has not landed) "is valued against
`position.price` until a refresh — started from the tick — lands". That
fallback is the defect: the first tick after a bot reloads decides TP/SL on
the whole-position average that `117` exists to stop using.

## §1 Definition

### §1.1 Expected

On a NEUTRAL, non-COIN-M futures grid with a value-changed TP or SL, `tpSl()`
only decides against the entry `closeEntryPrice()` would book the close at.
While that entry is not known for the current position, the value-changed
check does not fire. Once the refresh lands it is decided exactly as in `117`,
including the `position.price` fallback when the unpaired-fills read itself
falls back (`117` §4.5).

### §1.2 Actual

`tpSlEntryPrice()` starts the refresh in the background and returns
`position.price` for the tick that found the cache cold, so that tick can fire
TP early (or skew SL) by the gap between the two entries.

## §2 Evidence

Prod grid log, paper NEUTRAL futures grid, lev 1, value-changed TP 1.25%, on
2026-10-06 (the grid service reloaded every bot):

```
15:34:05.773Z Load data start
15:34:06.410Z Run after loading
15:34:12.309Z Position unPnL 1.55%, in settings 1.25%, TP trigger
15:34:12.998Z Close entry: 0.02908 from unpaired fills (position price 0.0278)
```

The first TP check after the reload valued a LONG against 0.0278; the close
booked against 0.02908, about 0.75%. No `TP/SL entry:` refresh preceded the
trigger, as no fill had happened since the reload.

## §3 Assumption (root cause)

The cold-cache branch of `tpSlEntryPrice()` returns `position.price`. Test:
on spec `117`'s BR fixture (3% TP: 3.08% on `position.price`, ≈1.03% on the
unpaired entry at 0.94742), the FIRST `tpSl(0.94742)` on a fresh instance
returns `tp`.

## §4 Required behaviour

- §4.1 A cold cache (fresh instance, or a position the cache was not computed
  for) makes the neutral value-changed TP/SL check return no trigger for that
  tick and start one refresh; the next tick after it lands decides on the
  unpaired entry.
- §4.2 SL waits the same way, then fires on the unpaired entry.
- §4.3 A refresh that throws does not leave the queue rejected (a rejected
  queue would never refresh again, and with §4.1 would skip the check forever).
- §4.4 Not changed: the entry used once warmed, its fallbacks (`117` §4.5),
  price-reached TP/SL, LONG/SHORT/COIN-M grids, and how a triggered TP/SL
  closes.
