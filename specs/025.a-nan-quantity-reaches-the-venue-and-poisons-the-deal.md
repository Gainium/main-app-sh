# 025 — A NaN quantity reaches the venue, and poisons the deal on the way

Issue #715. Bug spec (Definition / Evidence / Assumption).

Sibling of spec `023` (#714), which stopped ONE producer of a NaN quantity —
`getTPOrder`'s own sizing. This spec is about the two boundaries `023` did not
touch: the DCA ladder, which is the other producer, and the order-submission
boundary, which is what actually turns a NaN into money harm.

## §1 Definition

### §1.1 Expected

- **Submission boundary.** `sendOrderToExchange` never sends — and never
  write-ahead persists — an order whose quantity or price is not a finite
  number. There is no venue, symbol or bot type for which such an order can
  succeed, so refusing it costs nothing and it is refused with a named error.
- **DCA ladder.** `createInitialDealOrders` returns safety orders whose `qty`
  is a finite number. When the price it sizes them from is unusable it returns
  `[]` and says so — exactly as it already does for its `price` argument
  (`939a5fe`, "Latest price is 0"), and as `addDealFunds` already does for its
  own quantity ("Order qty is not a number").

### §1.2 Actual

- `createInitialDealOrders` divides the order size by `_price ?? price` — its
  fifth argument, the *sizing* price, which the `939a5fe` guard does not cover
  and which `??` passes through when it is `0`. `33 / 0` is `Infinity`, which
  `MathHelper.round` turns into `NaN` (spec `023` §2.3). Every clamp below is a
  no-op on NaN, the one thing that objects — `new Big(qty).mod(step)` throwing
  `[big.js] Invalid number` — is **caught and swallowed**, and the loop then
  pushes `{ qty: NaN }` onto the ladder anyway.
- `getTPOrder`'s equivalent catch does the same: it logs the throw and falls
  through to build the order from the unusable quantity.
- `sendOrderToExchange` then `setOrder`s it, `saveOrderToDb`s it and sends it.
  The venue rejects; the row survives as `origQty: "NaN"`.

### §2.2 The ladder is how the deal document goes NaN

`dcaHelper.ts` sums the ladder into the deal's own accounting:

```
totalBase  = regular.reduce((acc, g) => acc + g.qty, 0) + boQty + …
totalQuote = regular.reduce((acc, g) => acc + g.qty * g.price, 0) + …
```

and those two feed `assets.required.{base,quote}`, `usage.max.*` and
`usage.maxUsd` / `usage.currentUsd` — every field named in §2.1. One `qty: NaN`
in `regular` is sufficient for all of them.

### §2.3 Not one user, and not new

`Big number error … Method createInitialDealOrders Step dca` appears in the
pm2 archive for **8 distinct bots** across 2026-08-16 → 2026-09-08, in bursts
of ten-plus consecutive lines (one per ladder level) inside a single
millisecond window. The 2026-09-08 report is the occurrence that also produced
a venue send.

### §2.4 The affected deals are `orderSizeType: 'quote'`

Read-only on prod, deals `6a9fca447794d53dedbab119` (SWFTC-USDC) and
`6a90e161a76e7fe63ea3118f` (B3-USDC), both `exchange: 'coinbase'`:

```
settings.orderSizeType 'quote'   settings.orderSize '33'
settings.dcaVolumeBaseOn 'scale'  sizes { dca: [], origDca: [] }
```

So `useVolumeChange` is off, `sizes.dca` contributes 0, and the ladder's
quantity reduces to `round((33 / (_price ?? price)) * volumeScale**(i-1), p)`.
With `orderSize` finite and `sizes.dca` empty, the divisor is the only input
that can produce a non-finite result — and it is the one argument the existing
guard does not check. `symbol.baseAsset.step` is valid on prod for these pairs.

## §3 Assumption (root-cause hypothesis)

### §3.1

`createInitialDealOrders`' `_price ?? price` accepts a `0` (and a non-finite)
sizing price because `??` only rejects `null`/`undefined`. `939a5fe` guarded
the `price` argument for exactly this reason and stopped there; the fifth
argument, added later for on-demand/indicator DCA execution, reintroduced the
same division by zero one line below the guard.

### §3.2

A `try/catch` whose body is the ONLY thing that can detect a non-finite
quantity must not be a `catch`-and-continue. Both the ladder's and
`getTPOrder`'s catches log and then use the poisoned value.

### §3.3

Neither of the above is where the money harm happens. That is
`sendOrderToExchange`, which has no opinion about the numbers it is handed. A
guard there is venue-independent, is not a judgement call (no order with a
non-finite quantity or price has ever been accepted by any venue), and bounds
every present and future producer of a NaN — including ones this spec has not
found.

## §4 Solution

- **§4.1** `sendOrderToExchange` refuses an order whose `origQty` or `price` is
  not finite, before `setOrder` / `saveOrderToDb` / the venue call, reporting
  `Order qty is not a number` — the string `bot/utils.ts` `errorDict` already
  maps to the `orderParams` subtype.
- **§4.2** `createInitialDealOrders` extends the existing latest-price bail to
  the sizing price it actually divides by, so a `0`/non-finite `_price`
  returns `[]` with `Latest price is 0` rather than a NaN ladder — and guards
  `baseQty`, the other input everything it returns is derived from. `baseQty`
  is read off a persisted order row as a STRING: `parseFloat('NaN')` is falsy
  and falls through harmlessly, but `'Infinity'` is truthy and `math.round`
  turns it into NaN.
- **§4.3** Both of `createInitialDealOrders`' `catch`es — the take-profit one
  and the ladder's — bail when the quantity they were handed is not finite,
  instead of building/pushing it.
- **§4.4** `getTPOrder`'s `catch` returns `[]` when `tpOrder.qty` is not
  finite, instead of falling through to build the order.
- **§4.5** A healthy ladder and a healthy take-profit are unchanged to the
  unit — the guards only fire on values that already could not be filled.

## §5 Blast radius

`core/` submodule, so shared with every consuming service. No contract shape
changes: no GraphQL, REST, socket.io, Redis channel or queue payload is
touched, and no Mongo field changes meaning. The behavioural change is
confined to inputs that are already non-finite, which no venue accepts today.
`sendOrderToExchange` is the highest-traffic method in the engine, so §4.1 is
two `Number.isFinite` reads on values it already parses.
