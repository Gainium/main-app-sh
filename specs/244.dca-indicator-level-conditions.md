# 244 — Several indicator conditions per DCA level

Status: implemented (frontend + engine + backtester), not deployed.

## §1 Behaviour

DCA by indicators places one safety order per **level**. Until now a level was
one `startDca` indicator. A level can now hold several indicators arranged in
AND/OR groups — the same group editor Deal start uses — and its safety order
is placed when the level's conditions hold, exactly as a deal opens when its
start groups hold.

§1.1 A level keeps its own order size and minimum % from the last filled
order. Those are stored on the level's **anchor** indicator: the indicator
whose `uuid` equals the level key, else the level's first indicator.

§1.2 Levels are ordered by the first appearance of their key among the
`startDca` indicators. Level N is the N-th level, not the N-th indicator.

§1.3 The level key is the indicator's `dcaLevel`, or its `uuid` when
`dcaLevel` is unset. A bot saved before this change has one `startDca`
indicator per level and no `dcaLevel`; every such bot reads and trades exactly
as before (no migration).

§1.4 A level's conditions are the `startDca` groups whose `dcaLevel` equals
the level key. Inside a group, indicators combine with the group's `logic`.
Groups combine with their own `join` (AND binds tighter than OR); a group
without `join` joins with AND.

§1.5 A level with no such group (legacy) fires when its indicator fires.

§1.6 An AND group with a configured leg that is not subscribed or has no data
cannot pass (same rule as deal start), so a missing leg never lets the
remaining legs place a safety order alone.

§1.7 A deal only acts on the level it has reached (`nextLadderLevel`), and
only that level's indicators are subscribed for the deal's pair. All of the
level's indicators are subscribed together and armed together.

§1.8 When a level fires, the statuses of its indicators reset, as the single
indicator's did before. The minimum % from the last fill still gates the
order.

§1.9 The deal snapshot `dcaIndicatorLevels` holds one entry per level (from
the anchors), so a bot-settings save still does not move a running deal's
ladder.

§1.10 The ladder size, the deal's `levels.all`, the projected ladder (dashboard
overview and server/client backtests) count levels, not indicators.

§1.11 `hideOnChart` on any indicator keeps it off the dashboard chart. It
never changes trading.

§1.12 Billing is unchanged: the whole DCA ladder still counts as one billable
indicator.

## §2 Data

- `settings.indicators[].dcaLevel?: string`
- `settings.indicators[].hideOnChart?: boolean`
- `settings.indicatorGroups[].dcaLevel?: string` (`startDca` groups only)

Stored in Mongo, exposed in GraphQL (types and inputs) and accepted by the
public v2 API. Absent = previous behaviour.

## Invariants

States the feature must never produce:

- **244.level-without-anchor-size** — a running indicator-DCA bot whose
  ladder has a level with no order size on its anchor while volume is not
  "required change". The user would get a safety order sized from the base
  order instead of the size they set for that level.
- **244.orphan-level-group** — a `startDca` group with a `dcaLevel` that no
  `startDca` indicator carries. Harmless to trading, but it means the form
  saved a level's groups without its conditions, so the level the user built
  is not the one that trades.

Pack: `specs/244.invariants.json` (parent repo), mode `observe`.
