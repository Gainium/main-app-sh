# 094 — Inline string-literal unions keep only their first member in the OpenAPI spec

## §1 Definition

### §1.1 Expected

A settings property declared with an inline union of string literals, e.g.
`stopStatus?: 'closed' | 'monitoring'` on `DCABotSettings`, must be published in
`src/server/v2/openapi-v2.yaml` as `type: string` with an `enum:` listing
**every** member of the union, in declaration order.

### §1.2 Actual

Only the first member survives. `DCABotSettings.stopStatus` (and the same field
on the combo settings schema) is published as `enum: [closed]`, so the public
reference tells integrators that `monitoring` is invalid — while
`POST /api/v2/bots/dca` accepts it (`validators/bots/config.ts`, `stopStatus`
→ `shouldBeValidEnumValue` over `Object.values(BotStatusEnum)`) and it is the
value that makes the engine park a stopped bot in monitoring.

## §2 Evidence

1. On a clean `origin/main`, `npm run generate:schemas` rewrites
   `openapi-v2.yaml` with an **empty** `git diff`: the published `enum: [closed]`
   is the generator's deterministic output, not hand-edited drift.
2. `https://api.gainium.io/api/v2/openapi.yaml` serves the same `enum: [closed]`
   for both `stopStatus` occurrences.
3. `SchemaGenerator.parseProperty`, union branch: after dropping
   `null`/`undefined` it takes `types.find(...)` — the FIRST remaining member —
   and parses only that. `parseTypeNode(LiteralTypeNode)` returns
   `{ type: 'string', enum: [<that one literal>] }`.
4. Latent: the branch dates from `f036f2d` (2026-02-17, the commit that created
   the generator); `stopStatus`'s inline union was added later (`40632c9`,
   2026-02-25). Spec 092 fixed the same truncation class for NAMED union
   aliases (`parseStringLiteralUnion`) but not for inline property unions.

## §3 Assumption (hypothesis)

The truncation is entirely the `types.find(...)` first-member pick in
`parseProperty`. If every non-null member of an inline union is a string
literal, collecting all of their texts yields the complete enum; nothing else in
the pipeline narrows it.

## §4 Scope

- §4.1 Only inline unions whose non-null members are ALL string literals change.
  Mixed unions (`string | number`, `Foo | Bar`) keep today's behaviour.
- §4.2 Which values the API accepts does not change; no validator is touched.
  Bot stop behaviour does not change.
- §4.3 `nullable` handling is unchanged (`'a' | 'b' | null` still marks nullable).
- §4.4 Test: the published `DCABotSettings.stopStatus` enum contains both
  `closed` and `monitoring`, and every published `stopStatus` example lies
  inside its enum.
