# 251 — A Binance PERCENT_PRICE refusal is never re-priced

Bug spec (Definition / Evidence / Assumption). Extends the price-band re-send
of combo grid levels (246) and DCA / combo safety orders (248) to Binance.

## 1. Definition

### 1.1 Expected
A limit DCA / combo safety order or combo grid order the market has already
passed, refused by Binance's percent-price band (`Filter failure:
PERCENT_PRICE` / `PERCENT_PRICE_BY_SIDE`), is re-sent once at the market price
with its level (`origPrice`) kept — exactly as a Bybit, OKX or Bitget band
refusal already is. If the re-sent order is refused on price again, the user
gets a visible `Grid order cannot be placed` error naming the level.

### 1.2 Actual
The order is written off CANCELED and nothing else happens. On every bot
reload the same level is re-sent at the same stale price and refused again.
`handleErrors` returns early on any `PERCENT_PRICE` message, so the user never
sees it either.

### 1.3 Not changing
Every other Binance filter refusal (LOT_SIZE, MARKET_LOT_SIZE, NOTIONAL,
MIN_NOTIONAL, PRICE_FILTER, MAX_NUM_ORDERS …) keeps its current handling and
is never re-priced. The classification of the refusal (`refusal.subType` on the
order row) is unchanged.

## 2. Evidence

- Observed: a spot combo deal on Binance had several passed safety levels
  re-sent at their levels on each reload while the market sat ~20% below
  them; every one was refused `Filter failure: PERCENT_PRICE_BY_SIDE`, the
  order rows carry `refusal.subType: 'Order params'`, and the
  `refused on price band … Re-send at` line was logged for other venues but
  never for that bot.
- Code: the re-send gate in `sendOrderToExchange` is
  `getErrorSubType(reason) === 'Order price'`. Binance's wording matches the
  generic `Filter failure` → `Order params` (static `errorDict` and the
  higher-precedence DB rule `filter failure`), so the gate is false.
- Harness `src/bot/binancePercentPriceReprice.spec.ts` drives the real
  `sendOrderToExchange`: before the change the venue is called once; a Bybit
  band refusal in the same harness is re-sent (the harness reaches the gate).

## 3. Assumption (root cause)

The gate identifies a price-band refusal only by the `Order price` class, and
Binance's percent-price refusal never lands in that class because it shares
the `Filter failure` wording with every other Binance filter. Recognising the
filter by its own name (`PERCENT_PRICE`) at the gate — not by reclassifying —
makes the re-send and its second-refusal error fire without touching any other
filter. The early return in `handleErrors` is not on the error path: the
unplaceable report goes through `processError` directly.

## 4. Tests (traceability)

- §2.1 safety order through the market → re-sent once at market, level kept.
- §2.2 refused again → one `Grid order cannot be placed` report.
- §2.3 combo grid level → re-sent at market.
- §2.4 LOT_SIZE / NOTIONAL / MIN_NOTIONAL → one venue call, no re-price.
  (`binancePercentPriceReprice.spec.ts`; predicate cases in
  `priceBandReprice.spec.ts`.)
