# 289 — Binance futures deal closed outside the bot is priced from the venue's fills

## Definition
A futures deal whose position was closed on the exchange without the bot (a hand close in the exchange
app, a liquidation, an auto-deleverage) is settled by `settleExternallyClosedDeal` (spec `277`). It is
priced from the venue's account fills (`venueCloseEvidence`) when they cover the deal, and is otherwise
closed flagged `profitUnknown` at no exit price.

On Binance USDⓈ-M and COIN-M the second branch was the only one ever taken. The connector answered the
account-fills read with an empty page, so every such deal on those venues was booked "profit unknown"
with zero profit. That understated the bot's accumulated profit or loss, which the "stop after X profit
or loss" condition reads.

## Evidence
- E1. Connector: before exchange-connector spec `057`, Binance never overrode the abstract
  `getAccountFills`, which returns `[]`. Since `057` it answers from `userTrades`, which Binance publishes
  **per symbol only**. A read that names no symbol still gets `[]`.
- E2. `venueCloseEvidenceFor` called `getAccountFills()` with no arguments, and `Exchange.getAccountFills`
  had no way to send a symbol.
- E3. Observed on production Binance USDⓈ-M deals closed by hand from the exchange app: each was booked
  `closedExternally` + `profitUnknown` with profit 0, and the bot event read "did not report the fills
  that closed it".

## Assumption
- A1. Kraken Futures, Bitget and Bybit ignore the new `symbol` parameter (connector `057` §1.1), so the
  evidence they return, and therefore how their deals are settled, is unchanged.
- A2. When and how the bot decides that a position was closed outside it is not touched. Only the read
  that prices the close changes.

## Behaviour
- §1.1 `Exchange.getAccountFills(sinceMs?, symbol?, timeProfile?)` sends `symbol` when it is given, and
  `since` when given, as before. A caller that names neither sends no parameters, exactly as before.
- §1.2 `venueCloseEvidenceFor(deal)` asks for the deal's own symbol. On Binance futures, a deal whose
  position was closed by hand is then closed at the volume-weighted price of the closing fills that the
  bot did not place, with their reported quote fee, flagged `closedExternally` and not `profitUnknown`,
  with close trigger `manual` (`liquidation` when a fill is a forced close). The bot's own fills (an API
  client id) are never counted.
- §1.3 Every other caller (`readLiquidationFills`, the write-off settle, the position reconciler's order
  probe, the Kraken repair script) still names no symbol, so it reads exactly what it read before.

## Invariants
`deals.binance-futures-closed-outside-profit-unknown` (pack `specs/289.invariants.json` in the main-app
repo, observe mode): after this ships, a Binance USDⓈ-M / COIN-M deal closed outside the bot is booked
"profit unknown" only when the venue's fills really do not cover it. A run of such events signals that
the read is failing again.
