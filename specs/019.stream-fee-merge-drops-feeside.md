# 019 — the live-stream order merge never carries `feeSide`

Bug spec. Companion to `paper-trading/core` spec 003 and
`websocket-connector/core` spec 005 — those two repos make paper's
`feeSide` reach this app's `ExecutionReport` input; this spec is the
last hop, consuming it.

## 1. Definition

### 1.1 Expected

`convertExecutionReportToOrder` (`src/bot/main.ts`) merges every fee
field a stream message (`ExecutionReport`) carries onto the local
`order`, present-if-present, absent-means-unobserved — this is already
the stated rule for `feePaid`/`feeAsset`/`feeBreakdown`/`feePaidUsd`
(`main.ts:5257-5261` comment). `observedFeeSplit`
(`src/bot/orderFee.ts:97-157`), which real-fee-first TP sizing
(`dcaHelper.ts`) reads, resolves an order's fee from *either* `feeSide`
or `feeAsset` — `feeSide` is not optional-in-practice, it is the only
field paper-trading ever sets (it never sets `feeAsset` — paper spec
003).

### 1.2 Actual

The merge block (`main.ts:5263-5274`) copies `feePaid`, `feeAsset`,
`feeBreakdown`, `feePaidUsd` from `msg` onto `order` — never `feeSide`.
For an order whose only fee field is `feeSide` (i.e. every paper fill,
once the two upstream repos forward it), the live-stream path drops the
fee entirely: `order.feeSide` stays unset, `observedFeeSplit` cannot
resolve a leg from `feeAsset` (never set) or `feeSide` (dropped here),
and returns `null` — "fall back to the estimate" — even though the
venue (paper-trading) told us the exact fee.

The REST-poll merge, `mergeCommonOrderWithOrder` (`main.ts:5278-5333`),
does not have this gap: it uses `observedFeeOf`
(`src/bot/orderFee.ts:70-82`), which already copies `feeSide` alongside
the other three fields. This is a live-stream-only defect.

## 2. Evidence

Read directly:

- `main.ts:5263-5274` — four `if` blocks, one per field; grepped for
  `feeSide` in this function's body: zero matches.
- `types.ts` `SpotUpdate` (the `ExecutionReport` variant this function's
  `msg` parameter is typed as) — declares `feePaid`/`feeAsset`/
  `feeBreakdown`/`feePaidUsd`, not `feeSide` (a second, independent gap:
  even after the merge is fixed, the wire type must also carry the
  field for `msg.feeSide` to be legal TypeScript — see plan).
- `src/bot/orderFee.ts:70-82` (`observedFeeOf`) — copies `feeSide`
  alongside `feePaid`/`feeAsset`/`feeBreakdown`; used by
  `mergeCommonOrderWithOrder` (`main.ts:5301`), confirming the REST
  path is unaffected.
- `src/bot/orderFee.ts:97-157` (`observedFeeSplit`) — for a single-leg
  fee (no `feeBreakdown`), resolution requires `leg.side` (from
  `order.feeSide`) or `leg.asset` matching base/quote (from
  `order.feeAsset`); with both absent, every branch falls through to
  `return null` (`:151`).

## 3. Assumption (hypothesis)

The merge block at `main.ts:5263-5274` is missing one `if` clause for
`feeSide`, and `SpotUpdate` in `types.ts` is missing the field
declaration that clause would read. Both are required together — the
type addition alone changes nothing observable; the merge addition
alone doesn't compile against the narrower type. Nothing else on this
path (routing into `convertExecutionReportToOrder`, `processOrderQueue`,
`onFilled`) is implicated — once `order.feeSide` is set correctly,
`observedFeeSplit` already handles it (§2, `orderFee.spec.ts` existing
coverage for `feeSide`).
