# 296 — OKX USDT-swap open positions apply the contract value twice

Bug spec (Definition / Evidence / Assumption).

## 1. Definition

§1.1 `getAllOpenPositions` reports an `okxLinear` position's `quantity` in
base coin: the venue's contract count `pos` × the instrument's contract value
`ctVal` (`baseAsset.multiplier`). 9717 contracts of a 0.001-ETH contract read
9.717.

§1.2 `closePositionOnExchange` converts that coin size back to contracts once,
with the bot engine's own rule (`getOKXDenominator`: `ctVal > 1 ? 1/ctVal :
10^decimals(ctVal)`), so "Close position" sends a reduce-only MARKET order for
exactly the position's contract count.

§1.3 Not changing: pairs whose `ctVal` is 1 (or unset) read and close exactly
as before this change. (Superseded by spec 297, which applies the same rule to
`ctVal = 1` pairs.)

Actual: for `ctVal ≠ 1` the read is `pos × ctVal ÷ 10^decimals(step)`, and the
close divides by that denominator once more, so the read is off by the
denominator and the close order by its square.

## 2. Evidence

§2.1 The connector maps an OKX linear instrument to `baseAsset.multiplier =
ctVal` and `baseAsset.step = ctVal × minSz` (exchange-connector-sh
`okx/index.ts` getAllExchangeInfo), and forwards `positionAmt = pos`
(contracts).

§2.2 On OKX Europe X-Perps every instrument has `minSz = 1`, so `step =
ctVal` and the current read is `pos × ctVal²` (public instruments feed). That
reproduces all three observed misreads: ETH (ctVal 0.001) 1000× too small,
PEPE (ctVal 1e6) 1e6× too large, ONDO (ctVal 10) 10× too large, while
ctVal-1 pairs (SUI, LINK, STRK) read correctly. The position reconciler's
conversion (`pos ÷ getOKXDenominator`) reads the same venue rows correctly.

## 3. Assumption (root cause)

§3.1 The multiplication by `baseAsset.multiplier` (added when the engine's
`getOKXDenominator` was switched to prefer `multiplier`) was layered on top of
the original `÷ step-denominator` conversion instead of replacing it, so
`ctVal` is applied twice on read; the close path still divides by the
step-denominator, as it did before the engine switched.

## 4. Scope note

§4.1 OKX global swaps with `ctVal = 1` and a fractional `minSz` (step < 1)
also go through the step-denominator branch. They are left exactly as they
are here (§1.3); spec 297 fixes them.

## Invariants

None: the defect is a mis-read of live venue state in a query response, it
writes nothing to the database.
