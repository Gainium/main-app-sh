# 145 — a duplicate re-send reuses an id that already ends in `2`

Bug spec. Sibling of spec 136 (duplicate refusal is resolved before any
write-off), whose behaviour is unchanged.

## 1. Definition

### 1.1 Expected
When `sendOrderToExchange` writes an order off after a "duplicate client
order id" refusal and re-sends it, the re-send carries a client order id that
differs from the refused one, keeps the refused id's prefix and length, and
uses only characters the refused id's alphabet already allows (alphanumeric
tails, and hex for `0x…` ids).

### 1.2 Actual
The regenerated id is `id.slice(0, -1) + '2'`. When the refused id already
ends in `2` — one generated tail in 62, and every id this branch has already
regenerated once — the re-send carries the SAME id. It goes out with
`count = 1`, so it skips the duplicate branch, the venue refuses it again
(`Duplicated externalId + symbol`), and the order is written off for good:
that ladder level has nothing on the exchange.

## 2. Evidence

- Code: the duplicate branch of `sendOrderToExchange` in `src/bot/main.ts`.
- Production DCA bot log, Binance: safety order `D-RO-…6i2` was refused as a
  duplicate, the venue confirmed the original CANCELED, and the re-send under
  the identical id was refused 10 ms later with `Duplicated externalId +
  symbol`. Its sibling levels were re-placed and filled; this one never was.

## 3. Assumption (hypothesis)

The only defect is the suffix choice: a fixed `2` is not guaranteed to differ
from the character it replaces. Replacing the last character with `3` when it
is already `2` (and `2` otherwise) always yields a different id of the same
length and prefix; both characters are valid in every id alphabet in use.

## 4. Required behaviour

- §4.1 An id ending in `2` regenerates to a different id.
- §4.2 An id already regenerated once (ending in `2`) regenerates to a
  different id again.
- §4.3 Prefix and length are preserved; an id not ending in `2` regenerates
  exactly as before (`…2`).
- §4.4 Unchanged: spec 136 — the venue is asked first and a live original is
  kept rather than re-sent.

Tests: `src/bot/duplicateClientOrderId.spec.ts`.
