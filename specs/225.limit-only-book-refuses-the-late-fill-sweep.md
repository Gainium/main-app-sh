# 225 — A limit-only book refuses the sweep of a late fill on a closed deal

Bug spec (Definition / Evidence / Assumption). Tests:
`src/bot/limitOnlyLateFillSweep.spec.ts`. Sibling of spec `157`, which handles
the same refusal while the deal is still being closed.

## §1 Definition

When an entry-side order of a DCA deal (a safety order, or the base order)
fills after the deal has already closed, `updateDeal` /
`processFilledBaseOrder` ask `sellRemainder` to sell that fill back with a
MARKET order (`D-SR-…`). Callers that run after the close (spec `157`'s
`closeDeal` fallback path included) use the same send.

**Expected.**

- §1.1 If the venue refuses that MARKET sweep because the book is in limit-only
  mode (`isLimitOnlyReason`, `limitOnlyEntry.ts`), the same quantity is placed
  once more as a reduce-only LIMIT at the latest price, under a new `D-SR` id
  (spec `221`: a refused id is never re-sent).
- §1.2 When that LIMIT fills, its fill is booked to the closed deal exactly as
  an accepted MARKET sweep at that price would have been, and only once.
- §1.3 Unchanged: the MARKET sweep is always the first try; when the venue
  accepts it, that is the only send and it is booked as before.
- §1.4 Unchanged: a sweep refused for any other reason is reported and not
  retried.

**Actual.** The refusal is logged as a warning (hidden from the user) and
nothing else happens. The coins stay in the account, tracked by no deal and
sold by nothing.

## §2 Evidence (prod, read-only)

- `Gainium-DCA-bot` log, 2026-11-04T15:57:27.580Z: `Reason Orderbook is in
  limit only mode - please use limit order type Method limitOrders() Step Send
  new order request D-SR-…, qty 104.445, price 0.2299, side SELL` — a MARKET
  sweep of a part-filled safety order on a Coinbase spot pair, one second
  after that deal's take-profit filled. No order follows it.
- Spec `157`'s fallback line ("book is in limit only mode, cannot sell the
  remaining … Deal stays open") has no hits for these deals: the refusal did
  not come through `closeDeal`.

## §3 Assumption (root cause)

`sellRemainder`'s ordinary send (`sweep` absent) calls `sendGridToExchange`
without `returnError`, so the refusal is reported and swallowed inside the
send. Spec `157` added a limit fallback only to `closeDeal`'s `'send'` mode,
and that fallback (`closeRemainderByLimit`) needs an OPEN deal. A late fill
arrives with the deal closed, so nothing places a LIMIT for it.

Tests: §3.1 ← §1.1 (both callers), §3.2 ← §1.2, §3.3 ← §1.3, §3.4 ← §1.4.

## §4 Known limit

The booking context of a resting LIMIT sweep is held in memory. If the bot
restarts before it fills, the coins are still sold but that fill is not booked
to the closed deal.
