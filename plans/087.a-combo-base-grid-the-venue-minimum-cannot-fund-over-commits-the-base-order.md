3. `src/bot/comboHelper.ts` — new `refuseDealBelowMinimumBudget(symbol)`, built

4. `src/bot/comboHelper.ts` — `openNewDeal` calls it, immediately before
   `checkBalance`, and returns without opening a deal when it refuses, taking the

### 1.1 Decisions the spec left open

- **Where the guard reads its numbers.** It calls `getBaseOrder(symbol)` with no
  `dealId`, exactly as `checkBalance` already does — the call is read-only
  without a `dealId` (the `balanceStart` write is `dealId`-gated) and it is what
  populates `lastGridSizing` for the base grid. This costs one extra
  `getBaseOrder` per new-deal attempt, on a path that already sleeps 5 s and
  re-runs `checkBalance` on a shortfall. Rejected: reading the verdict off
  `checkBalance`'s existing call, because `skipBalanceCheck` and a set `action`
  both return from `checkBalance` before it ever sizes a base order, which would
  leave the over-commit reachable.
- **Not inside `getBaseOrder`.** Returning `undefined` from there would make
  `checkBalance` fall through its `if (!base)` bypass with `status: true`, and
  `placeBaseOrder` would then create a deal that never gets an entry order.
- **Order against `checkBalance`.** Before it: the configuration is wrong
  regardless of what the account holds, and reporting a balance shortfall
  computed from an over-committed base order would name the wrong cause.
- **Latch, not a stop.** Same `ConditionLatch` key shape and the same
  `handleErrors(…, 'openNewDeal', '', false, true, true, false, symbol)` call as
  the balance refusal beside it, so the alert names the pair and repeats once a
  day rather than once a cycle (spec 008).

## 3. Blast radius

1. **Other call sites of what changes.** `gridBudgetRefusalMessage` has two
   callers after this: `BotHelper.refuseStartBelowMinimumBudget` (passes no
   `advice`, output unchanged — pinned by `gridBudgetGuard.spec.ts §4.5`) and the
   new combo reader. `gridBudgetVerdict`, `gridLevelMinimum` and
   `lastGridSizing` are read, never modified. `openNewDeal` is combo-only; the
   DCA copy at `dcaHelper.openNewDeal` is untouched.
2. **`core/` submodule.** Yes — every file here is shared and deployed
   platform-wide (root `CLAUDE.md` Danger List #11). Consumers of these
   particular files are `main-app`'s bot workers only: `comboHelper`,
   `conditionLatch` and `gridBudgetGuard` are engine-internal, not part of any
   cross-service contract. **No** GraphQL field, REST shape, socket event name,
   Redis channel, RabbitMQ payload or Mongo document shape changes — the only
   externally visible artefact is the text of a bot message, which is already
   free-form and deliberately unclassified by `errorDict`.
3. **Documented couplings.** None touched. The new message is checked against
   `errorDict` by `§5.2`, so it does not steal another condition's
   classification.
4. **Other tests on this path.** `comboFuturesBaseGridSizing.spec.ts` (spec 086,
   7 tests — sizing unchanged, one control inverted), `gridBudgetGuard.spec.ts`
   and `gridBudgetRefusal.spec.ts` (spec 068 — must stay green untouched),
   `openNewDealRefusal` / `conditionLatch` specs (the latch).
