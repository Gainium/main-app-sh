# 007 — Plan

Spec: [`../specs/007.per-contract-bot-message-coalescing.md`](../specs/007.per-contract-bot-message-coalescing.md)

## Solution

Fixes the root cause the spec's Assumption names (§3): the coalescing key and
the re-raise cooldown key describe the bot, while the condition describes a
contract. Both are widened by `symbol` — for the per-contract subTypes only.

1. **`src/bot/errorRulesCache.ts`** — `DEFAULT_PER_SYMBOL_SUBTYPES`
   (`Agreement required`) + `isPerSymbolSubType(subType)`, and an optional
   `perSymbol` on `SubtypeBehavior` read from `boterrorsubtypes` so an admin can
   extend or override the list without a deploy. This file already owns the
   other per-subType write-path policy (`getSubTypeLogPolicy`,
   `logPolicyBucket`), so the question "how does this subType coalesce?" stays
   in one place.
2. **`src/bot/main.ts` — new private `buildCooldownKey(terminal, botId, subType,
   symbol)`** (Tier 1 extraction, JIT runbook): the three-way choice of what the
   re-raise window is a window *of* was an inline ternary that already had two
   cases and now has three. Named, documented and directly testable; still
   returns `string[]` for `RetryBackoff`, so no behaviour moved with it.
3. **`src/bot/main.ts` — `processError`** computes
   `perSymbol = !!symbol && isPerSymbolSubType(subType)` once and (a) takes its
   cooldown key from `buildCooldownKey`, (b) spreads `symbol` into the upsert
   key when `perSymbol`. Nothing else in the write changes: `symbol` was already
   `$set` on every occurrence via `onEvery`, so it is only moving from *over* the
   row to *under* it, and only for those subTypes.
4. **`src/db/schema.ts` — `botMessageCoalesceKey`** gains `symbol: 1` as its last
   field. Required, not cosmetic: the index is UNIQUE, so without it the second
   contract's insert collides on the prefix and is folded into the first
   contract's row — which is the defect.

### Contract decisions the spec left open

- **A short static allowlist, not "any occurrence carrying a symbol."** Most
  per-order failures (`Not enough balance`, `API keys error`, `User limit`) are
  one condition the bot meets on every pair it tries; splitting those per pair
  would give a 50-pair bot 50 rows and 50 notifications for one problem, which
  is exactly the flood coalescing exists to stop. Only conditions the user must
  clear *per contract* qualify, and today that is `Agreement required`.
- **Static in core rather than seeded into `boterrorsubtypes`.** Seeding needs an
  admin-app change, and this repo can ship without one. The DB value still wins
  where an admin sets it (`behavior?.perSymbol ?? DEFAULT_PER_SYMBOL_SUBTYPES`),
  so the list is extensible without a deploy the moment admin-app grows the
  column.
- **`symbol` appended to the index, not inserted mid-key.** Every existing reader
  and the un-widened upsert filter use the leading five fields, and an index
  prefix is still usable, so nothing else changes plan.
- **The cooldown key is widened too, not just the row key.** Widening only the
  row would leave §1.2.3 in place: the first contract's window suppresses the
  second contract's *first* refusal into the hidden lane, so the extra row would
  be written but never raised.
- **No give-up / park state for this rejection class**, deliberately. The retry
  is what lets the deal open the moment the user signs; the reported symptom is
  the retry being *silent about which contract*, not the retry itself.

## Blast Radius

1. **Other call sites.** `buildCooldownKey` is new and private, called once.
   `isPerSymbolSubType` is new. The only changed existing behaviour is inside
   `processError`, and it is gated on `isPerSymbolSubType`, which is false for
   every subType except `Agreement required` unless an admin says otherwise.
2. **`core/` submodule.** Yes — all four files are core (`main-app-sh`), shared
   by every consuming service and by self-hosted installs. `processError` is
   engine-wide, which is why the gate is an allowlist rather than a heuristic.
3. **Documented contracts** (root `CLAUDE.md` Danger List): #12, the shared Mongo
   `gainium` collections. `botMessages` is read directly by **admin-app**'s Bot
   Errors page. This change adds no field and removes none — `symbol` was already
   written on every row — it only changes *how many rows* a per-contract subType
   occupies, which that page renders as more rows, each correctly labelled.
   `SubtypeBehavior.perSymbol` is an optional read of a column admin-app does not
   write yet, which is why it is `?? static` and not required.
   The unique index change makes `syncIndexes()` drop and rebuild
   `botMessageCoalesceKey` on the next boot; measured at 98 ms locally, and the
   partial filter covers 49,429 of prod's 108,655 rows.
4. **Other tests on this path.** `core` `npm test` (277) — all green.
   main-app `tests/processErrorForce.ts`, `tests/handleErrorsSymbolRelay.ts`,
   `tests/dealStartBlocked.ts` — 17 passing / 9 failing both **before and after**
   this change (drifted fakes, pre-existing; see the memory note on
   `processErrorForce.ts`).
