# 054 — A failed balance read is reported to the user as a zero balance

Plan for [`specs/054`](../specs/054.a-failed-balance-read-is-reported-as-a-zero-balance.md).

## §1 Build order

The defect is at the producer (`checkAssets()` cannot express "I did not
read"), so the producer changes first and the two consumers follow.

1. **`src/bot/main.ts` — `checkAssets()` (§4.1).** Answer a read that
   returned nothing with `undefined` instead of an empty `Map`. Three
   failure exits: the `AuthFailureGuard` cooldown short-circuit, the
   `getBalance` `notok` branch, and the fall-through when there is no
   `this.exchange` to call at all. Partial DB figures are still served
   (`asset.size ? asset : undefined`).
2. **`src/bot/dcaHelper.ts` — `checkBalance()` (§4.2).** Guard directly on
   the `checkAssets` result and return `unknown: true` rather than pricing a
   map that does not exist.
3. **`src/bot/comboHelper.ts` — `checkBalance()` (§4.2).** Same guard; it is
   a separate `override` of the same defect.
4. **Both `openNewDeal`s (§4.3, §4.5).** Bypass on `unknown`; pass `symbol`
   to the shortfall `handleErrors`.

## §2 Contract decisions the spec left open

- **The `unknown` carrier is an optional property on the existing return
  shape**, not a new type or a thrown error. `checkBalance`'s callers read
  `.status` / `.required` / `.available` / `.price` off a union of object
  literals, so the new branch returns all four (zeroed) plus
  `unknown: true`. Both `checkBalance`s get an explicit `Promise<...>`
  return-type annotation so `.unknown` is reachable on the union and so
  combo's `override` stays assignable to the dca signature it overrides.
- **The 5-second retry is kept for an unreadable read.** It already exists,
  a transient venue failure is exactly what it can recover, and removing it
  would be an unrelated behaviour change. Only its debug text becomes
  conditional, because "Not enough balance" is the false claim being fixed
  and it should not be written at debug either.
- **The bypass calls `endMethod(_id)` before returning**, matching every
  other early return in `openNewDeal`; the refusal branch reaches the
  shared `endMethod` at the function tail instead.
- **JIT tier (Part 4): Tier 0.** The causal path is three guards inside
  existing methods. Extracting `checkBalance`'s sizing into a pure module
  is a real improvement and a genuinely larger radius than this fix — it
  is not sprung on a live-trading bug touch.

## §3 Blast Radius

1. **Other call sites of `checkAssets()`** — 11, all checked by hand:
   `dcaHelper` 6934 / 8795 / 9395 / 13447 / 13845, `comboHelper` 4082 /
   4960, `main.ts` 7089, `helper.ts` 751 / 4212 / 4241. **Every one already
   reads through `?.get(...)?.free ?? 0`**, and none iterates the map. The
   declared return type is _already_ `Map<...> | undefined`, so no caller
   is newly exposed to `undefined` — the compiler has always forced them to
   handle it. An empty `Map` and `undefined` therefore produce an identical
   value at all eleven; the only site whose behaviour changes is the one
   this fix changes deliberately. `getSmartSellOrderQty`'s parameter is
   literally typed `UnPromise<ReturnType<typeof this.checkAssets>>`.
2. **`core/` submodule** — yes. `main.ts`, `dcaHelper.ts` and
   `comboHelper.ts` are all shared `main-app-sh` code, deployed
   platform-wide (cloud + self-hosted). Pointer bump is deliberate.
3. **Cross-service contracts** — none touched. No GraphQL shape, no
   socket.io event name, no Rabbit queue, no Mongo schema. `botevents` rows
   keep their existing shape; this only changes _whether_ one false row is
   written, and populates the already-existing `symbol` field on it.
4. **Other tests that must stay green** — the whole `src/**/*.spec.ts`
   suite, and in particular anything exercising the spec-008 standing
   condition latch or the #789 limit-only entry path (§4.6 out-of-scope).

## §5 Gate 4 — plan verified against spec

Walked §1–§4.6. Every numbered behaviour appears in §4 above. The two
decisions in §2 (carrier shape, retry retained) are both things the spec
declined to specify as build detail — §3 of the spec fixes the _signal_
(`undefined`) and §4.2 fixes the _flag name_ (`unknown`), which this plan
adopts unchanged rather than re-deciding. The Solution fixes the cause the
spec's §3 Assumption names — the producer's inability to express "unread" —
and not the symptom (which would have been suppressing the message text in
`openNewDeal`).
