## Decisions the spec left open

- **No default on the deal schemas** (`dcaDealSchema`, `comboDealSchema`). A
  deal's settings override its bot's in the merge. A schema default there
  would hydrate `tp` into a deal that lacks the field and override its bot's
  explicit `techInd`/`webhook`, which §1.4 forbids.
- No data backfill. Rows already stored get `tp` only when mongoose hydrates
  them, and the engine sees `tp` in memory. A bot whose worker later saves
  `this.data.settings` persists that same, equivalent value.

## Blast radius

   self-hosted).
3. Contracts: the GraphQL schema is unchanged. Bot reads now return `tp`
   where they returned null, which matches what both dashboards already
   display. No socket or queue shape changes.
4. Tests: `signalDealOverrides`, `comboTpSlOwnPrice`, `dealCloseApproval`,
   `dcaReloadLadderDuplicate`, `newDealBalanceRetry`, `coldRestartOrderSnapshot`
   and `closeSweepResume` must stay green.

Behaviour change: open deals in this state get their TP placed, or their SL
armed, on the next order check after deploy. That is the goal, and it places
orders, so it is stop class `money`.

- Re-fix (§1.6 stored-state hold): `checkDealsStopLoss` is the only caller
