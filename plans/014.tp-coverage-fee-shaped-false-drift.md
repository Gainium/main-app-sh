# Plan 014 — Stop the take-profit coverage check reporting the fee as drift

Spec: [`specs/014.tp-coverage-fee-shaped-false-drift.md`](../specs/014.tp-coverage-fee-shaped-false-drift.md)
(issue #700).

## 1. Contract decisions the spec left open

**1.1 Where the tolerance lives.** On the drift, inside
`reconcileTpCoverage`, not on `tracked` inside `trackedPosition` — spec §1.5
and §2.4. `trackedPosition` keeps meaning "the base this deal still holds",
which is what its two other callers and every existing test read it as.

**1.2 How wide.** `|tracked| × fee / (1 − fee)`. That is the exact magnitude of
both `getTPOrder` branches — `× (1 − fee)` on a long, `÷ (1 − fee)` on a short
— so one expression covers both directions with no `isLong` plumbing into the
decision function.

**1.3 Where the fee comes from.** `worstFee(await this.getUserFee(symbol))` in
`checkTpCoverage`, i.e. the same accessor and the same `worstFee` reduction
`getTPOrder` sizes with (`dcaHelper.ts:13543`). This matters for correctness,
not tidiness: `main.ts:2173` short-circuits to `{maker: 0, taker: 0}` for a
`zeroFee` API key, so such a bot gets a zero-width tolerance here exactly as it
gets an un-shaved take-profit there.

**1.4 Optional, defaulting to 0.** `feeRate` is optional on the `venue`
argument so the decision still answers without it and the pre-existing tests
keep asserting the pre-#700 arithmetic unchanged. 0 is precisely the old
behaviour.

**1.5 Applied on both venue types.** Futures zero the quantity fee, so a
futures deal's drift is 0 and the tolerance is inert. Not gating on `futures`
keeps the decision function free of a flag it would otherwise need only to
narrow itself.

## 2. Build order

1. `core/src/bot/dca/tpCoverageReconcile.ts` — add the pure
   `unexplainedDrift(drift, tracked, feeRate)`; add optional `feeRate` to
   `reconcileTpCoverage`'s `venue` argument; feed the *unexplained* residue to
   the existing `isActionable` test instead of the raw drift; widen the
   not-actionable verdict text to name the residue.
2. `core/src/bot/dcaHelper.ts` — `checkTpCoverage` passes
   `feeRate: worstFee(await this.getUserFee(symbol))`. `worstFee` is already
   imported at line 135.
3. Tests, then the changelog + version bump.

No new helper was introduced beyond `unexplainedDrift`: `worstFee` already
exists in `./dca/tpFees` and is reused rather than re-derived, and the
placeability test is the file's existing `isActionable`.

## 3. Blast Radius

**3.1 Other call sites.** `reconcileTpCoverage` has exactly one production
caller, `dcaHelper.checkTpCoverage`; `trackedPosition` likewise, and it is not
modified. `unexplainedDrift` is new. Verified by grep across `src` and
`core/src`.

**3.2 `core/` submodule.** Yes — both changed files are under `core/`
(`main-app-sh`), shared with every consuming service. Mitigated by what the
change can do: `checkTpCoverage` runs only in the DCA/Combo bot engines, is
reached only from the reconcile pass, and (spec §4.1) can only ever *reduce*
what it reports. It cannot place, cancel or re-arm anything it would not have
placed, cancelled or re-armed before, in any consumer.

**3.3 Cross-service contracts.** None touched. No GraphQL shape, no REST
payload, no socket event name, no Redis channel, no RabbitMQ queue, no Mongo
field. The only externally-visible artefact is the text of a `[WARN]` log line,
which nothing parses in code — the `tp-coverage` fixed string an operator
greps for is unchanged.

**3.4 Behaviour of the correction path.** `BOT_TP_COVERAGE_REPAIR` is
untouched and still disarmed by default. Because the change only turns
`under`/`over` verdicts into `covered`, an armed engine gains no new target;
it loses the ten fee-shaped deals it would have reported, none of which it
could have acted on anyway (single `NEW` take-profit ⇒ `staleTps` empty,
`rearm` false).

**3.5 Other tests on this path.** `tpCoverageReconcile.spec.ts` (21 cases) and
`tpCoverageReconcile.harness.spec.ts` (17 cases, driving the real
`checkTpCoverage`) must stay green. The harness gained a `getUserFee` stub —
its absence is a real gap, since production has always had that method.
