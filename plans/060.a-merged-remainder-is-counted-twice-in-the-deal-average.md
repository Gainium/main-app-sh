## Contract decisions the spec left open

- **`br` only, not `[br, rebalance]`.** Settled in spec §4.3 with evidence, and
  pinned by two tests: `rebalance` is a real un-merged trade that
  `comboHelper.avgPrice` — the one cost-basis fold that can see those rows —
  deliberately includes.
- **No new helper.** `TypeOrderEnum.br` compared inline is what
  `loadOrders` (`main.ts`), `dcaHelper.ts:2661` and `:6440` already do. The
  reuse rule points at the existing enum, not at a new predicate; a
  one-member exclusion does not earn an abstraction.
- **`!==` rather than `![…].includes(…)`.** One member, so the array form
  would read as if a second exclusion were intended — which §4.3 says it is
  not.
- **The futures filter goes on the existing `let filledDealOrder` assignment**,
  before the sort, so the fold order is unchanged.
- **No history migration.** Spec §5. Deals keep whatever average they stored;
  the next recompute on a live deal corrects itself.

## Blast Radius

1. **Other call sites.** `getAvgPrice` is private with exactly three callers,
   all inside `dcaHelper`: `startDeal` (`:7622`), and two in `updateDeal`
   (`:8174` add-funds, `:8455` safety-order fill). `ComboBot` overrides both
   `startDeal` and `updateDeal` and uses its own `avgPrice`, so no combo path
   reaches this method — the change is DCA-only.
2. **`core/` submodule.** Yes — `main-app-sh`, shared and deployed
   platform-wide. The change is confined to one private method; it adds no
   export, no type and no signature change, so nothing outside `dcaHelper`
   can observe it except through `deal.avgPrice`.
3. **Cross-service contracts.** None touched. No GraphQL/REST shape, no
   socket.io event, no queue payload, no Mongo schema field is added or
   renamed — `dcadeals.avgPrice` / `settings.avgPrice` keep their type and
   meaning, and start holding the value they always claimed to hold.
4. **Spec `058` (`55c10f2`).** Unaffected and must stay so: that fix persists
   the MERGED parent row, which this change keeps counting. Only the separate
   `br` receipt stops being counted a second time. No file it touched is
   touched here.
5. **Other tests on this path.** `baseEntryTopUp.harness.spec.ts` (specs
   057/058), `evidenceFreeFilledPromotion.spec.ts` (028) and the rest of the
   `src/bot` suite exercise the surrounding order/deal machinery and must stay
   green.
