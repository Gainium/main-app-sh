# 144 — plan

## Build order

1. `dcaHelper.openNewDealMan`: pass `trigger: 'manual'` to `openNewDeal`.
2. `comboHelper.refuseDealBelowMinimumBudget(symbol, trigger?)`: report when
   `trigger === 'manual'` without calling `shouldReport`; `openNewDeal` passes
   its trigger.
3. Same `trigger === 'manual' ||` short-circuit in front of `shouldReport` at
   the combo balance refusal, the DCA balance refusal and the DCA
   single-position entry balance refusal.
4. Tests in `comboBaseGridBudgetRefusal.spec.ts`.

## Decisions

- Gate on the EXPLICIT trigger, not `resolveNewDealTrigger`: the resolver also
  answers `'manual'` for a bot whose start condition is manual, which would
  unlatch automatic calls on such bots.
- Short-circuit before `shouldReport` so a manual report never writes the
  latch timestamp (§1.3): the automatic loop's next report time is unchanged.
- JIT tier: none — one argument and one boolean term per site.

## Blast radius

1. Call sites: `openNewDealMan` is the only caller labelled `'manual'`; every
   automatic caller passes no trigger or its own label. The parent main-app
   `openNewDeal` overrides forward `trigger` unchanged; the loading-queue
   replay forwards it too. `resolveNewDealTrigger` already classified this
   call as manual (`skip && !dynamic`), so approval behaviour is unchanged.
2. `core/` — shared engine code (DCA and combo bots, cloud and self-hosted).
3. No GraphQL, socket, queue or schema change. A manual refusal writes one
   `botevents` row per click, bounded by the user's clicks.
