# Plan 108 — Merge Mongo's open orders into a cold-restart Redis snapshot

## Solution

In `MainBot._loadOrders`, on the cold-restart branch (`serviceRestart &&
!secondRestart && !skipRedis`, unchanged), after reading a non-empty snapshot:

1. Collect the deal ids to cover: the ids the caller passes in a new optional
   third argument, plus every `dealId` that appears in the snapshot.
2. If there are any, read `{ botId, dealId: { $in }, status: { $in: NEW,
   PARTIALLY_FILLED }, typeOrder: { $nin: liquidation, br } }` from
   `ordersDb`. Equality on `dealId` drives the `dealId_1` index, so the read
   touches only the orders of those deals (§1.1.4).
3. Merge by `clientOrderId`: a Mongo row is added when the snapshot does not
   have it, and replaces the snapshot row when its status is at least as
   advanced (`NEW` < `PARTIALLY_FILLED` < terminal). A terminal snapshot row
   is kept (§1.1.3).
4. If the read fails, log it and return the snapshot as before (§1.1.5).

DCA `loadOrders` passes its `keys` (the restored deal ids) as the third
argument. Combo reaches the same code through `super.loadOrders()`. Grid calls
`_loadOrders(undefined, true)` and never reads the snapshot.

The brief said "Mongo wins on status". The ranked rule gives the same result
for every row the open-only query can return, except that it never turns a
row the snapshot already has as terminal back into an open one. Order status
only moves forward, so that case can only be a lagging Mongo write.

JIT tier: none. The merge is a small pure function next to its only caller.

## Blast Radius

1. `_loadOrders` callers: DCA `loadOrders` (and Combo through it), Grid
   (`skipRedis`, unaffected). The DB-only path and the reload guard are
   unchanged.
2. `core/` (main-app-sh): shared by every main-app service; the DCA and Combo
   bot workers pick it up. No type, schema, GraphQL, socket or queue shape
   changes. The new argument is optional.
3. Mongo load: one extra indexed read per DCA/Combo bot per cold restart,
   bounded by its open deals' orders. Before this change a cold restart
   restored from Redis read no orders from Mongo at all.
4. `checkOrders` now sees orders it used to miss and checks them on the venue
   like any other resting order. A row that is no longer on the venue follows
   the existing not-found path.
