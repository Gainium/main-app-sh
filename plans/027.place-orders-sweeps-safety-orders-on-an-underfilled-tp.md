## Build order

1. **Test first** — `main-app/tests/processing/tpUnderfilledSweepsSafetyOrders.ts`.
   Copy the harness shape from `tpBurstInvariant.ts` (the established fixture for
   anything in `placeOrders`), reduced to one deal. Drive the real
   `DCABotHelper.prototype.placeOrders` with `orders: { new: [], cancel: [] }` so

   The test lives in `main-app` rather than `core` because that is where the

   `src/**/*.spec.ts`, a different idiom, and introducing a second one here is
   not warranted by this change.

2. **Fix** — `core/src/bot/dcaHelper.ts`, the `tpAfter` disjunct only.

## Contract decisions the spec left open

- **Which disjunct is guarded.** Only the `tpAfter` one. The
  `dealAfter.deal.status === DCADealStatusEnum.closed` disjunct is a direct
  statement that the deal closed and stays unguarded — a genuinely closed deal
  must still have its ladder pulled, and test §3 pins that.
- **Reuse, not a new helper.** `underfilledTpQty` already exists as a pure
  function (`core/src/bot/dca/partialTp.ts`) exposed on the class as
  `this.underfilledTpQty` (`dcaHelper.ts:15927`), with `PARTIAL_TP_TOLERANCE`
  measured against prod. `checkFilledTp` already calls exactly that at `:11014`.
  Nothing new is written; the existing predicate is applied at the second site
  that needed it. Grepped: `underfilledTpQty` has 4 call sites in the repo, all
  in `dcaHelper.ts`, and no near-duplicate partial-fill predicate exists
  elsewhere.
- **Log line.** The existing `handleLog` in the branch stays as-is; a new one is
  added on the skip path, worded like `:11018`, so the bot timeline shows the
  guard holding instead of falling silent. This is what made the defect
  diagnosable from logs in the first place.

## Blast Radius

1. **Other call sites of the changed expression.** The `tpAfter` lookup is local
   to `placeOrders` — declared at `:13976`, read once at `:13982`, never
   returned. `git grep tpAfter core/src` → 2 hits, both these lines. No other
   caller observes it.
2. **`core/` submodule.** Yes — `core/src/bot/dcaHelper.ts` is `main-app-sh`,
   shared code, deployed platform-wide (cloud + self-hosted). The parent pointer
   must be bumped deliberately. This is the change's main risk and is called out
   on the ship card.
3. **Cross-service contracts (root Danger List / main-app `CLAUDE.md`).** None
   touched. No GraphQL shape, no `/api/v2` route, no socket.io event name, no
   RabbitMQ queue or payload, no Mongo schema field, no `BaseReturn<T>`. The
   change is one boolean term inside one method; nothing is added to, removed
   from, or re-typed on any persisted or wire shape.
4. **Behavioural blast radius.** The guard can only ever make the branch fire
   **less** often, and only for a `dealTP` that is `FILLED` while short of its
   `origQty` by more than 5%. For every other order state the expression is
   byte-for-byte the previous behaviour. The worst case if the tolerance is
   mis-set is a deal keeping safety orders it no longer needs — recoverable, and
   `checkFilledTp` has already been making the identical judgement on the
   identical predicate in production since 2026-08-30.
5. **Other tests on this path that must stay green.** `tpBurstInvariant.ts`
   (drives `restoreWork` → `placeOrders`; its deals have no FILLED TP, so the
   guard is inert there), `tpRePlacePartialFill.ts`, `tpResizeCancelNeverPromotes.ts`,
   `orderProcessing.ts`, `marketEntryNotional376.ts`, `percentFundsBasis.ts`,
   `kucoinPriceProtection.ts` — i.e. the whole `processing:test` suite.

## JIT legacy extraction tier

**Tier 0.** The decision being corrected is already extracted: `underfilledTpQty`
is a pure function in its own module with its own tolerance constant and
documentation. The causal path needs that existing pure predicate *called*, not
new logic pulled out of `placeOrders`. Extracting the surrounding
closing-detection into its own module would widen a one-term fix inside a
22,903-line file into a refactor of a method five other tests drive — scope
creep, not a lower smell. Nothing new is added to `placeOrders` that would
itself need extracting.
