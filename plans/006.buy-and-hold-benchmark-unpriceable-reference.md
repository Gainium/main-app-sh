# 006 — Plan

Spec: [`../specs/006.buy-and-hold-benchmark-unpriceable-reference.md`](../specs/006.buy-and-hold-benchmark-unpriceable-reference.md)

## Solution

Fixes the root cause the spec's Assumption names (§3): a failed price lookup is
booked as a benchmark rate.

1. **Pure decision module** `core/src/bot/dca/buyAndHoldBenchmark.ts` — Tier 2
   extraction (JIT runbook): the benchmark arithmetic currently sits inline in
   two I/O-heavy methods and is untestable without a live bot. Exports
   `isBenchmarkRate`, `buyAndHoldOutcome`, `carryForwardBenchmark`. No DB /
   Redis / HTTP imports.
2. **`dcaHelper.updateEquityStats`** (~20512) — gate the price request on
   `getExchangeInfo` (§3.2), compute through `buyAndHoldOutcome`, and when it
   returns `null` leave `result`/`perc` alone and carry the chart's
   `buyAndHold` point forward instead of writing `0` (§1.1.1, §1.2.2).
3. **`dcaHelper.botUpdateStats`** (~21154) — same gate, same
   `buyAndHoldOutcome`. This site does not write a chart point (it carries
   `last.buyAndHold`), so only the ratio needs guarding.
4. **One shared private method** `benchmarkRate(pair)` on `DCABotHelper` for the
   `getExchangeInfo` → `getLatestPrice` gate, so the two sites don't duplicate
   it (main-app `CLAUDE.md`: duplicate helpers are an anti-pattern).

### Contract decisions the spec left open

- **Keep vs. clear on failure.** Keep the last computable value. Clearing to 0
  or `null` is the same information loss the defect already causes, and the
  dashboards render the field unconditionally.
- **Gate source.** `getExchangeInfo(pair)`, reusing the existing idiom at
  `dcaHelper.ts` ~12820 (`const ed = await this.getExchangeInfo(pair); if (!ed)`).
  It is cache-backed via `sharedData`, so it adds no per-tick network call.
  Deliberately *not* `confirmPairMissing` — that does forced re-reads with
  backoff and exists for the destructive "drop the pair and stop the bot"
  decision. Skipping one benchmark tick is not destructive, and a transient miss
  costs nothing because the value is simply carried forward.
- **`rate > 0` and not `rate >= 0`.** A genuinely worthless asset still quotes a
  tiny positive price; only a *failed* lookup yields exactly 0. Pinned by the
  "a real rate, however small, still computes" test.

## Reuse check (no new utility invented)

- `getExchangeInfo` — existing, reused as the listing gate.
- `!x || !Number.isFinite(x)` bail — the existing idiom at `dcaHelper.ts`
  ~13929, generalised into `isBenchmarkRate`.
- `[a, b, c].find((v) => Number.isFinite(v)) ?? 0` carry-forward — the existing
  idiom on the neighbouring `realizedProfit` line (~20543), generalised into
  `carryForwardBenchmark` and applied to `buyAndHold` on the same chart point.

Grepped `core/src/utils` and `core/src/bot` for an existing benchmark/rate
helper: none. The new module is arithmetic lifted out of the two call sites, not
a new capability.

## Blast Radius

1. **Other call sites.** `stats.numerical.ratios.buyAndHold` is written in
   exactly two places, both in `core/src/bot/dcaHelper.ts` (`updateEquityStats`
   ~20424/20526, `botUpdateStats` ~21151/21165). `grep -n "buyAndHold.symbol|updateEquityStats"`
   over `core/src/bot/*.ts` and `src/bot/*.ts` returns no others; `comboHelper`
   inherits `DCABotHelper` rather than redefining them.
2. **`core/` submodule.** Yes — this is `main-app-sh`, root Danger List #11
   (widest blast radius; cloud + self-hosted + prod). Mitigated by the change
   being confined to one bot-engine method pair with no exported shape change.
3. **Documented contracts.** None touched. No GraphQL/REST shape, no socket.io
   event, no RabbitMQ queue, no Mongo schema change — the same
   `stats.numerical.ratios.buyAndHold` and `stats.chart` fields are written,
   with the same types. Dashboards and `backtester` read them unchanged.
   Danger List #12 (shared Mongo collections read by legacy main-dash /
   admin-app) is *touched but not broken*: field set and types are identical,
   only the values become correct.
4. **Other tests on this path.** `core` mocha suite (`npm test`,
   `src/**/*.spec.ts`) must stay green, in particular the DCA specs under
   `src/bot/dca/`.
