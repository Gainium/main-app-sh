## Decisions left open by the spec

- **max(estimate, observed), not observed-only.** Observed-only would RAISE the close on
  every row whose fee is in quote or unreported (e.g. Kraken `fciq` BUYs, where the close
  SELL's own base fee is paid from exactly that headroom — see the `feeFactor` note in
  `createOrder`). max keeps every such case byte-identical and can only lower a close.
- **JIT extraction tier:** tier 1 (pure function extracted at the one call site touched).
  The surrounding combo branch is not restructured.
- **Refused-close restore (brief item).** Not changed. `restoreCloseAfterRefusal` re-arms
  through `getTPOrder`, so it now inherits the corrected size. Routing it through spec 015's
  `forceFullFeeSizing` fallback would not have helped the observed case: that fallback
  resizes to the ACCOUNT-RATE size, which is 0 on a zero-fee account — the same quantity.
