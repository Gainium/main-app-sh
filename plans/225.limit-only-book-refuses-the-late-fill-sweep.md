# 225 — plan

Spec: `specs/225.limit-only-book-refuses-the-late-fill-sweep.md`.

## Solution

1. `sellRemainder`, ordinary send (`sweep` absent): send with `returnError`.
   On a string answer, report it with the same `handleOrderErrors` call the
   `'send'` branch makes (setError/sendError off, as for every `D-SR`). If
   `isLimitOnlyReason`, call `sweepRemainderByLimit`.
2. `sweepRemainderByLimit` (new, private): re-sends the same grid as
   `OrderTypeEnum.limit` under a fresh `D-SR` id, recording the booking
   arguments (`dealId`, the fill's qty and price, `sellNotByOrder`,
   `updateBalances`) in `limitRemainderSweeps` by client id. If the venue
   answers FILLED at once and the entry is still there, it returns the order
   and `sellRemainder` books it as today; otherwise nothing is booked now.
3. `bookLimitRemainderSweep(order)` (new, protected), called from BOTH
   `processFilledOrder`s — dcaHelper's and comboHelper's override, since combo
   bots run the same `sellRemainder`: a FILLED order found in
   `limitRemainderSweeps` is removed from it and booked through
   `sellRemainder(…, force, lateEntryFill, { result: order })` — the existing
   booking code, unchanged. Whoever removes the entry books, so the send answer
   and the stream event cannot both book. The send never awaits fill
   processing, so the per-deal `sellRemainder` mutex cannot deadlock.

JIT tier: none — two narrow additions inside the existing legacy method; the
booking arithmetic is reused, not copied.

## Blast Radius

- Callers of `sellRemainder` with `sweep` absent: `updateDeal` (late safety
  fill), `processFilledBaseOrder` (late base fill), `closeDeal`'s post-close
  call when no pre-sweep was sent, and three `comboHelper` calls. All behave as
  before unless the venue answers limit-only.
- `core/` (main-app-sh) — shared; parent pointer bump needed.
- No contract, schema, GraphQL, socket or queue change. No new persisted field.
- Other tests on this path: `lateEntryFillAfterClose`, `limitOnlyCloseRemainder`,
  `zeroSizeOrderRefusal`, `reduceOnlyCloseMinimum`.
