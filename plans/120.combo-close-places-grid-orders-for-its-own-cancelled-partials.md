# 120 — plan: combo close places grid orders for its own cancelled partials

Spec: `specs/120.combo-close-places-grid-orders-for-its-own-cancelled-partials.md`.

## Build order

1. Harness test `src/bot/combo/closeInFlightGrid.harness.spec.ts`, red first.
   §4.1 and §4.2 fail with `BUY 22.38, 22.436, 22.492` placed: the
   production levels, all above the close price.
2. `comboHelper.ts`:
   - override `closeDealById` (undecorated; the base keeps its `@IdMute`).
     For a market or limit close of an `open` deal, count the running call
     and mark the deal close-requested. On return, when no call is left
     running and no dealTP is live for the deal, drop the mark;
   - `isDealClosing(dealId)` = a close is running, OR (close requested AND a
     dealTP is live `NEW`/`PARTIALLY_FILLED` and the deal is open). Evaluated
     when the placement happens, so a close order that disappears without
     closing the deal lifts the block by itself (§4.4);
   - `updateMinigrid`: its two `placeOrders` calls (the counter/rebuild diff
     and the post-minigrid-close deal ladder) also require `!isDealClosing`.
     All accounting before them is untouched (§4.3);
   - `afterDealClose` / `clearClassProperties` drop the state.
3. Core patch bump + CHANGELOG entry.

## Decisions the spec left open

- **Where the gate sits.** It goes in `updateMinigrid` only, not in
  `placeOrders`. `placeOrders` is shared with DCA and with spec 083's
  refused-close restore, which must still place. `allowToPlaceOrders` is
  not stretched over the whole close either: that flag also gates the
  close's own balance-refresh path (`allowToProcessBr`) and the restore.
- **Not `closeBySl`/`closeByTp`.** Setting them on a manual close would
  change how the close runs (`checkDealsStopLoss`, spec 049/050 trailing
  retries), which the brief puts out of scope.
- **Unchanged:** the fee-order block (already on `closeBySl`) and the
  base-minigrid-close → `closeDealById` branch. Neither places a grid order.

## JIT extraction tier

Tier 0 (no extraction). The change is two predicates on existing gates plus
a thin override. `updateMinigrid` is 600 lines of mixed I/O, and pulling
it apart is out of proportion to a two-line gate.

## Blast Radius

1. Call sites: `closeDealById` is called from combo (base minigrid close,
   SL at `comboHelper` ~5776, the stuck-deal sweep ~791), from dcaHelper
   (TP/SL/timer/slippage retry, `checkTPOrder` reposition), and from the API
   (`closeDCADeal`). All of them go through the override. Only market/limit
   closes of open deals are tracked; leave, cancel and start-status deals
   pass straight through.
2. `core/` submodule, shared by main-app only for this class (the combo
   engine runs in main-app's `Gainium-Combo-bot` workers). No type, schema,
   GraphQL, socket or queue shape changes.
3. No cross-service contract touched.
4. Other tests on this path: `combo/minigridWhipsaw.harness.spec.ts` (spec
   116, drives `updateMinigrid`), `comboGridCancelLedger.spec.ts`,
   `comboPartialBaseEntry.spec.ts`; full core suite green (1836).
