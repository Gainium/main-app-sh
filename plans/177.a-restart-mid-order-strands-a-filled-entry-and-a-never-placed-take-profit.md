# Plan 177 — A restart mid-order strands a filled entry and a never-placed take-profit

Spec: `specs/177.a-restart-mid-order-strands-a-filled-entry-and-a-never-placed-take-profit.md`.

## Build order

1. `src/bot/main.ts` — `neverPlacedOrderRetireMinAgeMs(reason)` (pure) and the
   `BOT_NEVER_PLACED_ORDER_MIN_AGE_MS` floor (default 5 min). `noteOrderNotFound`
   evaluates the `-1` retire on that floor BEFORE the 24h young-order guard, and
   returns whether it retired.
2. `src/bot/dcaHelper.ts` `checkOrders` (restart branch): a TP retired by
   `noteOrderNotFound` joins `unsentTPs`, so the existing grid comparison places
   it again (same mechanism spec 172 uses). A regular order retired the same way
   joins `canceledOrders`, the existing "Send order again" path.
3. `src/bot/dcaHelper.ts` `restoreWork` (start deals): on a cold restart, when the
   Mongo row is not FILLED but the order map holds FILLED,
   `confirmRestoredFilledEntry` asks the venue by client order id, saves the row
   and `startDeal` opens the deal. Otherwise unchanged.

No contract decisions were left open by the spec beyond the default floor, set
at 5 minutes: above the seconds-scale propagation lag the 24h floor guards
against on venues that answer definitively, and well inside the brief's
"within minutes".

JIT extraction tier: minimal — the floor choice is a pure exported function;
the restore and reconcile changes stay inline in the legacy methods they patch,
matching spec 172/174's treatment of the same loops.

## Blast Radius

1. Call sites: `noteOrderNotFound` — `dcaHelper.checkOrders` (TP + regular
   loops, both updated) and `helper.ts` grid restart check (return value unused;
   a grid `-1` order is now retired after 5 min instead of 24h and re-placed by
   the grid's next rebuild, as it was after 24h). No subclass overrides it.
   `restoreWork` change is DCA only (combo overrides `restoreWork`; hedge DCA
   uses the DCA one). The parent main-app `src/bot/dcaHelper.ts` does not
   override `restoreWork`, `checkOrders` or `noteOrderNotFound`.
2. All files are under `core/` (main-app-sh, public, shared). The parent's
   core pointer is bumped at ship.
3. No GraphQL/REST/socket/queue/collection shape change. `orders` rows are
   written with existing fields only (`status`), via existing `updateOrderOnDb`.
4. Other tests on this path: `orderNotFound.spec.ts`,
   `restartMidDealStart.spec.ts`, `restartUnsentBaseOrder.spec.ts`,
   `coldRestartOrderSnapshot.spec.ts`, full core suite.
