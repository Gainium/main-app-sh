# 293 — plan

## Change

- `src/bot/dca/closeSweepShortfall.ts`: two pure helpers.
  `filledTpAlreadyBookedAsPartial` (the restart decision, §1.1/§1.2) and
  `unsoldBaseProfit` (the §1.3 correction, `unsold × (price − avgPrice)`,
  capped at the base delta).
- `src/bot/dcaHelper.ts` `restoreWork`: after the existing underfilled-TP skip,
  skip the close when `filledTpAlreadyBookedAsPartial` holds. Remaining base =
  ledger base + queued entry fills (spec `238`) − booked take-profit fills,
  mirrored for a short. Minimum = the pair's `baseAsset.minAmount`; no exchange
  info means no skip.
- `src/bot/dcaHelper.ts` `closeDeal`: quote-profit `total` minus
  `unsoldBaseProfit(unsoldBase, …)`. `unsoldBase` is set only on the spec `267`
  `unsold` branch (spot LONG, quote profit), so every other close is unchanged.

## Blast radius

- Every DCA bot restart passes the new check. It skips only when every FILLED
  take profit is already in `tpHistory` with qty ≥ executedQty and base is still
  held, which only the keep-open branches of `closeDeal` produce. Multi-TP and
  multi-SL deals already skip on unfilled targets; their last target is booked by
  `closeDeal` itself and never in `tpHistory` before it.
- Profit: only closes stamped `unsoldBase`. `pureBase` and `pureQuote` are
  untouched. The bot total and the user profit step follow `total`/`totalUsd`.
- The parent main-app's `dcaHelper` calls core `restoreWork` and does not
  override it, nor `closeDeal`'s profit block.
- Combo, grid and futures: `unsoldBase` is never set there; the restart check
  depends only on `tpHistory`, which their whole-position closes do not write
  first.

## Not changed

The behaviour when two bots on opposite sides share the same coins (one bot's
orders lock the other's coins) is left as is. That is what produces the refused
sweep in the first place; here it is handled only by keeping the deal open.
