## Decisions the spec left open

- Linger length = the bot's latest unexpired retired route `at` + `RETIRED_ROUTE_TTL_MS` (60 s) +
  `LINGER_MARGIN_MS` (1 s). Timer is `unref`'d so it never holds a process open.
- The linger end runs under the same `@IdMute removeListener:${key}` id as `removeListener`, so an
  `addListener`/`removeListener` racing the timer is serialised; a timer-identity check makes a
  cancelled timer a no-op.
- "no route" is logged at **debug**: every fee-bearing FILLED report for any other process's bot on
  a shared account channel takes that exit, so at info it would flood.

DESIGN_CALL: §4.1 of 863763d said "removeListener forgets the bot's retired routes". That is
reversed: removeListener now keeps them (and the listener) for the retired-route TTL, because the
two evidenced drops are exactly a close that runs in the same tick as the last fill.

## Blast Radius

1. **Call sites.** `removeListener` is reached via `closeUserStream()` (`main.ts:3610`) from
   `dcaHelper.ts:32841`, `dcaHelper.ts:32873` and `helper.ts:3916`, and from every bot type's stop
   path. Behaviour change: when (and only when) the bot holds an unexpired retired route, its
   listener and channel subscription stay up to ~61 s after the close, and the bot instance is
   referenced until then. With no retired route, teardown is immediate as before.
2. **`core/` submodule.** Shared, deployed to every bot worker; the parent needs a pointer bump
   (done by `psh`).
3. **Contracts.** No GraphQL, REST, socket.io, Redis channel name, RabbitMQ queue or Mongo schema
   change. The rabbit `close stream` message is still sent at once; only the in-process Redis
   listener lingers. Liquidation broadcasts skip lingering bots.
4. **Other tests that exercise this path** (must stay green, run in the full core suite):
   `restartMidOrder`, `placementAnswerAfterStreamFill`, `placementFillFeeOnce`,
   `lateFillReportUnfills.harness`, `outOfBandHold`, `outOfBandRetry.harness`, `coldRestartOrderSnapshot`,
   `paperUnknownOrder`, `neverPlacedKrakenOrder`, and the rest of `src/bot/*.spec.ts` that construct a
   SharedStream.
