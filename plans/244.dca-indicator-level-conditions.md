# Plan 244 — Several indicator conditions per DCA level

Spec: `specs/244.dca-indicator-level-conditions.md`.

## Build order

1. **main-app-sh (core)** — types (`dcaLevel`, `hideOnChart` on indicators;
   `dcaLevel` on groups), Mongo schema, GraphQL types + inputs, v2 validator
   config, OpenAPI / SCHEMAS / AI guide. New pure module
   `src/bot/dca/indicatorLevels.ts` (levels, anchors, level groups, trigger).
   Engine call sites switched from "N-th startDca indicator" to "N-th level".
2. **backtester** — identical copy `src/dca/strategy/ti/levels.ts`; same call
   sites (`ti/index.ts` trigger, `main.ts` levels/anchor, `dcaBotFunctions`
   ladder size/sizes/distances). Release, then bump the dependency in
   main-app and the dashboard.
3. **main-dash-sh (dashboard core)** — level cards on the shared
   `IndicatorGroupsManager`; `hideOnChart` toggle on the shared indicator row;
   GraphQL fragments request the new fields; projected ladder, smart orders
   and frozen deal levels read levels via `utils/bots/dca/indicatorLevels.ts`.
4. Parent repos: core pointers, the `@gainium/backtester` bump, invariants
   pack `specs/244.invariants.json` (main-app parent).

## Decisions left open by the spec

- Level identity: `dcaLevel` string on indicators and groups, defaulting to
  the indicator's `uuid` (no migration, §1.3).
- Level size/distance stay on an indicator (the anchor), so
  `dcaIndicatorLevels` snapshots, variable bindings
  (`indicators.<uuid>.orderSize`) and the v2 API keep their shape.
- Fired-level bookkeeping (`indicatorActions.dcaOrder`) is set only when a
  level fires, so an AND group still waiting on a leg does not consume the
  candle.
- JIT tier: Tier 2 (pure module) for the level rules; the engine's
  orchestration stays in `dcaHelper` (Tier 0 elsewhere).

## Blast radius

- `core/` of main-app is `main-app-sh`: public, shipped to self-hosted and
  cloud. Additive fields only.
- GraphQL schema and public v2 REST: additive optional fields. The dashboard
  requests them, so a dashboard must not run against a main-app without them
  (ship main-app first).
- Shared Mongo `bots` collection: two new optional fields; admin-app reads
  bots but not these.
- `@gainium/backtester` engine (danger list #13): legacy inputs produce
  byte-identical output (whole suite's actual outputs compared before/after,
  including the indicator golden that runs DCA by indicators).
- Credits/indicator cap (`billableIndicators`, main-app and dashboard): the
  ladder counts as its largest level. Existing bots (single-indicator levels)
  keep counting one, so no existing bot's credit lock changes.
- Other paths reading startDca indicators: scale-AR (first startDca indicator
  as a value, unchanged), v2 validator (needs ≥1 startDca, unchanged).
