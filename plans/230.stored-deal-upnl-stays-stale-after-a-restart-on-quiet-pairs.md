# 230 — plan

## Build order

1. `dealMonitor.ts`: the first sample a process takes of a deal writes it when
   the stored uPnL is stale (§1.1.1). Replaces spec 229's `neverStored`, which
   is the "absent" case of the same condition.
2. `dcaHelper.ts`: extract the DCA stats payload from `priceUpdateCallback`
   into `sendDealStats` (records the deal in `dealsStatsSampled`) and
   `dispatchDealStats`; add `seedDealStats`, called un-awaited from
   `priceTimerFn` (§1.1.2, §1.1.3).
3. `comboHelper.ts`: override `sendDealStats` with combo's existing payload and
   call it from combo's `priceUpdateCallback` (§1.1.4). Payloads are moved
   verbatim, not changed.

Hooked on `priceTimerFn` because both `start()` implementations (core's and
main-app's override) arm `startPriceTimer()`; neither `start()` is edited.

## Blast Radius

- Writes: one extra `dcadeals`/`combodeals` `updateOne` by `_id` per open deal
  per bot load, only when its stored uPnL is stale (value moved and the last
  write is older than `NET_STATS_REFRESH_MS`). Same fields as today; no schema,
  GraphQL, socket or REST change.
- Exchange I/O: none added. The seed uses `lastStreamData`; a pair without a
  held price is sampled by the existing REST poll.
- Trading: none. The seed calls only the stats path, not
  `priceUpdateCallback`, so no TP/SL/DCA/trailing check runs from it.
- Mutex: the seed is not awaited inside `priceTimerFn`'s per-exchange mutex.
- Grid bots: untouched (`GridMonitor` is a separate path).

## Post-deploy check

The fix only takes effect when the bot workers restart onto it, which the core
ship path does. 10 min after that restart, list the reporter's open deals
whose `stats.updatedAt` is older than the restart, and match their pairs
against the venue's last trade. Expected: none whose held price implies a
different stored uPnL.
