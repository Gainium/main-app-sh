# Plan 225 — a flat deal waits for an unrelated event to take its second reading

Spec: `specs/225.a-flat-deal-waits-for-an-unrelated-event-to-take-its-second-reading.md`.

## Solution

In `reconcileDealPosition` (`dcaHelper.ts`, specs 005/175/185), when the
first answered "position gone" reading is recorded, arm a per-deal timer
(`armPositionReprobe`). It fires 5 s after the later of the probe window
(`dpp`) and the reading window (`dpg`) ends. When it fires, it calls
`reconcileDealPosition` again with the same outcome, trigger and settle.
That probe goes through the same throttle and the same readings count, so the
two-readings rule (§1.1.2) is untouched: the timer only replaces the price tick
or ladder re-placement that used to be needed to ask.

- Dedup per deal through `positionReprobes: Map<dealId, {misses, timer}>`.
  Re-arming replaces the timer (§1.1.3).
- `runPositionReprobe` re-reads the live deal and drops itself if the bot has
  stopped, or the deal is gone, not open, or `closeBySl` (§1.1.4). An answered
  probe that sees the position, and the settle branch, both call
  `clearPositionReprobe`.
- An unanswered probe re-arms only an existing chain, up to 3 misses (§1.1.5).
  An unanswered FIRST probe arms nothing, which is the same as before.
- Timer `unref()`, the same as `missingTpRearm`. A worker stop resets
  `deals`, so a pending timer finds no deal and drops.

JIT tier 0: two small protected methods beside the method they serve, plus
one private one. The timing is what is tested. There is no decision logic
worth extracting.

`@RunWithDelay` was rejected. Its latest-call-wins slot would let a later
first reading's arguments win, which is fine, but it cannot be cancelled when
the position is seen again or the deal settles. Cancelling is required by
§1.1.4.

## Blast radius

1. Call sites of `reconcileDealPosition`: `checkTPLevel` (default settle =
   `closeDeal`), `getTPOrder`'s under-minimum refusal, and combo
   `settleFlatDealAfterGridRefusal` (base-trigger settle, which re-checks the
   deal's state inside its closure). All three now also arm the timer on a
   first reading. No caller's return value changes.
2. The file is under `core/` (main-app-sh), so it runs in every DCA/combo bot
   worker. The parent pointer needs bumping.
3. No GraphQL, socket, queue, schema or Redis-key change (it reuses `dpp` /
   `dpg`). A new in-memory field only.
4. Tests that must stay green: `comboFlatDealGridRefusal` (175/185),
   `restingTpPositionGone`, `hyperliquidSharedPositionClose`, `hedgeMode`,
   `settingsReloadLeverage`, `newDealBalanceRetry`.
