# 021 — `commission` books the full estimate for an off-pair observed fee

Plan for [`specs/021.commission-double-books-third-asset-fee.md`](../specs/021.commission-double-books-third-asset-fee.md).

## Solution

Add an off-pair check to `getCommDeal`'s fallback branch, mirroring
`closeDeal`'s inline `if (feeByAssetGated && legs.length) { continue }`
— but **unconditional**, not gated behind `DCADealFlags.feeByAsset`.
That flag (spec 014, "new deals only") governs whether the NEW
`feeByAsset` ledger structure gets built — a migration concern for a
schema field that didn't used to exist. Whether `commission` double-
books a real observed fee is a plain correctness question with no such
migration concern: it affects every account with a genuine
BNB/BGB/KCS-style discount today, flagged or not, and there is nothing
"new-deal-only" about the fix.

```ts
async getCommDeal(findDeal: ExcludeDoc<Deal>) {
  const fee = await this.getUserFee(findDeal.symbol.symbol)
  const profitBase = await this.profitBase(findDeal)
  const dealPrice = findDeal.lastPrice || findDeal.avgPrice || 0
  return this.getOrdersByStatusAndDealId({
    status: 'FILLED',
    dealId: `${findDeal._id}`,
  }).reduce((acc, v) => {
    const price = parseFloat(v.price) || dealPrice
    const observed = price
      ? observedFeeSplit(v, findDeal.symbol?.baseAsset, findDeal.symbol?.quoteAsset)
      : null
    if (observed) {
      return acc + (profitBase
        ? observed.base + observed.quote / price
        : observed.base * price + observed.quote)
    }
    // A fee was observed, just not resolvable to base/quote (BNB/BGB/KCS,
    // or this session's third-asset test tool) — that's real information,
    // not "we don't know." Book 0 for this order rather than the estimate,
    // same rule `closeDeal`'s feeByAsset loop and `ordersFeeIsThirdAssetOnly`
    // already apply for feePaid/TP sizing (spec 014/015).
    if (
      observedFeeLegs(v, findDeal.symbol?.baseAsset, findDeal.symbol?.quoteAsset)
        .length
    ) {
      return acc
    }
    return acc + (profitBase
      ? parseFloat(v.executedQty) * (v.type === 'MARKET' ? (fee?.taker ?? 0) : (fee?.maker ?? 0))
      : parseFloat(v.executedQty) * parseFloat(v.price) * (v.type === 'MARKET' ? (fee?.taker ?? 0) : (fee?.maker ?? 0)))
  }, 0)
}
```

Needs `observedFeeLegs` imported into `dcaHelper.ts` — it's already
imported there (`:92`, used by `closeDeal`'s loop) — no new import.

This is the root cause the spec's Assumption names — one added branch,
same shape as the sibling check `closeDeal` already has two functions
away in the same file.

## Why no extraction

JIT tier **0**. `observedFeeLegs` is already the pure decision function
this repo uses for "was this order's fee off-pair" (spec 014) — this
is one more call to it from an existing `.reduce()` callback, not new
decision logic. `getCommDeal` itself is already a small, single-purpose
method; nothing here is decision-logic-mixed-with-I/O that needs
pulling apart.

## Blast radius

1. **Other call sites.** `getCommDeal` has 5 call sites in
   `dcaHelper.ts` and 4 in `comboHelper.ts` (grepped) — feeding
   `commission` (the TP-close paths) and `fullFee` (several combo/DCA
   bookkeeping points). The fix lives inside `getCommDeal` itself, so
   every caller gets it uniformly — none needs its own change. All 9
   are existing behavior asking the same question ("what should this
   deal's fee estimate be right now"); none has a reason to want the
   old double-booked answer.
2. **`core/` submodule.** `main-app-sh` — parent pointer bump at ship
   time.
3. **Contracts this repo owns.** No shape change — `getCommDeal`'s
   return type (`number`) and callers are unchanged. This changes a
   computed VALUE for accounts with an off-pair observed fee only;
   every other account (the overwhelming majority — no BNB/BGB/KCS
   discount, no third-asset test symbol) sees identical output, since
   `observedFeeLegs` returns `[]` for them exactly as before.
4. **Other tests.** No existing test exercises `getCommDeal` (grepped —
   none). `orderFee.spec.ts`'s `observedFeeLegs`/`observedFeeSplit`
   coverage is unaffected — this only adds a new caller, no change to
   either function.

## Test approach

Same constraint as spec 020 — `getCommDeal` lives on the same
`MainBot`-derived class, too heavy to instantiate for a unit test given
this repo's current tooling, and no lighter harness reaches it today.
Gate 2/6 here are the live reproduction already on file (spec 021 §2)
plus a fresh live re-run after the fix: same third-asset-fee paper deal
shape, `commission` should land near 0 (both fills off-pair) instead of
~2× the flat estimate. Flagging the same follow-up spec 020 did: a
`tests/processing/` integration case for this method is real, valuable,
and larger than this fix.
