# Plan 228 — repeated unfilled base-entry cancels pause the pair

Spec: `specs/228.repeated-unfilled-base-entry-cancels-pause-the-pair.md`.

## Build order

1. `src/bot/dca/partialBaseEntry.ts`: `refusedBaseEntryPauseAfter`,
   `refusedBaseEntryPauses(attempt)` and `refusedBaseEntryMessage(...)`. Pure.
2. `src/bot/conditionLatch.ts`: `refusedBaseEntry` latch reason.
3. `src/bot/utils.ts` + `errorRulesCache.ts`: `refusedBaseEntrySubType`,
   reported per pair like `orderBelowExchangeMinSubType`.
4. `src/bot/dcaHelper.ts`:
   - `refusedBaseEntryBackoff` (`RetryBackoff`, namespace `rbe`, 5 min → 1 h,
     2 h memory so that refusals spaced by a start cooldown still count as
     consecutive).
   - `cancelDealOfCanceledBaseEntry` → `noteRefusedBaseEntry(symbol)` after the
     deal cancel: record, and from the threshold on, remember the window in
     memory and report through the latch.
   - `refuseNewDealAfterRefusedEntries` — the gate, read from memory only (no
     Redis read on the per-minute start loop). After a worker restart the
     first refusal re-records at attempt ≥ threshold and restores the pause, so
     a restart costs one order.
   - `clearRefusedBaseEntries(symbol)` from `processFilledOrder` for a
     `dealStart` fill. `settlePartialBaseEntry` (the partly-filled path) is
     not touched: it is out of scope, and a partial fill never records a
     refusal, so it cannot start or lengthen a run.
   - `reportPerPairWarning(subType, symbol, message)`. `reportOrderBelowExchangeMin`
     now delegates to it, so there is one copy of the per-pair report.
5. `src/bot/comboHelper.ts`: call the gate after `refuseNewDealNearDelivery`
   (Combo has its own `openNewDealBody`), and clear in its `processFilledOrder`.
6. Test, CHANGELOG, version.

## Decisions the spec left open

- Threshold 3. One refusal can be a passing gap in the book. Three in a row,
  about four minutes apart for an ASAP bot, is a condition.
- The gate sits beside `refuseNewDealNearDelivery`: same manual/terminal
  bypass, same "quiet return" shape. The minute start loop retries on its
  own, so no timer is armed.
- JIT tier: decisions in the pure module, I/O stays in the helper (tier 1 →
  2 for the new logic only). Nothing legacy is pulled apart.

## Blast Radius

1. `cancelDealOfCanceledBaseEntry` callers: the armed timer only. The gate is
   new. `processFilledOrder` gains a guarded Redis DEL for `dealStart` fills.
2. All files are under `core/`: shared, parent pointer bump.
3. No GraphQL, socket, queue or schema change. One new Redis key family
   `rbe:cd:<botId>:<symbol>` with a TTL. One new bot-message subType (warning,
   never sets error status).
4. Must stay green: `reconnectCanceledBaseEntry`, `dca/venueCanceledBaseEntry`,
   `comboUnbuiltBaseEntry`, `userRefusalFeedback` and the full core suite.
