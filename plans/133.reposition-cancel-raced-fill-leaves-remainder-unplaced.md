# 133 — Plan: a reposition cancel that races a partial fill

Spec: [specs/133](../specs/133.reposition-cancel-raced-fill-leaves-remainder-unplaced.md)

## Solution

1. Tier 1 extraction (JIT runbook): move everything `settlePartialBaseEntryNow`
   does after its cancel into `bookCanceledBaseEntry(order, answer, observed,
   dealId, cancelled)`, unchanged — the forced `FILLED` write, the
   `awaitBaseEntryCancel` wait, the `noteSettled` mark with its
   fill-did-not-shrink guard, the spec `059` fill reconciliation and the
   unsettled mark. It returns `{ booked, settled }`, and the settle keeps its
   own warn. Not Tier 2: the chain is cancel/DB/venue I/O throughout; its pure
   decisions already live in `dca/partialBaseEntry.ts`.
2. The reposition arm of `checkBaseOrder` reads `observed` before the cancel
   and hands the cancel answer to `bookCanceledBaseEntry`. Booked → return.
   Otherwise it falls through to the existing re-place. The old FILLED-only
   branch is kept only for a row with no `dealId`.
3. In `bookCanceledBaseEntry`, a terminal no-fill row learnt from a re-read is
   persisted with the default filter (§4.3).
4. `noteReconciledBaseEntry(before, after)`, called by the DCA reconcile sweep
   for every row it finds newly `FILLED` (§4.5).

## Blast Radius

1. Call sites: `settlePartialBaseEntryNow` (restore, enter-market, reposition
   settle and stream-cancel paths) now goes through the extracted method with
   identical logic. `checkBaseOrder` is shared by DCA and combo (combo's
   `restBaseEntryRemainder` returns early, so the mark is a no-op there). The
   reposition arm now waits up to `baseEntryCancelSettleAttempts ×
   baseEntryCancelSettleDelayMs` (3 s) inside the `placeBaseOrder` mutex, only
   when the cancel answer was not terminal (OKX, Coinbase).
2. `core/` (main-app-sh): shared, but only the bot engine runs this path.
   Needs the parent pointer bumped.
3. Contracts: none. No GraphQL, socket, queue or schema change. Order rows get
   the same statuses as before, written sooner.
4. Tests: new `dca/repositionCancelRacedFill.harness.spec.ts`. Must stay
   green: `settleAsyncCancel`, `settleCancelNoFillReport`, `partialBaseEntry`,
   `baseEntryReposition`, `baseEntryRemainder`, `settledBaseEntryCancelReplay`
   and the full core suite.
