# 172 — plan

## Solution

1. **`dcaHelper.loadOrders` (§1.1.1, §1.1.2).** This step runs after
   `_loadOrders` has filled the order map, and before the orders of
   snapshot-restored deals are generated. It picks the snapshot deals that are
   `open`, have a FILLED `dealStart` order in the map, and have no non-entry
   order with a real exchange id. Only when there is such a deal does it read
   them from Mongo (`_id $in`, `status: start`). It is one indexed read and only
   for those deals. Each deal Mongo returns is dropped from `restoredFromRedis`
   and pushed onto `deals`, so the existing Mongo-load block sets it with empty
   orders, the way a Mongo load does. `restoreWork`'s filled-base branch then
   calls `startDeal`. If the read fails, the snapshot copy is kept and the
   failure is logged, as in spec 151 §1.1.4.
2. **`MainBot.retireUnsentOrder` (§1.1.3).** A new protected method next to
   `noteOrderNotFound`. It returns `true` and drops the order from the map only
   when all of these hold:
   - the order has `'-1'`;
   - the order is older than `unsentOrderMinAgeMs` (2 min, env
     `BOT_UNSENT_ORDER_MIN_AGE_MS`);
   - Mongo has no row for its client order id.

   It writes nothing to Mongo, because there is no row.
3. **`dcaHelper.checkOrders` TP loop (§1.1.3–§1.1.5).** On the service-restart
   pass only, a definitive not-found first tries `retireUnsentOrder`. If the
   order is retired, it is excluded from the resting set that the
   `tpOrdersInCurrent` comparison uses, so that existing block places the
   grid's take-profit through `placeOrders`. Otherwise `noteOrderNotFound` runs
   unchanged.

JIT tier: Tier 0. This adds a guard inside the existing legacy methods. The new
helper is I/O by nature (a Mongo existence check), so a pure extraction would
only move one comparison.

## Blast Radius

- Call sites: `loadOrders` is shared by DCA and Combo (`comboHelper.loadOrders`
  calls `super`). Combo snapshot deals get §1.1.1 too, and the condition is the
  same. The checkOrders change is in the DCA override only. Grid's
  `helper.ts` loop is untouched.
- `core/` (main-app-sh): public and shared. The submodule pointer needs a bump
  in main-app.
- No GraphQL, socket, queue or schema change. It reads `dcadeals`/`combodeals`
  by `_id` and `orders` by `clientOrderId`, both of which are indexed.
- Order-moving: §1.1.1 hands the deal to `startDeal`, which places the
  take-profit and safety orders. §1.1.3 places one take-profit. Neither path
  touches a deal whose non-entry orders carry a real exchange id.
- Tests that must stay green: `coldRestartDealSnapshot.spec.ts` (spec 151),
  `coldRestartOrderSnapshot.spec.ts`, `dcaReloadLadderDuplicate.spec.ts`,
  `comboReloadLadderDuplicate.spec.ts`, `comboPartialBaseEntry.spec.ts`,
  `ladderPlacementCap.spec.ts`, and the quarantine specs.
