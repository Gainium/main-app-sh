## Decisions the spec left open

- **Derive at close, don't track live.** The unpaired set is read from Mongo at
  the close (FILLED regular orders minus ids in paired transactions, the same
  two reads `loadOrders` already does), not kept as a running figure. A running
  figure would need a new persisted field and would drift across restarts,
  which is exactly when `loadOrders` only restores the in-memory unpaired set
  if `newProfit`/`profitBase` is set. The ledger is the thing the round trips
  were booked from, so it is the only complement that is exact by construction.
- **Return an entry price, keep the formula.** The close stays
  `qty × (close − entry) × (1 − maker)`; only `entry` changes. That keeps the
  `(1 − maker)` convention and the USD/ledger writes from spec 045 as they are.
- **Guard = signed quantity reconciles.** If the unpaired set does not net to
  the signed position (a fill not yet saved, a partial fill, a pre-`089`
  double-booked position), or a read fails, return `position.price` and warn.
- **JIT tier: none.** One pure-ish helper beside the method it feeds; no legacy
  extraction.
