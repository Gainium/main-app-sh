# 206 — plan

## Solution

In `sendOrderToExchange`'s refusal branch (`src/bot/main.ts`), split the
final write-off into its two halves:

- the in-memory `deleteOrder` stays gated on the map being populated;
- the DB write-off (CANCELED for a venue refusal, delete for a local one)
  also runs when the map was cleared, unless the failure is ambiguous.

JIT tier 0. One condition in place, no extraction: the branch is legacy, but
splitting it into a module is not needed to remove this defect.

## Blast radius

- Call sites: the refusal branch of `_sendOrderToExchange` only. Every bot type
  uses it. Behaviour changes only when `this.orders` is empty at refusal time,
  which happens only if something cleared the map during the placement,
  because `setOrder` adds this order first.
- `core/` submodule: yes, so the parent pointer has to be bumped.
- Contracts: none. Same `orders` statuses, no schema, GraphQL or socket change.
- Tests that must stay green: `strandedLocalRefusal`, `neverPlacedKrakenOrder`,
  `duplicateClientOrderId`, `cancelDuringPlacement`, `gridTpCloseSingleShot`,
  the full `npm test`.
