# 148 — plan

## Build order
1. `src/bot/settingsReloadLeverage.spec.ts`: drives the real `MainBot.loadData`
   twice (a user start, then a keep-orders reload) over a fake venue that
   counts `changeLeverage` / `changeMargin` calls. Red before the change.
2. `src/bot/main.ts`:
   - a `MainBot` instance field `appliedFuturesSettings: Map<symbol, key>`,
     where `key = leverage|margin|positionSide`;
   - in `loadData`'s futures loop, clear the map when `!this.reload`, so only
     keep-orders reloads can reuse it;
   - per symbol: skip both calls when `this.reload`, the stored key equals
     the current one, and the venue either reports no row for the symbol or
     reports one that matches. The existing `zeroPosition` leverage/margin
     predicates are hoisted and reused, not re-derived;
   - record the key only when both calls succeeded (a margin "No need to
     change" counts as success, as it already does for logging). A failed
     symbol is retried on the next load.
3. Version bump plus CHANGELOG in core, then a parent pointer bump, version and
   CHANGELOG.

## Contract decisions left open by the spec
- Key granularity: the symbol plus the exact values passed to the venue, with
  side derived from the live hedge read. A hedge-mode toggle therefore
  re-applies.
- Not cleared by `clearClassProperties`. That runs inside every `start()`,
  reloads included, and would defeat the memory. It is cleared at the loop
  instead, gated on `this.reload`.

## JIT tier
Tier 0/1 boundary: a small instance-state addition inside the legacy loop. The
loop is left otherwise untouched. Extracting it is out of radius for a latency
fix.

## Blast radius
1. Call sites: `loadData` is the only caller of `changeLeverage` /
   `changeMargin` in the bot engine.
2. `core/` file: shared with every main-app consumer (DCA, Combo, Grid,
   hedge legs). Grid's `reloadBot` never sets `this.reload`, so grid bots keep
   today's behaviour. So do hedge legs on a plain start.
3. No GraphQL, socket, queue or DB shape is touched.
4. Must stay green: `hedgeMode.harness.spec.ts` (drives the same loop) and the
   full core mocha suite.
