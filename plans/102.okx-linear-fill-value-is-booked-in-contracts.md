# 102 — An OKX USDT-margined fill's value is booked in contracts — plan

## Solution

One method, `MainBot.convertOrderQuoteQty(symbol, quote)`, beside
`convertOrderExecutedQty`, applied at each of the three writers named in spec
§1.2. It divides by the same `getOKXDenominator` the quantity is divided by, so
the two conversions cannot disagree on any `ctVal`.

JIT tier: 0/1. The helper is a named, tested unit. The surrounding order-merge
code is on the causal path only at the assignment, and it is not restructured.

Contract decisions the spec left open:

- Scope is `exchange === okxLinear && sizedInContracts`, not `sizedInContracts`
  alone. KuCoin already derives its quote from the converted quantity
  (`kucoinFutures` branches), and `okxInverse` takes the COIN-M quantity branch,
  so the contract arm of `convertOrderExecutedQty` never runs for it.
- Placement path (§4.4): only the payload's own `cummulativeQuoteQty` is
  rescaled. A quote inherited from the held row via `{ ...ord, ...processedOrder }`
  is already in base.
- No rounding: the stored value has always been an unrounded product.

## Blast Radius

1. Call sites. The quote is written by `getOrder`, by
   `convertExecutionReportToOrder` (also used by `getOrder`'s Redis cache read)
   and by `sendOrderToExchange`. Readers of the stored quote were checked:
   - grid balance/transaction accounting (`helper.ts`) is gated `!this.futures`;
   - `mergeCommonOrderWithOrder` already ignores the quote when
     `sizedInContracts`;
   - the placement and stream price derivations divide the RAW payload quote
     by the RAW contract quantity, before this conversion, so they are
     unchanged;
   - `fillEvidence` only asks whether the quote is non-zero;
   - dcaHelper and comboHelper only log it.

   The dashboards select the field but render nothing from it.
2. `core/` submodule (main-app-sh): this change is platform-wide. The parent's
   pointer bump happens at ship.
3. Contracts: no GraphQL, socket, queue or `BaseReturn` shape changes. The
   stored `orders.cummulativeQuoteQty` VALUE changes for new `okxLinear` rows
   only, and becomes consistent with every other venue.
4. Other tests: the full core mocha suite.
