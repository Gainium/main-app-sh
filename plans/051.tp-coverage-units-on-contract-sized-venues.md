# Plan 051 — take-profit coverage is measured in two units on contract-sized venues

Spec: `specs/051.tp-coverage-units-on-contract-sized-venues.md` (issue #788).

## 1. Solution

Put both sides of the comparison into ONE unit at the call site,
`dcaHelper.checkTpCoverage`, on each of the two contract-sized families. This
is the root cause the spec's Assumption names — §3 — not a symptom:
`reconcileTpCoverage` is unit-agnostic arithmetic and gets two quantities in
different units handed to it, because `getOrder` converts one of them back and
not the other.

The unit differs per family, and that is forced rather than a preference:

* **COIN-M** (spec §4.1) → **contracts**, because the base↔contract factor is
  the PRICE, so base is not conserved across a close.
* **OKX / KuCoin futures** (spec §4.6) → **base**, because that factor is a
  fixed denominator, so base IS conserved, the tracked side does not move at
  all, and only the venue's `origQty` is put back.

Rejected alternative, and why (spec §3 corollary): converting the venue's
contracts to BASE at the order's price and comparing against `deal.size` is
the conversion the triage brief proposed, and it is wrong — base is not
conserved on an inverse contract, so a healthy deal reads `under` by the whole
take-profit distance (`0.1068` BTC on the production deal). The other rejected
alternative, skipping `settings.coinm` deals entirely, is safe but leaves the
detector permanently blind on COIN-M, which is exactly what the check exists
to prevent.

Rejected alternative, exactness: re-deriving the position notional from the
filled entry orders, the way `getTPOrder` does at `dcaHelper.ts:15188-15214`,
is exact rather than `0.031%` off — and is a SECOND definition of the position
inside the check, the failure mode `014` documents. Spec §5 states the residual
bias, its direction and its ceiling instead.

## 2. Contract decisions the spec left open

| Decision | Choice | Why |
|---|---|---|
| Which predicate selects contract sizing | `this.coinm && !this.isBitget` | Byte-identical to `sendOrderToExchange` (`main.ts:7188`) and `convertOrderExecutedQty` (`main.ts:6996`). The check cannot disagree with the code that placed the order, whatever those two get right or wrong. |
| Which price converts `tracked` | each TERM at its own price; `deal.size` at `deal.avgPrice`, falling back to `lastPrice` | `getAvgPrice` (`dcaHelper.ts:7678`) builds `avgPrice` for every futures deal by folding fills through `calculateAbstractPosition`, which maintains the contract-weighted average. Verified to the last stored digit on the production deal. Converting the NET base once instead values a close at the entry average — 400 contracts sold at 83041.7 read as 372, a covered deal reads 29 `under` (spec §4.1). |
| What a term with no price of its own converts at | `deal.avgPrice` | Converting it to zero would drop a quantity that really sold and report a covered deal as `under`, which is the branch that acts. |
| Which price converts `executedQty` back | the order's own `price`, then `origPrice` | The inverse of the division `convertOrderExecutedQty` performed on the same field. |
| How the one-contract floor is expressed | `price: contractSize` into `isActionable` | `|qty| × contractSize ≥ quoteAsset.minAmount` is `contracts ≥ 1` exactly, because on COIN-M `quoteAsset.minAmount` IS the contract size. No new constant, no change to `isActionable`. |
| Where the unit label lives | optional `unit` on `reconcileTpCoverage`'s venue argument, default `'base'` | Keeps every string the existing suites assert on byte-identical. |

## 4. Blast Radius

1. **Other call sites of the functions changed.**
   `reconcileTpCoverage` — `grep -rn 'reconcileTpCoverage' src/` gives exactly
   one production call site (`dcaHelper.ts` `checkTpCoverage`) plus the two
   spec files. `trackedPosition`, `restingTpQty`, `unexplainedDrift`,
   `isActionable` are **not touched at all**; the new `unit` field is optional
   and defaults to today's value, so every existing caller is unchanged by
   construction. `checkTpCoverage` itself is private and has one caller,
   `checkOrdersAfterReconnect`.
2. **`core/` submodule.** Yes — both files are under `core/` (`main-app-sh`),
   shared/public/deployed platform-wide. The blast radius is nonetheless
   confined: `tpCoverageReconcile.ts` is imported only by `dcaHelper.ts`, and
   `checkTpCoverage` is reached only from the DCA reconcile pass. Nothing
   outside the DCA bot engine links to either symbol. The submodule pointer is
   bumped deliberately in the parent.
3. **Documented cross-service contracts.** None touched. No GraphQL/REST shape,
   no socket.io event name, no RabbitMQ queue, no shared Mongo collection
   field, no `BaseReturn<T>`. The only externally observable change is the text
   of a `handleWarn` line, which is consumed by log triage keyed on the
   `tp-coverage drift` prefix — unchanged. The check **places and cancels
   nothing** while `BOT_TP_COVERAGE_REPAIR` is unset, which is production
   today.
4. **Other tests on this path that must stay green.**
   `src/bot/dca/tpCoverageReconcile.spec.ts`,
   `src/bot/dca/tpCoverageReconcile.harness.spec.ts`,
   `src/bot/dca/tpCoverageRepairScope.spec.ts` — the `013`/`014`/`016`/`017`
   suites, all asserting on exact verdict strings in base. Plus the whole
   `npm test` suite from `core/`: **922 passing, 0 failing.**
5. **Deals on NEITHER family** — the large majority, 210 spot deals of the 233
   measured — must take a numerically identical path. Both new predicates are
   false there, so the conversions are not merely equivalent but unreached;
   pinned by the `AIXBTUSDT` case. This is also what keeps ledger note **F326**
   (spec §6) exactly where it was: that deal is `coinbase` spot.

## 6. JIT extraction tier

**Tier 0 — no extraction.** The causal path is a call-site mapping inside
`checkTpCoverage`; the decision itself already lives in a pure module
(`tpCoverageReconcile.ts`) from spec `013`. There is no decision-mixed-with-I/O
seam to cut, and the change adds none. A higher tier here would mean lifting
COIN-M unit handling out of `dcaHelper` — a real refactor of a 21k-line module
with thirty-odd contract-conversion sites, and scope creep on a unit fix.
