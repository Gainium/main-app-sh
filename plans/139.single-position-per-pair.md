# 139 — Single position per pair (backend plan)

Spec: `specs/139.single-position-per-pair.md`. Dashboard work is separate and
builds against the contract in §Contract.

## Contract (fixed with the dashboard)

- DCA settings `singlePosition?: boolean`, `maxPositionEntries?: string`
  ('' / '0' / missing = no limit): `types.ts`, db schema, GraphQL
  `DCABotSettings` / `createDCABotInput` / `changeDCABotInput`, v2 config +
  defaults + OpenAPI.
- Deal fields `positionEntries: Float`, `adoptedIds: [String]` (GraphQL
  `dcaDeal`).
- `adoptDeals(input: adoptDealsInput!): mergeDealsResponse`,
  `adoptDealsInput { botId, targetDealId, dealIds }`.
- `changeDCABot` / v2 update accept top-level `adoptOpenDeals: Boolean`.
- Reasons: spec §5.1.2, §5.1.4, §7.2, §8.1, §2.3.3 (`dca/singlePosition.ts`).

## Build order

1. Pure rules `src/bot/dca/singlePosition.ts` (reasons, validation, plans).
2. Types / schema / GraphQL / v2 config, defaults, generated definitions.
3. Engine (`dcaHelper.ts`): `singlePositionActive`; `openNewDeal` wrapper →
   `addPositionEntry` | `openNewDealBody`; entry fill in `updateDeal`'s
   add-funds branch; `checkInDynamicRange` reference; `adoptDeals`,
   `enableSinglePosition`, merge routing; `reportMaxDealsReached('entries')`.
4. Bot service (`index.ts`): validation in `prepareDCABot` / `changeDCABot`,
   enable-on-save refusals and dispatch, `adoptDeals`, `resetStatsAfter`;
   combo / hedge strip the setting; worker queue key for adoption.
5. Backtest refusal at every server-side request entry (GraphQL core +
   parent, v2 submit).
6. Parent: alert text for scope `entries`, backtest refusal, core bump.

## Decisions the spec left open

- Adopted entry fills are booked as additions (`dealRegular` + `addFundsId` +
  `deal.funds`), recorded in spec §4.2.3.
- Per-pair serialisation skips (not queues) a concurrent signal; the cloud
  parent additionally queues `openNewDeal` per pair under its own mutex.
- In-flight = deal still `start`, a resting entry / base remainder, or an
  entry sent and filled but not yet booked (`positionEntriesSent`).
- Adoption, conversion and merge share `runPositionOp` in the engine and the
  `mergeDeals<botId>` key in the worker queue, so the adoption can close the
  bot's own source deals directly.

## Blast radius

- `core/` is the public `main-app-sh` submodule; every change is additive
  and gated on `singlePosition`, which no existing bot has.
- `openNewDeal` is now a wrapper: bots without the setting call
  `openNewDealBody` (the unchanged previous body). Combo overrides
  `openNewDeal` and is unaffected.
- `mergeDeals` now runs under `runPositionOp`; without the setting the body
  is unchanged.
- `sendMaxDealsReachedAlert` gains scope `entries` (parent override updated).
- GraphQL / v2 shapes: additive fields and one new mutation.
- Suites that cover the touched paths: `mergedDeals.harness.spec.ts`,
  `botStatsResetCallSite.spec.ts`, `maxDealsReachedAlert.spec.ts`, the v2
  validator specs.
