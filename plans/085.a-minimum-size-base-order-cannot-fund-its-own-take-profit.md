# Plan 085 — a minimum-size base order cannot fund its own take-profit

Spec: `specs/085.a-minimum-size-base-order-cannot-fund-its-own-take-profit.md`.

## Build order

One edit, in one block, in one file.

1. `src/bot/dca/minSizeBaseEntry.harness.spec.ts` — written first, red on the
   `baseAsset.minAmount` branch (spec §1.1.a). Confirmed red for the stated
   reason: the real `getBaseOrder` returns `origQty: 60.06000001`, the same
   quantity the reported production entry carries, and `60.06000001 * (1 -
   0.001)` floors to `59.99994`, under the `60` floor.
2. `src/bot/dcaHelper.ts`, the `settings.useTp` close-floor block inside
   `getBaseOrder` — replace both `* feeFactor` raises with `/ (2 - feeFactor)`
   (spec §4.1).

Nothing else changes. No new helper: `2 - feeFactor` is the spelling of
`(1 - fee)` this block already uses three lines above to compute `tpQty`, and
reusing it is the point — the raise and the shave it compensates for are now
literally the same expression, so they cannot drift apart. `MathHelper.round`
already does the rounding.

## Contract decisions the spec left open

- **Which of the two raises.** Both. They are the same defect in the same
  block, one against the base floor and one against the quote notional floor,
  and the spec's §1.1.a states the invariant for both. Fixing only the one the
  reported case hit leaves the other producing the identical permanent-stuck
  shape on any pair where the notional floor binds first.
- **Direction of the change.** `1 / (1 - f) >= 1 + f` for all `f >= 0`, so
  every affected entry gets strictly larger (by `f²` of the floor — 6e-5 base
  on the reported pair). No case that satisfied the floor before can stop
  satisfying it.
- **Divide-by-zero.** `2 - feeFactor` is `1 - fee.taker`. A fee of 1 (100 %) is
  not a rate any venue quotes and would already make `tpQty` zero three lines
  above; not guarded, on purpose — a guard here would be dead code that implies
  the surrounding arithmetic survives it, which it does not.

## Blast radius

1. **Other call sites.** The two edited expressions occur nowhere else. The
   containing block is reached only from `getBaseOrder`, which is called from
   `placeBaseOrder` (+ the `terminal`/import branch, which returns before this
   block). `grep` for `baseAsset.minAmount * feeFactor` finds one more site 8
   lines below, `if (qty < ed.baseAsset.minAmount)`, which is **not** changed:
   that one raises the ENTRY to the venue minimum, not the close, and
   `minAmount * (1 + f) >= minAmount` already satisfies its own purpose.
   `comboHelper.ts` carries a structurally similar block (`4460`, `4468`) — out
   of scope, untraced, and combo deals are not what was reported.
2. **`core/` submodule.** Yes — `src/bot/dcaHelper.ts` is in `main-app-sh`, so
   this ships to every consumer of that core, cloud and self-hosted. The change
   is arithmetic inside one private method with no exported shape, so there is
   no type or contract surface: the blast radius is behavioural only, and only
   for entries that were already being raised to a venue floor.
3. **Documented contracts.** None touched. No GraphQL field, no socket event,
   no queue name, no `BaseReturn<T>`, no Mongo field. The order document's
   shape is unchanged; only one numeric field's value moves, by `fee²`.
4. **Other tests on this path.** `baseOrderQty.spec.ts`,
   `unbuiltBaseEntry.harness.spec.ts`, `partialBaseEntry.harness.spec.ts`,
   `unreadableBalance.harness.spec.ts`, `limitOnlyEntryReport.spec.ts`,
   `tpFees.spec.ts`, `tpCoverageReconcile*.spec.ts`, `multiTpCompletion.spec.ts`
   and the `qtyStepGuard` / `zeroSizeOrderRefusal` / `nanOrderRefusal` suites
   all exercise entry or close sizing and must stay green. The full `npm test`
   is the gate.

## Money-path note

This changes the quantity of a real entry order, on spot, for deals whose
configured base order is under a venue floor. It is an increase of `fee²` —
about one part in a million, `6e-5` base units on the reported pair — so the
notional moved is a rounding artefact rather than a position change. It is
still an order-sizing change and is called out as such on the ship card.
