# 142 — Plan: trailing ignores ticks older than the deal's latest fill

## Solution

Fixes the cause named in spec §3.1. `checkTrailing` now skips a deal for any
tick whose venue time is earlier than that deal's latest fill. The fill time is
recorded where every fill passes, at the first (non-duplicate) processing of
the order in `processFilledOrder`.

- `src/bot/dca/tickBeforeFill.ts`: a pure `isTickBeforeLatestFill(tick, fill)`.
  JIT tier 2. The decision needs no I/O, so it is pure and tested without
  mocks.
- `dcaHelper.ts`:
  - a `latestDealFillTime: Map<dealId, number>` field;
  - recorded in `processFilledOrder` (keeps the max, since fills can be
    processed out of order);
  - read in `checkTrailing` right after the price read;
  - dropped in `removeDealFromStopLossMethods`.

Rejected alternatives:

- Seed `lastStreamData` with the fill (the combo `unrealizedProfit` pattern).
  That would make `priceUpdateCallback` drop old ticks for every check (stop
  loss, DCA level, move-SL), not only trailing. Wider than the brief.
- Key on `deal.updateTime`. Many paths write local `Date.now()` there, so
  ordinary saves would make live ticks look stale.

## Blast radius

1. Call sites: `checkTrailing` is called only from `priceUpdateCallback`.
   `processFilledOrder` is the `onFilled` handler and the restore paths' entry.
   The new field is read nowhere else. Combo bots inherit both methods, so they
   get the same guard.
2. `core/` is the shared `main-app-sh` submodule. This is a bot-engine-only
   change: no types, GraphQL, REST, socket, queue or DB shape is touched. The
   parent needs a pointer bump.
3. Contracts: none. The guard relies on the existing meaning of a tick's
   `time`: the venue event time in milliseconds on every price connector
   (Binance `E`, Bybit/Bitget/OKX `ts`, KuCoin `time` / ns→ms, Kraken and
   Coinbase timestamps; Hyperliquid and the REST price poll use local now).
   Order `updateTime` is venue time in milliseconds too.
4. Tests that must stay green: every `src/bot/dca/trailing*` harness,
   `dealRefPrice.spec.ts`, and the full core suite.
