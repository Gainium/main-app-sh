# 135 — plan

## Solution

`tpSlEntryPrice()` returns `number | null`; the cold-cache branch returns
`null` after starting the refresh. `tpSl()`'s futures value-changed branch
returns `none` on `null`. `refreshTpSlEntry()` gains a `catch` that warns, so
its chained queue cannot stay rejected (§4.3). JIT tier 0: the touched code is
already a named private helper; no extraction.

The alternative — awaiting the refresh during load before the first tick —
was not taken: it covers only restarts, not the post-fill window or a
settings change, and adds an await to the load path of every grid.

## Blast Radius

1. Call sites: `tpSlEntryPrice()` has one caller, `tpSl()` (futures
   value-changed branch). `refreshTpSlEntry()` callers unchanged.
2. `core/` file (`src/bot/helper.ts`, the grid mixin): shared with every
   main-app consumer; the parent pointer must be bumped. No type, schema,
   GraphQL, socket or collection shape changes.
3. Only NEUTRAL non-COIN-M futures grids with a value-changed TP or SL are
   affected; the delay is one ledger read (two Mongo reads).
4. `gridPositionValue.spec.ts` (spec 064) drove a default-NEUTRAL bot without
   a ledger through single synchronous ticks, relying on the cold fallback;
   its harness now pins the entry to `position.price`, which is what that spec
   tests. `gridTpSlCloseBasis.spec.ts` (spec 117) stays green unchanged.
