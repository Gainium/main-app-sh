# Plan 130 — Smart Grids trimmed levels are never re-placed

## Solution

In `comboHelper.processCanceledOrder`, after the `dealGrid` type check and
before the `stillResting` check and the prune, return when
`this.isOwnCancel(order.clientOrderId)` is true. Fixes the root cause named in
spec §3: the branch did not distinguish a bot-issued cancel.

JIT tier 0: a one-line guard on an existing method; nothing is extracted.

## Build order

1. Regression tests in `comboGridCancelLedger.spec.ts` (red).
2. Guard in `comboHelper.ts` (green).
3. Version bump + CHANGELOG.

## Blast radius

1. Call sites: `processCanceledOrder` is the Combo override of the DCA
   `onCanceled` callback; `isOwnCancel` is the same check the DCA branches
   already use (spec 095). No other caller changes.
2. `core/` submodule (main-app-sh): shared; the parent pointer is bumped at
   ship.
3. No GraphQL, socket, queue or schema change. Stored minigrid `grids` and
   `assets` keep trimmed levels counted, as they did before spec 077.
4. Must stay green: the 15 existing cases in `comboGridCancelLedger.spec.ts`
   (spec 077, base-entry cancel) and the full core suite.
