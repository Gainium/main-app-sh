# 096 — plan

## Build order

1. `src/server/clientIp.ts`: `parseTrustProxy` + `getClientIp` (§4.1, §4.2).
2. `src/server/index.ts`: `app.set('trust proxy', parseTrustProxy(TRUST_PROXY))`
   right after `express()`; both keyGenerators and the Apollo context `ip`
   call `getClientIp` (§4.3).
3. `src/server/clientIp.spec.ts` over a real Express app and socket.

## Legacy tier

Tier 0: three one-line call-site swaps plus a new leaf module. Nothing else in
the server is touched (§4.4).

## Blast Radius

1. Call sites: the three in `src/server/index.ts` are the only raw
   `x-forwarded-for` reads in `src/`.
2. Under `core/`: this file is the standalone (self-hosted) server entry. The
   hosted service runs its own server entry, which already resolves the
   client address this way, and does not import this one.
3. Contracts: no API, schema, event or DB shape change. `ApolloContext.ip`
   keeps its type; its value is now the resolved address.
4. Behaviour change for a deployment behind a reverse proxy that does not set
   `TRUST_PROXY`: every client resolves to the proxy's address and shares one
   bucket. That is the safe failure (fewer attempts, never more); the proxy
   must append the peer to `X-Forwarded-For` and `TRUST_PROXY` must be set to
   restore per-client buckets.
