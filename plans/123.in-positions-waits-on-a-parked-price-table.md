## Decisions left open by the spec

- **A separate hash, not "don't `hDel`".** The `allPrice` field carries its
  own `hExpire`, so keeping it past the minute would mean changing what every
  bot caller reads. `allPriceLast` is read only by the new method.
- **Background refresh goes through `getAllPrices()`**, so it re-checks the
  minute cache and joins `fetchAllPricesOnce`; a stall costs one connector
  call no matter how many dashboard reads arrive.
- **No age cap on the last good table.** Whenever any process (bots included)
  fetches a good table it is rewritten, so it is old only while every fetch
  for that venue is failing — and then a live wait would fail too, scoring
  every asset at $0.
- JIT tier 0: one new method beside the one it wraps; nothing extracted.

## Blast Radius

1. Call sites: `priceBalancesUsd` is the only caller of the new method. It
   serves `dashboardInPositions` and `getBalances(includeUsdValues)` (plus
   `/user/balances?withUsd`). `getAllPrices` callers (bot engines,
   `additionalAPIs`, backtest) are untouched.
2. `core/` is the shared `main-app-sh` submodule: the parent's pointer must be
   bumped. No other service reads `allPriceLast`.
3. No GraphQL/REST/socket shape changes. New Redis hash `allPriceLast`
   (one field per exchange, one price table each).
4. Other tests on this path: none existing; full core suite must stay green.
