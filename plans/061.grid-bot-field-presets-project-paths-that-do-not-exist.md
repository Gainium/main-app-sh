# Plan 061 — Grid bot field presets project paths that do not exist

Spec: [`specs/061.grid-bot-field-presets-project-paths-that-do-not-exist.md`](../specs/061.grid-bot-field-presets-project-paths-that-do-not-exist.md)

## Solution

Rewrite the two `bots.grid` preset arrays in
`core/src/server/v2/fieldConfig.ts` so every entry is a path the grid bot
mongoose schema actually stores (spec §2.1), and add to `extended` the six
take-profit / stop-loss settings that make a read-modify-create round trip
lossless (spec §1.1, §3).

`GRID_BOT_STANDARD_FIELDS`

| was | becomes | why |
|---|---|---|
| `settings.symbol` | `settings.pair` + `symbol` | `settings.pair` is what `POST /api/v2/bots/grid` takes back, and is what the `bots.dca` / `bots.combo` standard presets already name; `symbol` is the stored `{symbol, baseAsset, quoteAsset}` object, which no other entry provides |
| `createdAt`, `updatedAt` | `created`, `updated` | the schema's own names |

`GRID_BOT_EXTENDED_FIELDS`

| was | becomes |
|---|---|
| `settings.gridLevels` | `settings.levels` |
| `settings.lowerPrice` | `settings.lowPrice` |
| `settings.upperPrice` | `settings.topPrice` |
| — | `settings.tpSl`, `settings.tpSlCondition`, `settings.tpSlAction`, `settings.sl`, `settings.slCondition`, `settings.slAction` |

No other file changes. Nothing is extracted: `fieldConfig.ts` is already a pure
data module with no I/O (JIT runbook **Tier 0** — the causal path is a constant
array, there is no decision logic mixed with infrastructure to cut apart, and
the consumers `fieldUtils.ts` / `middleware.ts` are equally pure). Reusing the
existing `parseFieldsParam` / `filterFields` helpers means no new utility.

## Blast Radius

1. **Other call sites.** `ENDPOINT_FIELD_CONFIG['bots.grid']` is read only by
   `getFieldConfig` (`fieldConfig.ts:445`), which is called only from
   `fieldUtils.parseFieldsParam` / `fieldUtils.getSelectionFor…` and
   `middleware.fieldSelectionMiddleware`. The only route registering
   `fieldSelectionMiddlewares('bots.grid')` is `GET /api/v2/bots/grid`
   (`api.ts:1016`). Nothing else consumes these two arrays — greppped for
   `GRID_BOT_STANDARD_FIELDS` / `GRID_BOT_EXTENDED_FIELDS` across `src/` and
   `core/src/`.
2. **`core/` submodule.** Yes — this is `main-app-sh`, shared and deployed
   platform-wide. The parent's pointer must be bumped deliberately.
3. **Owned contract.** `/api/v2/*` is the public `api.gainium.io` contract
   (root Danger List #2), consumed by `gainium-mcp`, `n8n-nodes-gainium`, the
   `chrome-extension` and both dashboards. The change is additive on the wire:
   every name removed never resolved to a value on any stored grid bot
   (0 / 2 956), so no consumer can be reading it; every name added resolves on
   every stored grid bot. `fields=full` and explicit comma-separated field
   lists bypass the preset table entirely and are untouched. The generated
   OpenAPI / AI docs describe the `fields` parameter's presets by name, not by
   their contents, so no generated artefact goes stale.
4. **Other tests on this path.** No existing spec covers `fieldConfig` /
   `fieldUtils`; the full `core` suite must stay green.
