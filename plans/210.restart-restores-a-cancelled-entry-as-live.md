# Plan 210 — restart restores a cancelled entry as live

Spec: `specs/210.restart-restores-a-cancelled-entry-as-live.md`.

## Solution
Tier 1 on the touched legacy code: two pure helpers in
`src/bot/orderSnapshotMerge.ts` (`unconfirmedOpenSnapshotIds`,
`dropOrdersEndedUnfilled`) and one extra, conditional `ordersDb.readData` at the
end of the snapshot branch of `MainBot._loadOrders`, after the spec 109 merge.
The optional hardening of `placeBaseOrder`'s "already active" check named in
the brief is not done: with the row no longer restored, the check is correct,
and loosening it risks a second entry on top of a live one.

## Blast Radius
1. Callers: `_loadOrders` is called by every bot type (DCA, Combo, Grid,
   hedge) on load; only the cold-restart snapshot branch changes. Reload and
   no-snapshot paths are untouched.
2. Under `core/` (main-app-sh): pointer bump needed in main-app.
3. Contracts: no schema, GraphQL, socket or queue change. One read on
   `orders` by `clientOrderId` (unique index), usually not issued at all.
4. Tests: `src/bot/coldRestartOrderSnapshot.spec.ts` (spec 108/109 cases stay
   green), `restartDealCounter.spec.ts`, the full core mocha suite.
