# Plan 062 — DCA and combo field presets project paths that do not exist

## Solution

Rename the dead paths in `core/src/server/v2/fieldConfig.ts` to the ones
`DCABotSettings` / the deal schema actually store. This is the root cause the
spec's §3 Assumption names: the preset table is the only place the wrong names
appear; nothing downstream needs to change.

| preset | remove | add | why this pairing |
|---|---|---|---|
| `DCA_BOT_STANDARD_FIELDS`, `COMBO_BOT_STANDARD_FIELDS` | `createdAt`, `updatedAt` | `created`, `updated` | the stored names (spec §2.1); matches what 061 did for grid |
| `DCA_BOT_EXTENDED_FIELDS`, `COMBO_BOT_EXTENDED_FIELDS` | `settings.stopLoss` | `settings.useSl`, `settings.slPerc` | the value alone is not enough: `DCA_FORM_DEFAULTS.useSl` is `false`, so a round trip that reads back only `slPerc` still disarms the stop loss |
| ″ | `settings.trailingDeviation` | `settings.trailingTp`, `settings.trailingTpPerc`, `settings.trailingSl` | `trailingTpPerc` is the deviation; `trailingTp` is the toggle that governs it (`bot/utils.ts:1161`) and defaults to `false`; `trailingSl` is the other trailing exit, validated at `:1071`, and also defaults to `false` |
| ″ | `settings.maxSafetyTradesCount` | `settings.ordersCount`, `settings.activeOrdersCount` | `ordersCount` is the max safety-trade count; `activeOrdersCount` (how many rest on the book) defaults to `1` and is reset without it |
| `DCA_DEAL_EXTENDED_FIELDS` | `settings.safetyOrderSize`, `settings.maxSafetyTradesCount` | `settings.orderSize`, `settings.ordersCount` | the stored names. Deals have no create endpoint, so there is no round trip to keep lossless — this is a pure rename, no toggle needed |

`COMBO_DEAL_EXTENDED_FIELDS` is an alias of `DCA_DEAL_EXTENDED_FIELDS` and
needs no separate edit.

### Deliberately NOT changed

- `2e2a05b`'s grid preset lines and the `fieldConfig.ts` comment above
  `GRID_BOT_EXTENDED_FIELDS` — 061's fix, still correct.
- `settings.baseOrderSize`, which resolves on every document.
- `api.ts:1240`'s use of `bots.dca` for `/bots/:botType/details` — spec §4.2,
  its own defect.

### Reuse check

No new helper. `unresolvedPaths()` in `gridFieldProjection.spec.ts` is already
preset-agnostic and is reused verbatim for the new fixtures; the production
name lookup is `DCABotSettings` in `core/types.ts`, not a new mapping table.

## Blast Radius

1. **Other call sites.** `DCA_BOT_*_FIELDS` / `DCA_DEAL_EXTENDED_FIELDS` are
   referenced only from `ENDPOINT_FIELD_CONFIG` in the same file; that table is
   read only by `getFieldConfig` → `parseFieldsParam`. Endpoints reached:
   `GET /api/v2/bots/dca` (`api.ts:254`), `/bots/combo` (`:357`),
   `/bots/:botType/details` (`:1240`), `/deals/:dealType` (`:463`),
   `/deals/:dealType/details` (`:634`). `syncStream.ts` and the hedge paths do
   not use these constants.
2. **`core/` submodule.** Yes — `main-app-sh`, shared and deployed
   platform-wide. Needs a submodule commit plus a pointer bump in `main-app`.
   Public repo: no bug numbers or user detail in the `core/` commit message.
3. **Owned contract.** Root Danger List #2, the public `/api/v2/*` shape.
   Additive on the wire (spec §5): the removed names resolved on **0**
   documents in production, so no consumer can be reading them; the added ones
   resolve on every document. No schema, socket or queue name changes.
4. **Other tests on this path.** `gridFieldProjection.spec.ts`'s existing grid
   cases (061) must stay green — they move into the renamed file unchanged.
   Full `npm test` in `core`.
