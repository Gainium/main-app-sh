# Plan 227 — a venue-cancelled base entry seen only by the reconnect check

Spec: `specs/227.venue-cancelled-base-entry-seen-only-by-reconnect-check.md`.

## Build order

1. `src/bot/dcaHelper.ts`, `checkOrdersAfterReconnect`: after the changed-status
   branch has deleted the row from the map and written it to the DB, a
   `dealStart` row answered CANCELED goes to `checkUnfilledBaseEntryCancel`.
   The existing predicate decides (CANCELED, nothing executed, `start` deal, not
   an own cancel, no other live entry); nothing new is decided here.
2. Spec test `src/bot/reconnectCanceledBaseEntry.harness.spec.ts` (DCA + Combo).
3. `CHANGELOG.md` + `package.json` patch bump.

## Decisions the spec left open

- **Called after `deleteOrder`.** `liveBaseEntries` reads the map, so the row
  must be out of it first or it would count as its own live entry. It already
  is: the changed-status branch deletes before it does anything else.
- **No Combo copy.** Combo does not override `checkOrdersAfterReconnect`; it
  inherits the DCA one. `helper.ts`'s copy is the Grid bot's, which has no
  deals and no base entry.
- **JIT tier 0.** The pass is legacy (venue I/O + decisions inline), but the
  decision already lives in a pure module (`dca/partialBaseEntry.ts`); this is
  one call into it.

## Blast Radius

1. Callers of `checkOrdersAfterReconnect`: the user-stream reconnect callback
   (DCA, Combo), `start`/restore (`checkOrdersAfterReconnect(botId, false)`),
   and the fill-failsafe / periodic reconcile sweep (`reconcileViaSweep`). All
   now arm the check for an unfilled venue-cancelled entry. On the restore path
   an entry re-placed afterwards is a live entry, so the pending check finds it
   and does nothing (spec 205 §4.2 / `cancelDealOfCanceledBaseEntry`).
2. `core/` file — shared; parent pointer bump needed.
3. No GraphQL / socket / queue / schema change. The only effect is that a
   `start` deal is cancelled (`CloseDCATypeEnum.cancel`) 15 s later, as the
   queue route already does.
4. Other tests on this path: `dca/venueCanceledBaseEntry.harness.spec.ts`,
   `comboUnbuiltBaseEntry.harness.spec.ts`, the `startReconcilesBook` harnesses,
   the full core suite.
