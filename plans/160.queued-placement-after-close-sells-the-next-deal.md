# 160 — plan

Spec: `specs/160.queued-placement-after-close-sells-the-next-deal.md`.

## Solution

All in `src/bot/dcaHelper.ts`.

1. New `dealReleased(dealId)`: true when the deal is no longer in the bot's
   deals (`getDeal`, keyed as a string), false for simple terminal deals, which
   is the same exclusion `dealClosedByFilledTp` makes.
2. `placeOrdersHoldingDealLock`, top of the method: a released deal places
   nothing and logs the skip (§1.1). It cancels nothing, because
   `processDealClose` is already sweeping that deal's orders.
3. Same method, order loop, right before each send: a released deal, or (outside
   the spec 083 restore) a full TP fill per `dealClosedByFilledTp`, stops the
   loop with a log naming the dropped order (§1.2). The existing post-loop
   block then pulls the resting ladder, as it already does for a close it sees.

JIT tier 0: a predicate method beside its sibling, plus two guard sites in the
existing orchestrator. Nothing on the path calls for extraction.

## Decisions the spec left open

- `break`, not `continue`: once the deal is closed, none of the rest of the
  burst should go out.
- The batched ladder phase (spec 082 §7) gets no extra check. It runs right
  after the top-of-method check and sends only safety orders. A close that lands
  during that phase is still seen by the post-loop block.
- The spec 083 opt-out does not cover `dealReleased`: a released deal has no
  position left for the restore to cover.

## Blast Radius

- Call sites: every `placeOrders` caller in DCA, combo and hedge (startDeal,
  updateDeal, checkOrders, checkTpCoverage, restoreWork, rebuildDealOrders,
  cancelTerminalDealOrder, dropCanceledReduceFunds, comboHelper). Each passes
  a deal it read from memory. A deal missing at placement time only happens
  after `deleteDeal`, and in that case no fill could be booked anyway. The parent
  `src/bot/dcaHelper.ts` does not override this method.
- `core/` (main-app-sh): shared, deployed to the bot workers. The parent pointer
  needs a bump at ship.
- No GraphQL/REST, socket, queue or schema change.
- Tests that must stay green: `lateLadderAfterClose`, `canceledTpRestore`,
  `refusedCloseRestore`, `restingTpPositionGone` harnesses, the rest of
  `src/**`, and the parent's `tests/processing/*` placeOrders harnesses
  (`tpBurstInvariant`, `tpUnderfilledSweepsSafetyOrders`, `refusedCloseRestorePlaces`,
  `tpResizeCancelNeverPromotes`, `tpDiffCancelNeverPromotes`, `tpRePlacePartialFill`).
