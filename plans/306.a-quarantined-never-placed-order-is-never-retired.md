# Plan 306 — retire a quarantined never-placed order

## Build order

1. `src/bot/main.ts` — `isOrderQuarantined` returns false for a `'-1'` order,
   so the restart probe asks the venue about it and `noteOrderNotFound`
   retires it (spec 109) on a definitive answer.
2. `src/bot/main.ts` — extract spec 109's retire out of `noteOrderNotFound`
   into `retireNeverPlacedOrder(order, reason, now)`. `noteOrderNotFound`
   calls it first; behaviour there is unchanged.
3. `src/bot/dcaHelper.ts` `checkOrdersAfterReconnect` (DCA and Combo) — a
   definitive not-found (`isDefinitiveOrderNotFound`) for a `dealRegular`
   calls `retireNeverPlacedOrder`; a retired order is not counted as
   unresolved. After `processOrdersAfterCheck`, each retired order of an open
   deal whose book is not being rebuilt is placed again through `placeOrders`.
4. `src/bot/helper.ts` `checkOrdersAfterReconnect` (grid) — same retire, no
   re-placement (the restart check's grid diff places the empty level).
5. Harness `src/bot/quarantinedNeverPlacedOrder.harness.spec.ts`.

## Decisions

- The reconnect pass calls `retireNeverPlacedOrder`, not `noteOrderNotFound`:
  the latter also adds quarantine strikes and posts the not-found notice,
  which the reconnect pass deliberately never did. Only the retire is new.
- All of spec 109's guards are reused unchanged: `'-1'` id, never-placed age
  floor (spec 177 §1.2), the strikes feature flag, and the bot's own "no
  exchange order id" answer never retiring (spec 184 §4.4).
- DCA reconnect retires only safety orders. A `'-1'` take-profit is left to
  the restart check, which already retires it and places its replacement
  (spec 177 §1.2.1); retiring it here without re-sizing would leave the deal
  without a TP until then.
- Re-placement goes through `placeOrders`, so the spec 283 price-band hold
  and its notice apply as for any other safety order.

## Blast Radius

- Only orders whose `orderId` is the `'-1'` placeholder can change state. An
  order with an exchange id follows exactly the old paths (tests §4.5).
- Restart probe: a quarantined `'-1'` order now costs one venue lookup per
  restart until retired (at most once in practice).
- Reconnect pass: no extra lookups (it already asked); a retired order writes
  one `CANCELED` row and logs one line.
- Re-placing a safety order is an order placement (money). It happens only
  for an open deal not under a book rebuild, at the order's stored level and
  size, rounded to the pair's base precision. If the price has crossed the
  level it may fill at once — the same outcome the restart path already has
  for a never-placed order it retires.
- Grid: retire only; placing waits for the next restart, as on the grid
  restart check. No schema, GraphQL, stream or contract change.
