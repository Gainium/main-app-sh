# 092 — Plan

## Solution

Fix the cause the spec's §3 Assumption names: `SchemaGenerator` never learns
what a string-literal union type alias is, so it emits `{ type: 'object' }`.

1. **Collect string-literal union aliases.** In `parse()`'s first pass (where
   TS `enum` declarations are already collected), also record every
   `TypeAliasDeclaration` whose type is a union of string literals — or a bare
   string literal — into a new `stringLiteralUnions: Map<string, string[]>`.
   A separate map rather than reusing `this.enums`, because `this.enums` is
   also walked at `:1292` to log "enum schemas" and these are not TS enums.

2. **Resolve them in `parseTypeNode`.** For a `TypeReferenceNode`, right after
   the existing `this.enums` lookup, check `stringLiteralUnions` and return the
   same `{ type: 'string', enum: values }` shape. Every downstream consumer
   (`parseProperty`, array items, `generateOpenAPISchema`) already handles that
   shape — nothing else changes.

3. **Correct the four invalid examples** in `fieldMetadata` to a member of the
   field's enum (spec §4.2): `prioritize` `'volume'`→`'gridStep'`,
   `tpSlCondition` `'any'`→`'priceReached'`, `tpSlAction` `'close'`→`'stop'`,
   `slCondition` `'price'`→`'priceReached'`, `slAction` `'closeAll'`→`'stop'`.
   `gridType`'s `'arithmetic'` is already a member and stays.

4. **Regenerate** `src/server/v2/openapi-v2.yaml` via `npm run generate:schemas`
   (spec §4.3), and delete the `.backup` artefact it drops beside the YAML.

5. **Version bump + changelog** per `main-app/CLAUDE.md` (patch; public-repo
   wording — mechanism only).

### Why not source the enums from `gridBotSchemaConfig`

The triage brief proposed reading the enum values out of
`validators/bots/config.ts`. Rejected as the *generator* mechanism, kept as the
*test* mechanism:

- `SchemaGenerator` is a standalone TS-AST parser over `types.ts`; it is run by
  `ts-node` with no app boot. Importing `config.ts` pulls the validator module
  graph into a docs script for values that are already stated, identically, in
  `types.ts` — which is the source the runtime types come from.
- It would fix only the grid fields named in the brief. Resolving the alias
  fixes `profitCurrency` and `orderFixedIn` too (also `type: object` today, see
  spec §1 evidence probe) and every future alias-typed field in DCA/Combo
  schemas — the same defect, one cause.
- The anti-drift guarantee the brief asked for is delivered instead by gate 2's
  test, which compares the **published YAML** to `gridBotSchemaConfig` directly.
  That is strictly stronger than sourcing: sourcing would make the two agree by
  construction while leaving the *committed YAML* free to go stale (it is a
  generated file a human can forget to regenerate — exactly the artefact users
  read).

### Reuse check (no new helper)

`parseTypeNode` already returns `{ type: 'string', enum }` for TS enums, and
`parseEnum` already owns literal-value extraction. The change adds one narrow
collector in the same shape and reuses the existing return contract; no new
formatting/precision/enum helper is introduced. Grepped `src/utils/` and
`core/src/utils` for an existing "union → values" extractor — none exists.

## Blast Radius

1. **Other call sites.** `parseTypeNode` is private to `SchemaGenerator` in
   `src/utils/generate-openapi-schemas.ts`; the class is used only by that
   file's `main()`. `fieldMetadata` likewise. `grep -rn "generate-openapi-schemas"`
   → only `package.json`'s `generate:schemas` script. No runtime code imports
   either: this is a build-time docs generator.

2. **`core/` submodule.** Yes — all edits are under `core/` (`main-app-sh`),
   which is public and deployed platform-wide. The parent `main-app` pointer
   must be bumped. **But the blast is documentation-only**: the generator is not
   imported by any service, and `openapi-v2.yaml` is served as a static
   document. No validator, resolver, engine or wire shape changes.

3. **Cross-service contracts** (root Danger List #2, "Public REST `/api/v2/*`").
   This touches the *description* of that contract, not the contract.
   `POST /api/v2/bots/grid` accepts exactly the same values before and after —
   the published spec stops lying about them. The change is strictly corrective
   for the consumers that read it (gainium-mcp, n8n-nodes-gainium,
   chrome-extension, generated clients): `type: object` → `type: string` + enum
   matches what those clients must already send to succeed.

4. **Other tests on this path.** None exercise the generator today. The YAML is
   read by `src/server/v2/` handlers only as a served asset. Full `npm test`
   must stay green in `core/`, and the regenerated YAML must diff *only* in
   alias-typed properties — every other line byte-identical, which is verified
   because a pre-change regeneration on `origin/main` was already a no-op
   (spec §2.2).
