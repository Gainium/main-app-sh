# Plan 234 — A restart never asks the venue about a market-close take-profit

Spec: `specs/234.restart-never-asks-about-a-market-close-take-profit.md`.

## Solution

In `src/bot/dcaHelper.ts` `checkOrders` (restart branch), drop `!forTPCheck`
from the guard on the take-profit reconcile loop, and inside the loop keep
every action that is not "book a fill" behind `!forTPCheck`:

- not-found answer: for a market-close deal, warn and `continue` (no
  `retireUnsentOrder`, no `noteOrderNotFound`).
- CANCELED answer: for a market-close deal, log and leave the order (no
  delete, no DB write, no `placeOrders`).
- FILLED / PARTIALLY_FILLED / unchanged: unchanged code, now also reached by
  market-close deals.

The grid comparison below the loop stays behind `if (!forTPCheck)`.

JIT tier 0: the touched loop is changed in place; no extraction (the change
is three guards inside an existing branch).

## Rejected alternatives

- A new post-load pass in `main.ts` calling `resolveNeverPlacedOrder`: that
  helper answers only Kraken/Coinbase/KuCoin-futures (returns `null` for every
  other venue, including the venue of the evidence), and `getOrder` already
  calls it for a `-1` order. The restart loop is the existing pass for exactly
  this question; it was only filtered.
- Adding MARKET `-1` rows to `positionReconciler/load.ts` `loadResting`: every
  consumer of resting rows (`intent.ts`, `compare.ts`) discards orderId `-1`,
  and the reconciler is detect-only, so it would add a per-chunk fleet read
  with no change in any verdict.

## Blast Radius

1. Callers: `checkOrders` runs on service restart and with
   `partiallyFilled=true` (PARTIALLY_FILLED orders only). Both now also look
   up a market-close deal's take-profits. Extra venue lookups: one per active
   take-profit on a market-close deal, normally zero (such deals rest none).
   Paced through the existing restart probe budget (`pace: true`).
2. File is under `core/` (main-app-sh, public). No types, schema, GraphQL,
   socket or queue contract touched.
3. Orders placed: none added. For a market-close deal no path in the loop can
   reach `placeOrders`, `retireUnsentOrder` or `noteOrderNotFound`.
4. Tests that stay green: `restartMidOrder.spec.ts`,
   `restartMidDealStart.spec.ts`, `coldRestartOrderSnapshot.spec.ts`,
   `dcaReloadLadderDuplicate.spec.ts`, `comboReloadLadderDuplicate.spec.ts`.
