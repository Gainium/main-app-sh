# 004 — Plan

Spec: `specs/004.tp-level-close-terminal-rejection.md`.

## Solution

Fix the **classification** the spec's §3 Assumption names, and gate the next
attempt on a cooldown instead of on the next price tick.

1. **`core/src/bot/dca/tpCloseOutcome.ts`** (new, pure — JIT runbook **Tier 2**).
   `classifyTpCloseAttempt` turns the three shapes
   `sendGridToExchange(…, returnError)` can return into
   `{ inFlight, bookFill, outcome, terminal }`; `tpCloseBlockedMessage` builds
   the deal-scoped sentence. Tier 2 rather than Tier 1 because the decision is
   arithmetic over strings with no I/O at all; Tier 3 (ports/adapters) would be
   a rewrite of `checkTPLevel`, which the runbook forbids on a bug touch. The
   classifier is exactly the `if (result …)` ladder that was already inline —
   the file it moves to is `src/bot/dca/`, where `dealOutcome.ts`,
   `partialTp.ts` and `baseOrderQty.ts` already sit for the same reason.
   `getErrorSubType` is **injected**, not imported, so the module never pulls in
   the DB-backed `errorRulesCache`.

2. **`core/src/bot/dcaHelper.ts` → `checkTPLevel`** (the only edited call site):
   - pass `returnError: true` and feed the result through the classifier
     (spec §1.1.1/§1.1.2);
   - re-raise the refusal through **`handleOrderErrors`**, which
     `returnError: true` suppresses inside `sendOrderToExchange`. To hold the
     prepared `Order` the call becomes `convertGridToOrder` +
     `sendOrderToExchange(orderPrepared, true)` — literally what
     `sendGridToExchange` does internally, and the exact idiom the sibling
     `checkDCAByMarketLevel` 60 lines above already uses. **No behaviour is
     added or removed by that swap**; it only surfaces the prepared order;
   - on `terminal`: `record()` a cooldown, log the venue's words, raise the
     deal message once per run of refusals, and **still release `closeByTp`**
     (spec §1.1.6 — the #617 latch must not come back);
   - on non-terminal: unchanged — release, `checkDealSlMethods`,
     `checkDealsPriceExtremum` (spec §1.1.5);
   - gate the whole trigger block on `check()` before anything else runs.

3. **Cooldown = the existing `RetryBackoff`** (`core/src/bot/retryBackoff.ts`),
   namespace `tpc`, keyed `[botId, dealId]`. **Reused, not written**: it is the
   mechanism `authGuard`, `complianceGuard`, `notEnoughBalanceBackoff`,
   `errorRaiseBackoff` and `terminalDealGuard` already share, and its Redis
   backing is what makes the window survive the worker restarts that
   `closeByTp` (in-memory) does not.

### §4.1 — cooldown bounds

`minMs` 60 s, `maxMs` 15 min, factor 2 → 1, 2, 4, 8, 15, 15… Shorter than the
5 min → 1 h siblings because this gates a **close**: a position-sync blip that
clears must not cost the user 15 minutes of unrealised profit, while a deal
whose position genuinely left the account settles at 4 attempts/hour instead of
~500. `clear()` on any successful in-flight close, so one good close re-arms
everything instantly.

### §4.2 — does the gate cover the single-TP branch?

Yes: it sits at the top of `if (trigger)`, before `getAggregatedSettings`.
Only the multi-TP branch ever `record()`s, so the single-TP `closeDealById`
path is affected solely for a deal whose settings changed mid-cooldown — and
for that deal the statement "the venue says there is no position to reduce"
is just as true. Placing the gate here is also what removes the log flood: all
three lines per attempt (`adding TP order`, `left nothing in flight`,
`TP Level Check Price`) are inside this block.

## Blast Radius

1. **Other call sites.** `classifyTpCloseAttempt` / `tpCloseBlockedMessage` are
   new and called from exactly one place. `checkTPLevel` itself has two callers
   (`dcaHelper.ts:17868` price callback, `:18641`), both price-driven; neither
   inspects a return value. `sendGridToExchange`'s other 13 call sites are
   untouched — the overload with `returnError: true` already exists and is
   already used elsewhere.
2. **`core/` submodule.** Yes — root Danger List **#11**. Everything here is in
   `main-app-sh`, so it ships to every consumer of `core/` (main-app cloud +
   self-hosted). Mitigated by the change being confined to one DCA-engine
   method plus one new leaf file: no exported type changes, no shared shape.
3. **Documented owned contracts.** None touched. No GraphQL/REST shape, no
   socket.io event name, no RabbitMQ queue, no Mongo schema field. The new
   deal message is a `botEvent` row using the **existing** optional
   `deal`/`symbol` fields of `BotEventSchema` — the same shape
   `announceLeftOpenPosition` already writes. One new Redis key namespace
   (`tpc:cd:*`), read and written only by this code.
4. **Other tests on this path.** `src/bot/dca/*.spec.ts` (`dealOutcome`,
   `partialTp`, `tpFees`, `baseOrderQty`) and the rest of `src/**/*.spec.ts`
   must stay green.
