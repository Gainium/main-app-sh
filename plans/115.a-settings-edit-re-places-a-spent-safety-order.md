# 115 — plan

## Solution

In `dcaHelper.createCurrentDealOrders`, compute
`ladderSpent = dcaOrdersCount > 0 && left === 0` and select no safety orders
when it holds. Both direction branches are skipped. Everything after the
selection (smart-order slice, trailing filter, TP/SL append) runs unchanged on
the empty list.

JIT tier 0: a one-expression guard at the decision point. The surrounding
method mixes selection with price reads and breakpoint I/O, but the fix does
not need that separated.

## Blast radius

1. Callers: every `createCurrentDealOrders` call in `dcaHelper.ts` (fills,
   settings edits, add funds, restarts). Only the `left === 0` case with a
   non-zero ladder changes, and there every level has filled, so no caller can
   legitimately want a safety order back. `comboHelper` overrides the method
   and has no `left` logic, so it is unaffected.
2. `core/` submodule (`main-app-sh`): shared, needs a pointer bump in main-app.
   The parent `src/bot/dcaHelper.ts` does not override this method.
3. No GraphQL/REST/socket/queue/schema shape is touched.
4. Stays green: `addFundsLadderSlot`, `nanLadderRefusal`,
   `indicatorDcaLevelMatch` harnesses and the full core suite.
