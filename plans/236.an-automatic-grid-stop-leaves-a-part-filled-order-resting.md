# Plan 236 — An automatic grid stop leaves a part-filled order resting

Spec: `specs/236.an-automatic-grid-stop-leaves-a-part-filled-order-resting.md`.

## Solution

Pass `cancelPartiallyFilled = true` to `stop()` at the automatic stop sites,
so the close sweep (`cancelAllOrder`) selects `NEW` + `PARTIALLY_FILLED`, the
same set the `stopAndSell` branch already cancels:

- core `helper.ts` — `closeBotByTp` `stop` branch (TP/SL), `processLiquidationOrder`,
  `processFilledStop`, and the missing-exchange-info stop in `start()`.
- main-app `src/bot/helper.ts` — its wholesale `closeBotByTp` override (the copy
  production runs) and its `start()` override's missing-exchange-info stop.

Left unchanged on purpose: `setStatus` (manual stop passes the user's flag),
the plain `else` stop in `setStatus`, and start-time refusals that run before
`loadOrders()` (archived, exchange unassigned, hedge neutral, load failure,
under-funded budget) — nothing is loaded for them to cancel.

JIT tier: 0 — one argument at each call site, no extraction.

## Blast Radius

1. Call sites: `stop()` signature unchanged; only the argument at the six
   automatic sites changes. `processSellAtStop` is not involved (it only runs
   for `close !== cancel`).
2. Under `core/` — shared by every main-app bot worker and the self-hosted
   build. Grid only (the helper mixin); DCA/Combo have their own `stop`.
3. No contract change: no GraphQL / REST / socket / schema / queue shapes.
4. Behaviour: the sweep now also cancels a part-filled level. The cancel reply
   is booked by the existing `cancelOrderOnExchange` path, which already handles
   PARTIALLY_FILLED cancels for `stopAndSell` and manual stops with the flag.
   Tests on this path: `grid*.spec.ts`, `closeCancelRefused.spec.ts` (core);
   `tests/gridClose*.ts`, `tests/gridBudgetRefusalStart.ts` (main-app).
