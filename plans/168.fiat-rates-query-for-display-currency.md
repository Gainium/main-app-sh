## Build order

1. `src/utils/fiatRates.ts` — pure `usableFiatRates` (§2), test first
   (`src/utils/fiatRates.spec.ts`).
2. `src/graphql/schema.ts` — `getFiatRates: getFiatRatesResponse`, `fiatRate`
   type (§1.1).
3. `src/graphql/resolvers.ts` — resolver reads the latest `rates` doc, like
   `getUsdRate`, and returns `usableFiatRates(...)` (§1.1, §2.1).
4. `src/utils/user.ts` — `fiatRateEntries` reuses the helper (§2.3); same rule,
   no behaviour change.
5. Consumer: main-dash-sh dashboard currency selectors (separate repo/commit).

## Blast radius

- Under `core/` (main-app-sh, public; also self-hosted). Additive GraphQL only —
  the GraphQL schema is a cross-service contract (dashboards), but nothing is
  renamed or removed, so no consumer breaks. A dashboard that ships before this
  backend sees the query fail and must fall back to USD (handled client-side).
- `fiatRateEntries` callers (`priceBalancesUsd`, snapshot pricing): identical
  filter, now via the helper. Covered by existing pegRates/snapshot specs.
- No Mongo writes, no schema change, no queue/event change.
