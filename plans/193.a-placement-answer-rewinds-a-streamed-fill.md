# 193 — Plan: a placement answer must not rewind a streamed fill

Spec: `specs/193.a-placement-answer-rewinds-a-streamed-fill.md`.

## Solution

- `heldExecutionAheadOfAnswer(held, answer)` in `staleExecutionReport.ts`
  (pure, next to the spec `090` / `114` rules): when the answer states a
  smaller `executedQty` than the held row, return the held row's
  `executedQty` / `cummulativeQuoteQty` / `price`, plus its fee fields when it
  states a fee. Otherwise `null` (§4.1, §4.2).
- `sendOrderToExchange`: after `orderToPush` is built and its quantities are
  converted to engine units, apply the kept figures and log one line (§4.1).
  The status merge, the market-order remainder top-up, the spec `155` late
  reply and the DB write are untouched (§4.2).

JIT tier: 2 for the decision (pure function, no I/O), 0 for the rest of
`sendOrderToExchange`.

## Blast radius

1. Call sites: `sendOrderToExchange` is the placement path for every bot type
   and venue. The rule only acts when the engine already holds a row with
   more executed than the answer states. That needs the user stream to
   deliver fills for this order before the answer arrives. In every other
   case the merge is unchanged.
2. `core/`: shared engine code. The parent pointer must be bumped.
3. Contracts: none. No GraphQL, socket, queue or schema shape changes. The
   Mongo row was already right (`updateOrderOnDb` does not overwrite a FILLED
   row); only the engine's in-memory and Redis copies change.
4. Tests: `staleExecutionReport.spec.ts`, `cancelDuringPlacement.spec.ts`
   (same harness, same function), and the full `npm test` suite.

Not changed: how the take profit is sized at close (`getTPOrder` /
`resolveBaseOrderQty` still read the position).
