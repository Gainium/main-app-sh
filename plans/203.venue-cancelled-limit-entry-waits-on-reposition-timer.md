# Plan 203 — a venue-cancelled limit entry waits on a reposition timer that never acts

## Solution

The fix is in `dcaHelper.ts` only. Combo shares `checkUnfilledBaseEntryCancel`
and `checkBaseOrder`, so it gets the same fix.

1. `checkUnfilledBaseEntryCancel` passes `hasPendingCheck: false` and the real
   `liveEntries` count. When the predicate holds, it calls
   `dropBaseEntryTimers(dealId)` and then `armCanceledBaseEntryDealCancel`.
2. New `liveBaseEntries(dealId)` holds the live-`dealStart` count that
   `cancelDealOfCanceledBaseEntry` used to compute inline. Both callers use it.
3. New `dropBaseEntryTimers(dealId)` calls the existing `clearDealTimer`,
   which clears both timers and `startTimeoutTime`, and then deletes the
   `dealTimersMap` entry. `clearDealTimer` on its own leaves that entry in
   place with both timers nulled. The 15 s re-check reads
   `dealTimersMap.has`, so an entry still present must mean a new entry was
   placed since.
4. `checkBaseOrder(id)` gets one new branch, before the existing `find &&`
   branch: when `!find`, `dealId`, the deal holds timers, the deal is in
   `start`, `!isOwnCancel(id)` and there is no live entry, it logs, drops the
   timers and arms the check.

The pure predicate `isUnattributedUnfilledBaseEntryCancel` is unchanged.

JIT tier 0: two small methods are extracted next to their callers. Nothing
else moves.

## Blast Radius

1. Call sites. `checkUnfilledBaseEntryCancel` is called from the DCA and
   Combo cancel callbacks. `checkBaseOrder` is called from the reposition
   tick, the enter-market timer (with no `id`, so the new branch does not
   apply), the DCA restore path and the Combo restore path. Neither restore
   path holds timers, so the new branch does not apply there either.
   main-app's parent `src/` overrides none of these methods.
2. All the changes are under `core/` (main-app-sh), so the parent's pointer
   needs a bump.
3. No GraphQL, socket, queue or collection shape changes.
4. Other suites on this path: `partialBaseEntry`, `baseEntryReposition`,
   `limitTimeouts`, `baseEntryRemainder` and `baseEntryTopUp`, plus the full
   core suite.
