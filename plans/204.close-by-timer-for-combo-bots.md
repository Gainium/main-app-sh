# Plan 204 — Close by timer for Combo bots

Spec: `specs/204.close-by-timer-for-combo-bots.md`.

## Build order

1. main-app core (this repo): engine + API validators (§2.1–2.4). Ships
   first and is inert on its own: no Combo bot has the timer on until the
   dashboard offers it.
2. main-dash-redesign core (dashboard spec 137): the timer row on the Combo
   form. The GraphQL inputs and fragments already carry the fields.

## Decisions the spec left open

- **Hook shape (§2.1).** `protected timerCloseOrder(settings)` returning
  `{ closeType, forceMarket }` on the DCA helper; Combo overrides it. Not a
  `combo ? … : …` branch inside `closeByTimer` (Open/Closed: the variant
  lives on the subclass, as the rest of the Combo close logic does).
- **Where Combo arms the timer.** `startDeal`: in the existing
  `updateUsage(...).then` after `checkDealSlMethods`, mirroring DCA's
  placement after the deal is saved open. `restoreWork`: first thing in the
  per-open-deal loop, before the branch on service restart, so both start
  kinds re-arm (DCA re-arms on both too).
- **Hedge (§1.7).** The keys move to an exported `closeByTimerSettingsKeys`
  that `hedge.ts` checks for a Hedge Combo leg, so a Hedge Combo clone keeps
  today's refusal with today's message.
- **JIT tier.** Tier 0 for the legacy helpers: one-line call additions and a
  three-line hook; nothing on the path needs extracting.

## Blast radius

1. `closeByTimer` callers: only `setCloseByTimer` and its own timer. Hedge
   bots compose DCA/Combo helpers through `hedgeHelper` and inherit the hook;
   a Hedge Combo leg never has `closeByTimer` on (form forces it off, API
   refuses it), so its behaviour is unchanged. DCA's result is identical to
   before (`closeDealType`, `forceMarket: true`).
2. All engine files are under `core/` (main-app-sh): shared with self-hosted.
   The parent's pointer is bumped at ship. The parent `src/bot/comboHelper.ts`
   does not override `startDeal`'s body path we touched (it wraps it with a
   webhook) nor `restoreWork`.
3. Contracts: the public REST/v2 API now ACCEPTS three keys on Combo it used
   to refuse — a widening, no consumer breaks. GraphQL schema, socket events,
   Mongo schema: untouched (fields already existed on Combo bot and deal).
4. Tests that must stay green: `startReconcilesBook.harness.spec.ts` (now
   stubs `setCloseByTimer`), every Combo/DCA spec under `src/bot`.
