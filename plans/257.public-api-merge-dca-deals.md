# 257 — plan: merge DCA deals through the public API and MCP

## Build order
1. `src/server/v2/mergeDeals.ts` — pure request checks (Tier 2, new code): `parseMergeDealsBody`
   (§1.2.2) and `checkMergeCandidates` (§1.2.3–7). No DB import.
2. `src/server/v2/middleware.ts` — the API-key restriction middleware also reads `body.dealIds[]`
   and `body.targetDealId` (§1.4).
3. `src/server/v2/api.ts` — `POST /api/v2/deals/:dealType/merge`: combo/other type refusal (§1.2.1),
   one projected `dcaDealsDb` read, the checks, then the existing `Bot.mergeDeals` with the target
   deal's bot (§1.3). 202 on dispatch.
4. `openapi-v2.yaml` + `AI_API_GUIDE.md` — the path and the documented edge cases (§2).
5. gainium-mcp `manage_deal` `action: "merge"` (§1.5), shipped from its own repo.

## Decisions the spec left open
- Route path `/:dealType/merge` (not a literal `/dca/merge`) so `combo` gets the clear 400 of §1.2.1.
- MCP keeps `dealId` required: it is the target, `dealIds` the others; the body puts it first.
