# Plan 124 — neutral grid stats value the position against the close entry

Spec: `specs/124.neutral-grid-stats-value-the-position-against-the-close-entry.md`.

## Solution

The worker already computes the entry (`refreshTpSlEntry()`, spec 117) and
caches it keyed to the position. Publish that cache instead of recomputing it
anywhere else:

1. `types.ts` — `GridCloseEntry = PositionInBot & { entry }`; optional
   `BotSchema.closeEntry`, `InputGrid.closeEntry`.
2. `src/bot/gridCloseEntry.ts` — pure `gridPositionEntry(position, closeEntry)`
   implementing spec §4.2 (match side/qty/price, else `position.price`).
3. `helper.ts` `refreshTpSlEntry()` — after setting `tpSlEntry`, set
   `data.closeEntry`, `updateData({ closeEntry })`, emit
   `bot settings update { closeEntry }`. `gridStatsSnapshot()` and the
   `calculateGridLiveStats` snapshot carry `closeEntry`.
4. `gridMonitor.ts` (`updateDealStats`, `addNewBot`) and `botMonitor.ts`
   (`calculateGridLiveStats`) value the futures position against
   `gridPositionEntry`.
5. `db/schema.ts` bot schema + GraphQL `fullBot.closeEntry: BotCloseEntry`.
6. main-dash-sh (paired): select `closeEntry` in `botFragment`; same rule in
   `transformGridBotToBot` and `calculateCurrentStats`, which also move from
   `qty × (Δ/entry) × price` to `qty × Δ` (spec 064's measure, already used by
   the bot and `liveStats`).

JIT tier: none. The helper is extracted only because two backend call sites
and the dashboard need the same rule; `tpSl()` and `tpSlEntryPrice()` stay
untouched (spec §4.6).

## Blast Radius

1. Call sites: `GridMonitor` is fed only by the two snapshot builders in
   `helper.ts` (+ main-app parent `src/bot/helper.ts:788`, which calls
   `gridStatsSnapshot()`); `calculateGridLiveStats` only from `helper.ts`. The
   refresh gate is unchanged, so no new ledger reads.
2. `core/` (main-app-sh) — shared; pointer bump in main-app.
3. Contracts: GraphQL `fullBot` (additive field), `bot settings update` /
   `bot sends settings` (additive key), shared Mongo `bots` collection
   (additive field). **Ship order: main-app before the dashboard** — a dashboard
   selecting `closeEntry` against a backend without it fails GraphQL validation
   for the whole `getBot` / `botList` query (verified against the current
   schema and against prod).
4. Tests that must stay green: `gridTpSlCloseBasis.spec.ts` (117),
   `gridPositionValue.spec.ts` (064), full core suite.
