# 192 — Plan: cover the pre-send guards with the in-flight placement handle

Spec: `specs/192.cancel-during-pre-send-guards-writes-off-a-placement.md`.

## Solution

- `beginPlacement(clientOrderId)` replaces `trackPlacement`: it registers the
  `placementsInFlight` entry at once and returns a handle with `send(fn)` (runs
  the venue call, resolves the entry with the venue id or nothing — exactly the
  old `trackPlacement` resolution) and `settle()` (resolves it with nothing).
  First resolution wins; the entry is removed only if it is still this one.
- `sendOrderToExchange` calls it right after `setOrder(order)` (the write-ahead),
  before `saveOrderToDb` and every guard (§4.1).
- Explicit `settle()` on each path that leaves without sending, BEFORE its own
  follow-up work (§4.2): the zero-quote-amount refusal, the two quant-rules
  holds, the split MARKET path, and right after the send line (covers every
  guard short-circuit that set `request`; a no-op once the venue answered).
- `sendOrderToExchange` becomes a thin wrapper over a private
  `_sendOrderToExchange` that settles the handle in `finally`, so a throw in a
  guard can never leave a cancel waiting forever (§4.2). Overloads unchanged.

JIT tier: 0 — the guards and the send are untouched; only the handle's
lifetime moves. A higher tier would be scope creep on a money path.

## Blast radius

1. Callers: `trackPlacement` had one call site (the send line); no subclass or
   spec referenced it. `sendOrderToExchange` keeps its public signature; the
   main-app parent's dry-run override calls `super.sendOrderToExchange`, which
   is now the wrapper (parent `tsc` clean).
2. `core/` (main-app-sh): shared, deployed with main-app; the parent pointer
   needs the usual bump.
3. No contract change: no GraphQL/REST/socket/queue/collection shape touched.
   Waiters (`cancelOrderOnExchange`, `getOrder`, the unknown-order ladder) may
   now wait for the guards too — bounded by Redis/DB reads, a balance fetch,
   and the Binance-futures quant-rules inline wait (≤ 60 s).
4. Tests that must stay green: `cancelDuringPlacement.spec.ts` (spec 155),
   every spec driving the real `sendOrderToExchange` (batch placement, quant
   rules retry, not-enough-balance cooldowns, NaN/zero-size refusals).
