# 274 — plan

## Change

1. `src/bot/helper.ts` `closeBotByTp`, `oldTpSl` guard: the `PARTIALLY_FILLED`
   early return stays for spot only. The `FILLED` return is unchanged.
2. `closeBotByTp`, stop-and-sell branch: for futures, `settleRestingCloses()`
   (spec 273) runs before `cancelAllOrder`. `filled` → return (fill path,
   §4.6); `refused` → clear `limitTimer` / `enterMarketTimer` and return
   (§4.7); `pending` → `retryCloseByTp()` re-arms `limitTimer` with the same
   trigger and `forceMarket`, places nothing (§4.5); `settled` → the existing
   flow, which sizes the close from the reduced `position.qty` (§4.1–§4.4).
3. `retryCloseByTp()` clears a pending `limitTimer` before arming one, so two
   re-run chains cannot run at once.
4. `checkOrders` restart branch: a futures close the venue reports
   `PARTIALLY_FILLED` is saved and handed to `processSellAtStop` (by order
   type), mirroring the existing `CANCELED` route (§4.9).

JIT tier 0: two branches and two small private methods inside the legacy
mixin. They reuse spec 273's `settleRestingCloses` / `bookPartialClose`. No
extraction.

## Blast radius

- Grid bots only (`helper.ts` is the grid mixin). Spot paths are untouched:
  every new branch is gated on `this.futures`.
- On a first trigger nothing closing rests, so `settleRestingCloses` returns
  `settled` with no venue call, and the flow is the old one.
- A futures re-run now cancels its resting close through
  `settleRestingCloses` (promotion off) instead of `cancelAllOrder`. For a
  close with no fills the venue answer is identical. For one with fills, the
  part is booked as a part instead of as a full close (§1.3).
- The restart route is shared with the user's close by limit/market (the
  close orders are the same `GRID-TP` stop orders). A part-filled manual close
  found after a restart now resumes through `processSellAtStop` too, instead of
  waiting with no timer. `processSellAtStop` itself is not changed.
- `core/` (main-app-sh) is shared by every main-app deploy: the change reaches
  every grid bot worker. No GraphQL, socket, queue or schema shape changes.
- Other tests on this path: `gridClosePartialFill.spec.ts` (273),
  `gridTpCloseSingleShot.spec.ts` (189), `gridStopAndSellFlatPosition.spec.ts`
  (127/240; its fake bot gained a `getOrdersByStatusAndDealId` stub, no
  assertion changed), `gridCloseProfitLedger.spec.ts`.
