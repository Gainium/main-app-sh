# 246 — plan

## Solution

In `openNewDealBody`, at the `refuseDealBelowExchangeMin` exit, call
`this.stop()` when the bot is a terminal deal — the same un-awaited call the
balance refusal of a terminal deal makes a few lines later, so the per-pair
`newDeal` mutex is not held across the stop. JIT tier 0: one branch beside
its existing twin; nothing extracted.

## Blast radius

- Other callers of `refuseDealBelowExchangeMin`: the quiet re-check in
  `applyNewDealSize` (answers only; falls back to the configured size) and the
  position-entry path (`refuse('entry below the exchange minimum')`, adds to an
  existing deal, so the bot already has a deal) — unchanged. The combo engine's
  own call site has no terminal bots.
- `core/` file: shared main-app-sh engine; parent main-app does not override
  `openNewDealBody`.
- No GraphQL, socket, queue or schema change. `stop()` writes `status: closed`
  as for any stop, which releases the bot-credit lock.
- Existing terminal trades left open by this defect stop themselves the next
  time a worker loads them and the refusal repeats.
- Tests that stay green: `newDealBalanceRetry`, `newDealApproval`,
  `allowRaiseToExchangeMin.harness`.
