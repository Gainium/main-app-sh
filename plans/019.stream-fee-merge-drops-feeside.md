# 019 — the live-stream order merge never carries `feeSide`

Plan for [`specs/019.stream-fee-merge-drops-feeside.md`](../specs/019.stream-fee-merge-drops-feeside.md).

## Solution

1. `types.ts` `SpotUpdate` gains `feeSide?: 'base' | 'quote'`, next to
   the existing `feePaid`/`feeAsset`/`feeBreakdown`/`feePaidUsd`.
2. Extract the four-field present-if-present copy at
   `main.ts:5263-5274` into a pure function in `src/bot/orderFee.ts`
   (JIT tier 1 — see below), add the missing `feeSide` clause there,
   and call it from `convertExecutionReportToOrder` in place of the
   inline `if` blocks — mirroring the line immediately above it,
   `Object.assign(order, accrueStreamFee(order, msg))`, which already
   uses this exact shape for the sibling Binance-commission case:

   ```ts
   // orderFee.ts
   export function streamFeeFields(msg: {
     feePaid?: string
     feeAsset?: string
     feeBreakdown?: { asset: string; amount: string }[]
     feePaidUsd?: string
     feeSide?: 'base' | 'quote'
   }): {
     feePaid?: string
     feeAsset?: string
     feeBreakdown?: { asset: string; amount: string }[]
     feePaidUsd?: string
     feeSide?: 'base' | 'quote'
   } {
     const out: ReturnType<typeof streamFeeFields> = {}
     if ('feePaid' in msg && msg.feePaid !== undefined) out.feePaid = msg.feePaid
     if ('feeAsset' in msg && msg.feeAsset !== undefined) out.feeAsset = msg.feeAsset
     if ('feeBreakdown' in msg && msg.feeBreakdown?.length) out.feeBreakdown = msg.feeBreakdown
     if ('feePaidUsd' in msg && msg.feePaidUsd !== undefined) out.feePaidUsd = msg.feePaidUsd
     if ('feeSide' in msg && msg.feeSide !== undefined) out.feeSide = msg.feeSide
     return out
   }
   ```

   ```ts
   // main.ts, replacing the four if-blocks
   Object.assign(order, streamFeeFields(msg))
   ```

This is the root cause the spec's Assumption names — the merge simply
never read `feeSide`; nothing else on the path needs to change.

## Why this JIT tier (1, not 0 or 2)

The four `if` blocks are already pure (no I/O, no `this`, only reads
`msg`/writes fields onto a plain object) but were inline inside a
~5000-line class method with no independent test — Tier 0 (leave
alone) isn't available because the causal path runs directly through
this exact code (adding the fifth field IS the fix), and testing it in
place would mean instantiating `MainBot` (heavy: DB singletons,
`ExchangeChooser`, `SharedStream`, …) just to exercise five field
copies. Tier 1 (named, tested module) removes that cost with a
same-shape sibling already established one line above
(`accrueStreamFee`) and an existing home for exactly this kind of logic
(`orderFee.ts`). Not Tier 2 (already pure) — no further transformation
needed, it already is one. Not Tier 3 — no new port/adapter boundary is
warranted for a five-field copy.

## Blast radius

1. **Other call sites.** `convertExecutionReportToOrder` has two
   callers (`main.ts:4633,5777` — spec 003 in paper-trading already
   enumerated these); neither needs changing, both benefit. The
   extracted block itself has exactly the one call site being changed.
2. **`core/` submodule.** This file is `main-app-sh`, shared/deployed
   platform-wide — parent pointer bump needed at ship time.
3. **Contracts this repo owns.** No GraphQL/REST/socket.io/Rabbit shape
   changes — `feeSide` already exists on `Order`
   (`src/db/schema.ts:772`, `deal.feeByAsset`'s `side` field reads it,
   `src/bot/orderFee.ts:72`); this only fixes how a value that already
   has a home gets there from one specific path.
4. **Other tests.** `src/bot/orderFee.spec.ts` already covers
   `observedFeeSplit`'s `feeSide` handling (base/quote) end to end —
   untouched, must stay green. No existing test currently exercises the
   inline block being replaced (confirmed: nothing in this repo
   references `convertExecutionReportToOrder` from a test file today) —
   gate 2 adds the first one, against the extracted function rather
   than the class method.
