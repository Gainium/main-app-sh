# Plan 025 — A NaN quantity reaches the venue, and poisons the deal on the way

Spec: `specs/025.a-nan-quantity-reaches-the-venue-and-poisons-the-deal.md`
(issue #715).

## Build order

1. **Spec** — written from prod log forensics + read-only prod Mongo (§2.1–§2.4).
2. **Red tests** — two harnesses driving the real code, no stack:
   - `src/bot/dca/nanLadderRefusal.harness.spec.ts`: pre-fix, 30 of 31 ladder
     levels came back `qty: NaN`, reported only as the swallowed
     `Big number error [big.js] Invalid number`.
   - `src/bot/nanOrderRefusal.spec.ts`: pre-fix, `venueCalls[0].quantity` was
     `NaN` and the persisted row carried `origQty: 'NaN'`; the only error
     surfaced was the venue's own `UNKNOWN_FAILURE_REASON: , ` — the exact prod
     string.
   Both files pin the HEALTHY case green pre-fix (`§4.5`), so a guard that
   moved a real number would fail.
3. **Fix**, in dependency order (producer, then boundary):
   - §4.2 `createInitialDealOrders` — extend the `939a5fe` latest-price bail to
     `_price`, the sizing price the ladder divides by, and guard `baseQty`,
     the other input everything the function returns is derived from.
   - §4.3 both of `createInitialDealOrders`' catches (take-profit and the
     ladder's `Step dca`) — bail on a non-finite quantity.
   - §4.4 `getTPOrder`'s catch — bail on a non-finite `tpOrder.qty`.
   - §4.1 `sendOrderToExchange` — refuse a non-finite quantity (any type) or
     price (non-MARKET) before the write-ahead persist and the venue call.
4. **Green** — 19/19 across the two new suites plus spec 023's, then the full
   `npm test`, plus `tsc --noEmit`.

## Contract decisions the spec left open

- **Which error string.** Reuse `Order qty is not a number`, already in
  `bot/utils.ts` `errorDict` → `orderParams`, and already the string
  `addDealFunds` refuses its own quantity with. No new taxonomy entry, so the
  admin bot-error grouping is unchanged.
- **Loudness.** `setError = false`, `sendError = false`, matching the sibling
  guard spec `023` shipped. A NaN order is an engine defect, not a
  user-actionable venue failure; error-stating the bot on every tick would
  flap it. The log line is the evidence path.
- **Price arm scope.** Skipped for `type === 'MARKET'`. A market order's
  `price` is not what fills and some connectors drop it, so a missing one there
  is not proof of a broken order the way a missing quantity always is. The
  reported incident is a LIMIT order.
- **Bail granularity for the ladder.** The whole ladder, not the one level. A
  partial ladder is a silently different strategy than the user configured, and
  the existing latest-price bail already answers `[]`.
- **Catch bails are narrow.** Only when the value is provably non-finite. A
  `new Big()` throw with any other cause (an unreadable `baseAsset.step`) keeps
  today's log-and-continue, so a pair with odd instrument data does not
  newly lose its take-profit.

## JIT legacy extraction tier

**Tier 0 — no extraction.** The runbook's rule is the lowest tier that removes
the smell on the path being touched. All four edits are guard clauses at
existing decision points inside `dcaHelper.ts` / `main.ts`; none of them adds
logic worth its own module, and none of the surrounding arithmetic is being
moved. Pulling `createInitialDealOrders`' ladder sizing into a pure module is a
real Tier 2 candidate, but it is a 300-line extraction on the hottest path in
the engine and is not "already being touched" by a four-line guard — that is
scope creep on a money-safety fix, and would be a deliberate modernisation
task instead.

## Blast radius

1. **Other call sites.** `sendOrderToExchange` — 9 call sites across `main.ts`,
   `dcaHelper.ts`, `comboHelper.ts`, `helper.ts`, all of which already handle a
   `void`/reason return (the compliance and quant-rules short-circuits return
   the same way). `createInitialDealOrders` — 14 call sites; all already
   handle `[]`, which is what the latest-price bail has returned since
   `939a5fe`. `getTPOrder` — 6 call sites, all `?.length`-guarded since spec
   `023`.
2. **`core/` submodule.** Yes — shared with every consuming service, cloud and
   self-hosted. Parent pointer bump required.
3. **Owned contracts.** None touched. No GraphQL, REST `/api/v2/*`, socket.io
   event, Redis channel, RabbitMQ payload or Mongo field changes shape or
   meaning. The `orders` documents this stops writing are ones no consumer can
   read as numbers today anyway.
4. **Other tests on this path.** `tpNanRefusal.harness.spec.ts` (023),
   `tpSizingFromPosition.harness.spec.ts` (017), `baseOrderQty.spec.ts`,
   `qtyStepGuard.spec.ts`, `strandedLocalRefusal.spec.ts` (013),
   `cancelNoExchangeOrderId.spec.ts` — all must stay green; the full suite is
   the gate.
