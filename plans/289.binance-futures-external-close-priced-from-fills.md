# Plan 289 — Binance futures external close priced from the venue's fills

## Build order
1. Ship exchange-connector core `057` first. It answers Binance futures account fills for a named symbol.
   Until it is live, a symbol main-app sends is ignored by the older connector, so this change is safe in
   either order. It just has no effect until `057` is live.
2. `src/exchange/exchange.ts#getAccountFills`: optional `symbol` as the second parameter, sent as the
   `symbol` query parameter. The retry replays `(sinceMs, symbol, timeProfile)`.
3. `src/exchange/index.ts` (paper): the signature gains `_symbol`. It still answers `[]`.
4. `src/bot/dcaHelper.ts#venueCloseEvidenceFor`: pass `deal.deal.symbol.symbol`.

## Blast radius
- `getAccountFills` callers:
  - `venueCloseEvidenceFor`: changed. It is used only by `settleExternallyClosedDeal` and the
    liquidation settle, both of which already price from the evidence when it covers the deal.
  - `readLiquidationFills`, `main.ts` write-off settle, the parent `positionReconciler/orderProbe` and
    `db/scripts/reconcileKrakenFills.ts`: unchanged. They pass no symbol, and `timeProfile` was never
    passed positionally by any caller.
- Kraken, Bitget and Bybit: the connector ignores `symbol` there, so their evidence is unchanged.
- Rate limit: one connector call per settled deal, as before. The Binance cost is bounded in connector
  `057`.
- Money: Binance futures deals closed outside the bot now book a real profit or loss. That moves the bot's
  accumulated profit, so the "stop after X profit or loss" condition can now trigger on these deals, which
  is correct.
- Type-check: core and parent `tsc` are clean. The parent build compiles `tests/` too.

## Traceability
| Spec | Test (`src/bot/dca/binanceExternalClose.harness.spec.ts`) |
|---|---|
| §1.1 | a symbol is sent as `symbol`; with a cursor both are sent; a caller that names nothing sends what it did before |
| §1.2 | the evidence read asks for the deal's own symbol; the reported case is closed at the hand close's price and fee |
| §1.3 | `venueCloseEvidence.spec.ts` and `partialLiquidation.harness.spec.ts`, unchanged and green (incl. §1.5 Binance USD-M liquidation settle keeps its old behaviour) |
- `AccountFill.realizedPnl?`: an optional field the connector now sends on Binance futures fills. Nothing
  in core reads it, and it is optional, so no existing consumer changes.

## Deals already booked "profit unknown"
The parent repo ships a read-only report, `src/db/scripts/repriceBinanceProfitUnknownDeals.ts`. It prices
those deals from the same `venueCloseEvidence` and writes a JSON file only. It works only once connector
`057` is live. It leaves take-profit closes to the funding restatement.
