# Plan 003 — absent `locked` on balance stream events

Spec: `specs/003.absent-locked-balance-stream.md`.

## Solution
Tier 2 extraction: the hold-write decision moves out of `processBalanceUpdate`
into the pure module `src/utils/balanceWrite.ts` (`normalizeLocked`,
`hasLocked`, `lockedUpdateFields`, `lockedInsertValue`) with its own spec;
`user.ts` spreads `lockedUpdateFields(d)` on the `$set` path and uses
`lockedInsertValue(d)` on the insert path. `getBalances` handler maps
`updated`; GraphQL `getBalancesResponseData.updated: String`.

## Blast Radius
1. `normalizeLocked` other callers in `user.ts` (REST snapshot paths at ~311,
   ~445) keep using the re-exported function unchanged.
2. Under `core/` (main-app-sh): the API process runs `processBalanceUpdate`
   (`server/index.ts` boot) — an API restart activates it; bot workers do not
   run this path.
3. Contract: additive GraphQL field `updated` on `getBalances` (dashboards);
   `AssetBalance.locked?` matches the connector's producer type.
4. Tests: `src/utils/balanceWrite.spec.ts`; main-app `schema:test` gate.
