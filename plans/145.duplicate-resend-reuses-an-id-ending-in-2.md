# 145 — plan: a duplicate re-send reuses an id that already ends in `2`

Spec: `specs/145.duplicate-resend-reuses-an-id-ending-in-2.md`.

## Solution

In the duplicate branch of `MainBot.sendOrderToExchange` (`src/bot/main.ts`),
replace the last character with `3` when it is already `2`, else with `2`.
JIT tier 0: a one-expression change on the causal path; nothing to extract.

## Blast Radius

1. Call sites: only this branch regenerates an id this way (the Binance
   `MARKET_LOT_SIZE` split builds split ids by index — a different path, not
   touched). Nothing in core or the parent keys off a trailing `2`. The parent
   `sendOrderToExchange` override only delegates to `super`.
2. `core/` submodule — shared; pointer bump needed in main-app.
3. No contract touched: client order id prefix and length are preserved, so
   D-/CMB- routing prefixes, broker prefixes and venue length limits (Kraken
   spot 18, OKX/MEXC 32, Hyperliquid `0x` + 32 hex) still hold; `2` and `3` are
   valid in each id alphabet.
4. Spec 136 cases in the same file (venue asked first, live original kept)
   must stay green.
