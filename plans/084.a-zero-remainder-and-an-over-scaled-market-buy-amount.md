# Plan 084 — A zero remainder, and a market-buy amount past the venue's scale

## Build order

1. `core/src/bot/dcaHelper.ts` — `sellRemainder`: hoist the base-step rounding
   above the minimum checks and measure the rounded quantity (spec §4.1).
2. `core/src/bot/main.ts` — `sendOrderToExchange`: clamp the Bitget market-buy
   amount scale (spec §4.2) and refuse a non-positive quantity (spec §4.3).
3. `core/src/bot/utils.ts` — one `errorDict` entry for the new refusal.
4. `core/src/bot/zeroSizeOrderRefusal.spec.ts` — the regression suite.

## Contract decisions the spec left open

- **Where the `> 0` lives.** Both at the producer (§4.1) and at the boundary
  (§4.3). The producer fix is the root cause; the boundary is the existing,
  documented last line of defence and makes the class unreachable venue-wide.
- **The clamp constant.** A named `BITGET_SPOT_QUOTE_MAX_SCALE = 6` next to the
  conversion, with the refusal that measured it in the comment. Not read from
  the venue: the venue's own `quotePrecision` is the number that is wrong.
- **The refusal message.** `Order qty must be greater than zero.` — a new
  `errorDict` key rather than reusing `Order qty is not a number`, because zero
  IS a number and the existing string is load-bearing in four other specs'
  assertions. Same `Order params` class, so nothing downstream reclassifies.

## Blast Radius

1. **Other call sites.**
   - `sellRemainder` — called from `dcaHelper`/`comboHelper` close paths. The
     change is internal to its own guard; the signature and every return are
     unchanged. The only behaviour difference is that a remainder that floors to
     zero (or under a minimum) is now skipped instead of sent — the same
     skip branch that already exists for a below-minimum remainder.
   - `sendOrderToExchange` — every order placement in the engine. The added
     refusal fires only for `origQty <= 0`, which no venue accepts today; the
     scale clamp is a no-op for the 2297 of 2706 Bitget spot symbols whose
     `quotePrecision` is already 6 or below, and only ever removes decimals.
   - `errorDict` — additive key.
2. **`core/` submodule.** All three files are under `core/` (`main-app-sh`):
   shared with every consuming service, cloud and self-hosted. Danger List #11.
   No exported type, GraphQL field, socket event or queue payload changes —
   the diff is entirely inside two method bodies plus one dictionary entry.
3. **Documented contracts.** None touched. `errorDict` feeds bot-error
   classification (admin-app rules); an added key classifies a string that is
   new in this release, so no existing rule changes meaning.
4. **Existing tests that must stay green.** `nanOrderRefusal.spec.ts`,
   `dca/nanLadderRefusal.harness.spec.ts`, `dca/tpNanRefusal.harness.spec.ts`
   and `dca/tpPriceRefusal.harness.spec.ts` all assert on the non-finite
   refusal string, which is untouched. `remainderDoubleCount.spec.ts` covers
   the remainder accounting, not its guard.

## JIT extraction tier

Tier 0 for `sendOrderToExchange` (the change is two expressions inside a method
already documented as the safety boundary) and Tier 0 for `sellRemainder` (one
hoisted local). Nothing on the causal path is worth pulling out: the decision
being fixed is a comparison against a number that is computed three lines away,
and extracting it would move it further from the send it has to agree with.
