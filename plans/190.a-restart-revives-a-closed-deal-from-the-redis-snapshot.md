# Plan 190 — a restart does not revive a closed deal from the snapshot

Spec: `specs/190.a-restart-revives-a-closed-deal-from-the-redis-snapshot.md`.

## Build order

1. `src/bot/dcaHelper.ts` `loadOrders`, cold-restart branch, after the snapshot
   deals are seeded: one `dealsDb.readData` of the restored ids for
   `closed` / `canceled`, projection `{status: 1}` (§4.1). Hits go to
   `deleteDeal`, leave `restoredFromRedis`, and are recorded in `closeSweeps`
   (`persistCloseSweeps`, awaited). A failed read logs a warning and keeps the
   snapshot (§4.2).
2. No combo change: `ComboBotHelper.loadOrders` runs `super.loadOrders()` first,
   and its `restoreWork` already calls `resumeCloseSweeps`, whose
   `afterCloseSweepResumed` closes the deal's minigrids (§4.3).
3. Version + changelog: core patch bump, main-app patch bump + core pointer.

## Contract decisions the spec left open

- The check runs before the `loadFromDb` decision. When every restored deal is
  dropped, `this.deals` is empty and the restart falls back to the full Mongo
  load, the same as an empty snapshot.
- The sweep record gets `Date.now()` as its start, so the 7-day expiry counts
  from the restart that found the deal.
- Only `closed` / `canceled` in Mongo drop a deal. Any other stored status keeps
  the snapshot (§1.1.3).

## JIT extraction tier

Tier 0. One read and its branch are added inline next to the spec `151` / `172`
reads of the same shape. The cleanup reuses spec `182`'s existing, tested
sweep resume, and no new logic needs isolating.

## Blast Radius

1. Call sites: only the cold-restart branch of `loadOrders` (DCA, Combo and
   Hedge inherit it). One indexed `_id ∈` read per bot that restores deals from
   the snapshot. A reload and a user start are untouched.
2. Under `core/` (main-app-sh): shared code. The pointer bump in main-app is
   deliberate.
3. Contracts: no GraphQL / REST / socket / queue / schema change. The
   `closeSweeps` Redis field is spec `182`'s own.
4. Tests that must stay green: `coldRestartDealSnapshot.spec.ts` (spec 151; its
   §1.1.3 query-count assertion now selects the spec 151 read, §4.4),
   `restartDealCounter.spec.ts` (spec 183; asserts `{57,1}` straight after the
   load instead of `{57,2}` plus a second close, §4.5),
   `restartMidDealStart.spec.ts` (spec 172; query count selects its own read),
   `closeSweepResume.spec.ts` (spec 182), `coldRestartOrderSnapshot.spec.ts`,
   `comboCloseDuringReload.spec.ts` (spec 173), the whole core suite.
