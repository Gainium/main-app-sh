# 199 — Plan: keep a call's minute prices for the call

## Solution

- `prices()` creates `have` (mid key → mid). `minutesNeeded` records every
  cached hit into it; `readCandles` → `readWindow` → `setMid` records every
  minute stored. The lookup reads `have` first, `midCached` otherwise (§4.1).
- `setMid` deletes then re-sets its key (so a re-stored minute moves to the
  newest end), and at `MID_CACHE_MAX` deletes keys in insertion order down to
  `MID_CACHE_LOW` (150k) — the same oldest-first pattern the `days` memo uses
  (§4.2).
- No tier of legacy extraction: the class is already a small singleton with
  pure helpers in `bot/feeAssetPrice.ts`.

## Blast Radius

1. Call sites: `prices`/`priceOne`/`warm` are used by `tradingCosts.handler.ts`
   only; their signatures and return shapes are unchanged. `setMid`,
   `readCandles`, `readWindow`, `minutesNeeded` are private, with an optional
   new argument.
2. Under `core/` (main-app-sh): shared, deployed with main-app; the parent's
   submodule pointer must be bumped.
3. No GraphQL/REST/socket/queue/collection shape changes. The values returned
   change only from unknown to a number (§1.3).
4. Tests that must stay green: `feeAssetPrices.spec.ts`,
   `tradingCosts.handler.spec.ts`.
