# 066 — Plan

Spec: [`specs/066.the-grid-extended-preset-omits-most-grid-settings.md`](../specs/066.the-grid-extended-preset-omits-most-grid-settings.md)

## §1 Solution

Name in `GRID_BOT_EXTENDED_FIELDS` (`src/server/v2/fieldConfig.ts`) the 23
`GRID_FORM_DEFAULTS` settings that are currently unreadable, as
`settings.<key>`.

23, not 25: `updatedBudget` and `newProfit` are `GRID_EXCLUDED_FIELDS`, which
`validateCommonSchema` answers with `Field <name> is not supported` (spec
§2.4). Returning them would turn the naive read-modify-create body into a 400 —
the opposite of the spec's §1.1. Neither the `bots.dca` nor the `bots.grid`
preset names an excluded field today; this keeps that invariant.

### §1.1 Why the list stays explicit

The spec's §3 names the root cause as the preset never being **tied** to
`GRID_FORM_DEFAULTS`. Deriving the list at runtime
(`Object.keys(GRID_FORM_DEFAULTS).filter(...)`) would tie them structurally,
but it changes `GRID_BOT_EXTENDED_FIELDS` from an `as const` tuple to
`string[]`, makes `fieldConfig.ts` import from `validators/bots/config.ts`, and
does it on the public `/api/v2` contract in a shared `core/`. The tie is
instead made by the **test**: §2's coverage assertion fails the build the
moment a key is added to `GRID_FORM_DEFAULTS` without being added here or to
`GRID_EXCLUDED_FIELDS`. Same guarantee, no type or import change, and it
matches the idiom of every other preset in the file.

### §1.2 Not a new helper

No utility is added. `parseFieldsParam` / `buildProjection` / `filterFields`
already do the whole job; the defect is data in a list they read.

## §3 Blast radius

1. **Other call sites.** `GRID_BOT_EXTENDED_FIELDS` is read only through
   `getFieldConfig`/`parseFieldsParam`. Its two consumers are
   `GET /api/v2/bots/grid` (binds `bots.grid` at registration) and
   `GET /api/v2/bots/:botType/details` (re-resolves per request via
   `endpointForBotType`). Both are fixed by the same edit; asserted in §2.
2. **`core/` submodule.** Yes — `fieldConfig.ts` is in `main-app-sh`, shared
   and deployed platform-wide (root Danger List #11). Parent pointer bump is
   deliberate.
3. **Owned contract.** `/api/v2/*` is the public `api.gainium.io` contract
   (Danger List #2), consumed by both dashboards, `gainium-mcp`,
   `n8n-nodes-gainium` and `chrome-extension`. The change is **purely
   additive**: no name removed, none renamed, and a caller on
   `fields=extended` receives a superset. No consumer can break on a field it
   did not previously receive. `fields=full` and explicit comma-separated
   lists bypass the preset table entirely.
   `src/server/v2/openapi-v2.yaml` documents the preset's contents in prose and
   is updated in the same change.
4. **Other tests on this path.** `gridFieldProjection.spec.ts` (specs 061/062)
   and `botDetailsFieldPreset.spec.ts` (spec 063, including its §4.3
   "removes no field the caller gets today" guard) — both must stay green.

## §4 Legacy tier

Tier 0. The causal path is a `const` array read by two pure functions
(`parseFieldsParam`, `buildProjection`) that already have no I/O. There is no
decision-logic-mixed-with-I/O to extract.
