# Plan 232 — A grid close on a key that may not cancel closes silently

Spec: `specs/232.grid-close-on-a-key-that-cannot-cancel-closes-silently.md`.

## Solution

1. `authGuard.ts` — pure predicate `isKeyPermissionRefusal(reason)`: the reason
   contains `permission denied`, or is a dead credential (`isHardAuthFailure`).
   It sits beside `isVenueLockout` and reuses the dead-key list, so the two
   lists cannot drift apart.
2. `main.ts` — `cancelOrderOnExchange`'s generic refusal branch (reached by every
   refusal that is not unknown-order, cancel-in-progress or a spec `180`
   teardown) calls a new protected hook `noteCancelRefused(order, reason)`. In
   the base class it does nothing, so DCA / Combo are unchanged.
3. `helper.ts` (grid) — overrides the hook: the first key refusal of the
   running sweep is kept on `sweepKeyRefusal`. `cancelAllOrder` skips every
   later order once it is set, and returns the refusal. `stop()` and
   `processSellAtStop()` pass it to `reportCloseCancelRefused`, which sends one
   `error` bot message through the existing `reportUserRefusal` (shown,
   bypassing subType classification) and lists the exchange order ids still
   `NEW` / `PARTIALLY_FILLED`.
4. `userNotice.ts` — the message text, beside the other user notices. It avoids
   the `errorDict` phrases ("was left open on the exchange", "still open").

Companion (paired, `exchange-connector` core): Kraken spot key verification
also probes "Query open orders" (a read of open orders) and "Cancel & close
orders" (a cancel aimed at a fresh random `cl_ord_id`, which no order carries).
It rejects the key only on a definite `EGeneral:Permission denied`, like the
WebSocket-permission probe beside it.

JIT tier: 0 for the sweep loop (one guard added in place), 1 for the predicate
(own named, tested function). No extraction of `stop()`.

## Blast Radius

1. Call sites: grid `cancelAllOrder` is called from `start()`, the stop-and-sell
   paths, `stop()` and `processSellAtStop()`. The halt applies to all of them
   (a key that may not cancel refuses in every one); only the two close paths
   send the message. The return type widens from `void` to `string | void`;
   every caller ignores it or is updated. DCA / Combo have their own
   `cancelAllOrder` and do not override the hook.
2. Under `core/` — shared by every main-app process (bot workers). Parent
   `BotHelper.stop()` only delegates to this one.
3. No contract changes: no GraphQL / REST / socket names. The bot message uses
   the existing `botmessages` row shape and `bot message` emit.
4. Existing tests on this path: `closeCancelRefused`, `teardownCancelRateLimit`,
   `closedDealCancelLockoutRetry`, `grid*.spec.ts` — all green.
