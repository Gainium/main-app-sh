Spec: `specs/129.restore-recomputes-a-settled-base-entry-average.md`.

## Build order

1. Harness `src/bot/dca/restoreSettledBaseAverage.harness.spec.ts`, driven
   over the real `restoreWork` and `getAvgPrice` with the production
   quantities. Red: the restore keeps 0.06849175515684121 and a user start

2. `dcaHelper.restoreSettledBaseEntryAverage(d)`, a private method placed

## Decisions the spec left open

- **Trigger:** a `dealStart` row in memory that is `CANCELED` with a fill.
  This is the defect class, and 128 §4.2 already counts these rows. A
  `FILLED` + `CANCELED` mix (spec 057 top-up) also qualifies, because the
  pre-128 average left out the cancelled part there too.
- **Equality:** exact. The recompute is the value the next fill would write.
  Only a bit-identical stored value is skipped.
- **Usage/size:** `updateUsage(dealId, false, false, false)`. `size` is
  derived from the new average, and `sendAlert=false` keeps a restore from
  firing the 80%/100% usage alerts.
- **Split deals (`parent`):** skipped. Their base row is the parent's, and
  `findBaseOrderByDeal` already treats them separately.

## Blast Radius

- `core/` is the `main-app-sh` submodule. The change is a private method on
  the DCA helper and one call site in `restoreWork`. No type, schema,
  GraphQL, socket or Redis contract changes.
- Combo overrides `restoreWork`, so it is unaffected (spec §5).
- Runtime cost: on every restore, per open deal, one in-memory filter of the
  deal's order rows. A Mongo read (indexed `botId`/`dealId`) happens only
  for a deal whose map has no base row with a fill at all. Deals with a
  `FILLED` base row never read (pinned by §4.3 test).
- Writes: deal docs only (`avgPrice`, `displayAvg`, `settings.avgPrice`,
  `usage`, `size`, `cost`, `value`), and only for deals in the defect class.
  The 12 production deals already within 0.015% get their canonical value.
- Orders: none sent or cancelled by this step (pinned by §4.4 and by
  `tpBurstInvariant`, which now runs the real method).
