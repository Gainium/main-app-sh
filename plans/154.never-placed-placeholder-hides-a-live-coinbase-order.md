# 154 — plan

## Solution

JIT tier 1: add one named helper on `MainBot` instead of extracting the legacy
methods.

- `adoptExchangeOrderId(order, venueOrderId)` records a real venue id onto a
  `'-1'` row: in memory if the row is in the map, and in the DB.
- `resolveNeverPlacedOrder(order)` is Coinbase only. It lists open orders for
  `order.symbol` and matches on `clientOrderId`, then adopts on a hit. It
  returns `ok(found: boolean)` or the lookup's `notok`.

Wiring:

1. `dcaHelper` restart reconcile, TP/SL and regular "not changed" branches,
   plus `checkOrdersAfterReconnect`'s "not changed" branch: call
   `adoptExchangeOrderId(o, merged.orderId)` (§4.1).
2. `cancelOrderOnExchange`, for Coinbase with a `'-1'` id: call
   `resolveNeverPlacedOrder` first.
   - Found: the real id is now on `order`, so `sendCancel()` addresses it
     (§4.2).
   - Lookup failed: `request` becomes a failure that names the lookup. It
     matches no `unknownOrderMessages` entry, so it lands in `handleErrors`
     (§4.3), and the teardown rate retry is skipped for it.
   - Not found: unchanged spec 011 path (§4.4).
3. `_runUnknownOrderLadder`, in the `byId` block: if the local row is `'-1'`
   on Coinbase, resolve first.
   - Found: `id` is now the real id and `neverReachedExchange` is false.
   - Lookup failed: build a non-definitive failure, so the ordinary retry
     ladder runs instead of the fast path.
   - (§4.5)

## Blast radius

- Code is under `core/`, which is `main-app-sh`, public and platform-wide. Its
  only consumer is main-app's bot workers (DCA/Combo/Grid all extend
  `MainBot`). The submodule pointer must be bumped.
- No GraphQL, socket or queue contract changes. It writes `orderId` on an
  `orders` row, which is a field it already writes.
- The venue cost is one extra `open/all` call per `'-1'` cancel or ladder entry
  on Coinbase only. Prod volume measured over the archived DCA logs since
  2026-10-06 is 16 ladder entries for `no exchange order id` across all
  venues, so this is negligible. That keeps #671's cost goal.
- Existing tests on this path: `cancelNoExchangeOrderId.spec.ts` (spec 011).
  Its fake exchange gains a `getAllOpenOrders` that returns no orders, which
  is the §4.4 world. Its assertions are unchanged.
- Other tests touching the ladder and cancel are the `cancelBatch`,
  `cancelPendingKraken` and `unknownOrder*` specs. All must stay green.
