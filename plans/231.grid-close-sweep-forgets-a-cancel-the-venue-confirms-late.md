# Plan 231 — a grid close sweep forgets a cancel the venue confirms late

Spec: `specs/231.grid-close-sweep-forgets-a-cancel-the-venue-confirms-late.md`.

## Build order

1. `src/bot/main.ts` `cancelOrderOnExchange`: read the map's copy once the
   answer is in (`heldWhenAnswered`, shared with spec 220's `known`). Skip the
   delete-on-zero when the answer still says `NEW`, the bot still holds the
   order as resting, and `keepsUnconfirmedCancelTracked(order)` says so.
   New hook `keepsUnconfirmedCancelTracked` returns `false` on the base bot.
2. `src/bot/helper.ts` (grid mixin): `closingSweep` flag and the override;
   `cancelAllOrder(cancelPartiallyFilled, setErrors, closing = false)` sets the
   flag for the loop, records answers of `NEW`, and after the loop cancels once
   more each one still held as resting (§4.2). Reset in `finally`.
3. Close callers pass `closing: true`: core `stop()`, `processSellAtStop`,
   `closeBotByTp` stop-and-sell, AND the parent main-app `src/bot/helper.ts`
   `closeBotByTp` override (the grid workers run the parent's copy).
4. Test, CHANGELOG + version in core and in the parent.

## Decisions the spec left open

- Scope by an explicit `closing` argument, not `cancelIsTeardown`: for a grid,
  `blockPriceCheck` is never set (it is DCA-only), so that predicate is always
  false. `start`/`reloadBot` call `cancelAllOrder()` and must keep deleting —
  a ghost `NEW` there would read as a resting level and suppress its
  re-placement.
- One re-cancel, not a timed wait: the venue's answer to a second cancel is a
  statement of the order's state, not a guess about stream latency. Hyperliquid
  answers "already cancelled", which `unknownOrderMessages` routes to
  `_handleUnknownOrder` (venue lookup + row write).
- JIT tier 0: the change is two conditions and one loop in methods already on
  the path; nothing extracted.

## Blast radius

1. `cancelOrderOnExchange` has ~35 callers (DCA, combo, grid, GraphQL). The
   new branch is gated by the hook, which is `false` everywhere but a grid
   close sweep. DCA/combo have their own `cancelAllOrder` and never set it.
2. Under `core/` (main-app-sh): shared with every main-app deployment incl.
   self-hosted. No type, schema, event or queue change.
3. No cross-service contract touched (no GraphQL/REST/socket/queue/Mongo
   shape change).
4. Kept green: `cancelAnswerKeepsStreamFill` (220), `gridCloseDuringLadderPlacement`
   (215), `teardownCancelRateLimit` (134), `closeCancelRefused` (180),
   `gridVenueCancelReplace` (201), `gridTpCloseSingleShot` (189),
   `gridStopAndSellFlatPosition`, and the full core suite.
