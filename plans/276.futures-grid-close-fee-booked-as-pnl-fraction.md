## Contract decisions

- Same fee gate as `createTransaction` (`BotFlags.feeByAsset`), so a bot's
  close leg and its grid legs resolve fees the same way.
- Estimate uses `maker`, as every other grid leg does; the old code did too.
- Observed fee scaled by `qty / executedQty` only when the order executed
  more than it closed (a part close is passed its executed quantity).

## Blast radius

- Core `profitAfterPositionClosed` / `processLiquidationOrder` run for every
  futures grid close. Only the booked profit moves, down by the close fee.
- No order, schema, GraphQL, socket or REST shape changes.
- Coin-M: the close PnL keeps its existing `price × qty` unit; the fee is
  expressed in that same unit. The restatement skips coin-M bots.
