## Build order

1. `dca/positionReconcile.ts`: `restingTpPositionGoneMessage` — the existing
   `dealPositionGoneMessage` says the deal was closed and `tpCloseBlockedMessage`
   says the take profit was reached; neither is true here.
2. `dcaHelper.ts`: `restingTpPositionGoneBackoff` (`tpg`), a futures-`dealTP`
   branch in `placeOrdersHoldingDealLock` → `sendFuturesRestingTp` →
   `checkRefusedRestingTpPosition`.
3. `dca/restingTpPositionGone.harness.spec.ts`.

## Decisions

- Send with `returnError` so the reason reaches the caller, and replay the
  `sendOrderToExchange` tail's report (§4.5) rather than changing that shared
  tail for every bot type.
- No second reading before acting (unlike `reconcileDealPosition`): nothing is
  closed, and a wrong "no position" costs one skipped resend for 15 minutes.
- JIT tier: none — two new private methods next to `reconcileDealPosition`;
  the surrounding placement code is untouched.

## Blast radius

1. Call sites: only the plain `else` of the `toPlace` loop in
   `placeOrdersHoldingDealLock` is narrowed; the spot fee/adaptive branches
   and every other `sendGridToExchange` caller are unchanged. The parent
   main-app `DCABotHelper` does not override `placeOrdersHoldingDealLock`.
2. `core/` — shared engine code (DCA and combo bots, cloud and self-hosted).
3. No GraphQL, socket, queue or schema change. New `botevents` rows use the
   existing `Deal` event shape. New Redis keys `tpg:cd:<botId>:<dealId>`.
4. Other tests on this path: `canceledTpRestore`, `refusedCloseRestore`,
   `spentLadderReplace` (all green).
