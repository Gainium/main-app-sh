# 001 — Wire real mocha to the scattered hand-rolled unit specs

## Build order

1. Add devDependencies: `mocha`, `chai` (v4, to match `app`'s pinned
   major and avoid chai 5's ESM-only breaking change against this repo's
   CJS/ts-node setup), `@types/mocha`, `@types/chai`.
2. Convert each of the 10 spec files (§1) in place: replace the file's
   own `expect`/`check` helper with real `describe`/`it` blocks
   (`import { describe, it } from 'mocha'`, `import { expect } from
   'chai'`), one `it()` per original assertion, preserving every
   fixture, comment, and code path untouched. Drop the trailing
   `process.exit`/`failures` bookkeeping — mocha owns pass/fail now.
3. Add an npm `"test"` script and a `.mocharc` (or CLI flags) that runs
   `mocha` over `src/**/*.spec.ts` via `ts-node/register`, matching how
   `app`'s own `mocha:test` script is built (`tsc` type-check +
   `NODE_ENV=testing mocha -r ts-node/register 'glob'`).
4. Run `npm test` and diff the per-assertion pass count against the
   baseline (§4): every case that was PASS before must be green after: no
   silent drift from the JSON.stringify → deep-equal semantics change
   (§3.2). Fix any mismatch by adjusting that one assertion's comparison
   (e.g. `.to.equal()` on a derived boolean instead of `.to.deep.equal()`
   on a possibly-`undefined`-bearing object), not by changing the
   fixture or the module under test.
5. Add `.github/workflows/test.yml`: PR + push to `main`, Node 22 (this
   repo already builds and runs on Node 22 in prod scripts), `npm ci`,
   `npm test`.

## Contract decisions (§3.1)

mocha + chai devDeps added, pre-authorized by this task's brief. chai
pinned to `^4` — the repo's `tsconfig`/build is CommonJS via `ts-node`,
and chai 5 is ESM-only, which would break `require('chai')` under
`ts-node/register` without an unrelated module-system migration.

## Blast radius

1. **Other call sites.** None of the 10 files are imported by anything
   else (`grep -rl` for each filename outside itself returns nothing) —
   they are leaf test files, not modules other code depends on.
2. **`core/` submodule.** This repo (`main-app-sh`) has no
   `.gitmodules` — it *is* what `app` submodules as `core/`. `app`'s copy
   of these files (if any exist there under `core/`) is unaffected until
   `app` bumps its submodule pointer; that is that repo's own change, out
   of scope here.
3. **CLAUDE.md-documented contracts.** No API/queue/event shape changes —
   test-file, devDependency, and CI-file changes only. The modules under
   test (`dealRefPrice.ts`, `orderFee.ts`, etc.) are not touched.
4. **Other tests exercising this path.** None — these are the only tests
   for these modules today.
