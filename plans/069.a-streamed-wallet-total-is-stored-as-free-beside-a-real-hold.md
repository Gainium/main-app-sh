# Plan 069 — a streamed wallet total stored as `free` beside a real hold

Spec: `specs/069.a-streamed-wallet-total-is-stored-as-free-beside-a-real-hold.md`.

## Solution
`streamedFree(item, storedLocked)` joins the pure helpers in
`src/utils/balanceWrite.ts`. `processBalanceUpdate` reads the stored `locked` for
the total-only assets of an event in ONE query, then uses the helper for the
live event and for both write paths. Events where every item carries `locked`
make no extra read.

## Blast Radius
1. Only items WITHOUT `locked` change — today that is Kraken spot. Every other
   venue's stream path is byte-identical.
2. Staleness: `locked` still moves only on a REST refresh. A newly placed order
   changes no total, so its hold appears at the next refresh (as before). After a
   fill, `free` reads LOW until the refresh — the safe direction. Refreshing on
   order events is a possible follow-up, not part of this change.
3. Order of deployment with connector 1.22.2: either order is safe. This change
   alone is a no-op while stored `locked` is 0; the connector alone reintroduces
   §1.2, so ship this first or together.
4. API process only (`processBalanceUpdate` runs there); bot workers unaffected.
5. One extra indexed `balances` read per total-only event.
