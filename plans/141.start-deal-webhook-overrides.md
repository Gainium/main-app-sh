## Build order

1. Pure module `src/bot/signalDealOverrides.ts`: parse/validate (§2.2), price
   side check (§2.4.1), deal-settings patch (§2.3.1–2). No I/O.
2. `types.ts`: `SignalDealOverrides`, `DCADealsSchema.signalOverrides`.
   `src/db/schema.ts`: additive `signalOverrides` subdoc on the DCA and Combo
   deal schemas.
3. `src/bot/index.ts` `singleWebhookProcess`: parse on `startDeal`, answer 400
   with the reason, pass the overrides as the 4th `openDealBySignal` arg.
   Hedge bots forward unknown methods' args to both legs unchanged.
4. `dcaHelper`: `openDealBySignal` → `openNewDeal` → `openNewDealBody` →
   `placeBaseOrder` → `createDeal`, threaded explicitly as a trailing optional
   parameter. A per-symbol pending map was rejected because other
   `placeBaseOrder` callers could create a deal in between and pick it up.
   `signalOverridesRefusal` (§2.4.1–2) runs before risk/reward;
   `requestSignalBaseOrderSize` sets a `base`-scoped multiplier with
   `sizeSource: 'webhook'` after approval (§2.3.5).
   `getAggregatedSettings` honours fixed prices when `deal.signalOverrides`
   records them (§2.3.4).
5. `comboHelper`: the same, through its own `openNewDeal` / `placeBaseOrder`
   / `createDeal`.
6. `newDealApproval.ts`: `sizeSource`, outcome `source` (set only for a
   webhook, so an extension's outcome keeps its shape), and the event text.

Decided here (left open by the spec): `slPerc` is stored negative, matching
the bot setting. Values are stored as strings, like the bot settings.

## Blast radius

- **`core/` is the public, platform-wide submodule.** The parent (cloud
  main-app) overrides `openNewDeal` for DCA and Combo, and must forward the
  new trailing argument.
- **Public webhook contract** (`/trade_signal`): additive optional fields
  only. Payloads without them behave exactly as before.
- **Shared Mongo deal collections:** additive field. Legacy readers ignore
  it.
- **Size multiplier path:** shared with approval hooks. Outcome shape is
  unchanged for extensions (covered by `newDealApproval.spec.ts`,
  `dca/newDealSize.harness.spec.ts`).
- Callers of `placeBaseOrder` / `createDeal` outside the open path pass no
  overrides (trailing optional), so they are unaffected.
