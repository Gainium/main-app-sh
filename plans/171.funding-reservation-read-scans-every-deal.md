# 171 — Plan: scope the funding-reservation read to the account owner

Spec: `specs/171.funding-reservation-read-scans-every-deal.md`.

## Build order

1. `FundingReservation.reservedQuote/reservedBase(userId, exchangeUUID, asset,
   fresh)`. `userId` is the first, required argument, so every caller fails to
   compile until it passes the owner. The read adds `userId` to the deals
   filter. A missing owner answers 0 without querying (§4.3).
2. Callers pass the owner:
   - `dcaHelper.reservedFundingQuote/Base` pass `this.userId`. This covers
     DCA, combo and hedge legs, since combo calls the same methods.
   - `previewFunding` / `previewHedgeFunding` pass the session `userId`.
3. Bump the core and parent versions, write changelogs, and bump the parent's
   core pointer.

## Contract decisions left open by the spec

- Parameter order: owner first and required, not a trailing optional. A
  trailing optional would compile at an unchanged call site and silently
  keep the full scan.
- Cache key: unchanged (`side:exchangeUUID@asset`). An account has one
  owner, so the key needs no `userId`, and `invalidate()` keeps its
  signature and its five callers.

## JIT tier

Tier 0. `fundingReservation.ts` is already a separate, tested module; only
its query changes.

## Blast Radius

1. Call sites: `grep -rn "\.reservedQuote(\|\.reservedBase("` finds 2 in
   `dcaHelper.ts`, 2 in `funding.handler.ts`, and test harnesses in
   `baseFundingHedge.harness.spec.ts` / `.review2.spec.ts`. All are updated.
   Prototype stubs in `funding.handler.spec.ts` ignore their arguments.
   The parent repo has no callers.
2. `core/`: yes. This is shared code (cloud and self-hosted), but the change
   is internal to the bot engine. No exported type, GraphQL field, event or
   queue changes.
3. Shared collections: read-only, with the same filter plus `userId`. No
   schema or index change, no DDL. The query uses the existing
   `userId_1_status_1_createTime_-1` index (`dcadeals`) and `userId_1`
   index (`combodeals`).
4. Tests that must stay green: the new `fundingReservation.spec.ts`,
   `funding.handler.spec.ts`, `baseFunding*.spec.ts`,
   `dca/baseFunding*.spec.ts`, and the full core suite.
