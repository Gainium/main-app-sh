# Plan 251 — Binance PERCENT_PRICE re-send

## Change
- `priceBandReprice.ts`: new pure `isPriceBandRefusal(reason, isOrderPriceClass)`
  — true for the `Order price` class or a reason naming `PERCENT_PRICE`.
- `main.ts` `sendOrderToExchange`: the re-send gate calls it instead of
  comparing the subType alone. JIT tier 2 (pure helper beside the existing
  pure re-price helpers); nothing else in the method moves.

## Decisions the spec left open
- Gate on the filter name, not reclassification. Mapping `PERCENT_PRICE` to
  `Order price` in `errorDict` would not reach prod (the DB `filter failure`
  rule wins first) and would change the recorded/behaviour class of the
  refusal on installs without DB rules; the gate change works on both.
- The `handleErrors` early return on `PERCENT_PRICE` stays: the second-refusal
  report goes through `processError`, which has no such filter, and a first
  refusal that is re-sent should stay quiet.

## Blast radius
1. Gate has one call site (`sendOrderToExchange`). `isPriceBandRefusal` is new.
2. `core/` (main-app-sh) — shared by every main-app bot worker; no type,
   schema, GraphQL, socket or queue change.
3. No cross-service contract touched.
4. Must stay green: `priceBandReprice.spec.ts`, the full core mocha suite.
