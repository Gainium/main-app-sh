# Plan 002 — krakenUsdm TP remainder recovery

Spec: `specs/002.krakenusdm-tp-remainder-recovery.md`

## Build order

1. Extract the two decision predicates the spec's Assumption names into a new
   pure module, `src/bot/reduceOnlyRemainder.ts`:
   - `canRecoverReduceOnlyRemainder(exchange, order)` — replaces
     `buyRemainder`'s blanket `if (order.reduceOnly) return order` bail with
     "bail unless this is a krakenUsdm MARKET order."
   - `isKrakenUsdmUnderfilledReduceOnlyClose(exchange, order)` — the new OR
     branch for the `sendOrderToExchange` hook, detecting krakenUsdm's
     terminal FILLED-with-shortfall shape the way the existing bybit branch
     detects its CANCELED-with-partial-fill shape.
   (Already done, ahead of this plan being written, as gate 1/2 groundwork —
   see traceability table.)
2. Wire `canRecoverReduceOnlyRemainder` into `buyRemainder`
   (`src/bot/main.ts:5041-5043`): only bail on `order.reduceOnly` when the
   predicate is false.
3. Wire `isKrakenUsdmUnderfilledReduceOnlyClose` into the `sendOrderToExchange`
   hook (`src/bot/main.ts:7436-7442`): OR it into the existing bybit
   condition so a krakenUsdm shortfall also routes through
   `fillPartiallyFilledOrder` before the function returns.
4. Run the full suite (gate 6); confirm no other spec regresses.
5. Version bump + changelog entry (this repo's release ceremony — versioned
   images depend on it downstream), matching the style of `11f7a7d`/`bf13d3d`
   in `CHANGELOG.md`.

No sequencing dependency between steps 2 and 3 — they touch disjoint lines —
but both are required together: step 2 alone still leaves the synchronous
`closeDealById` path (`dcaHelper.ts:6016-6018`) reading the raw, unrecovered
order (spec Actual/§2); step 3 alone has nothing to route through, since
`buyRemainder` would still bail immediately once it got there.

## Contract decisions the spec left open

- **Predicate boundary.** The spec's Assumption fixes *what* to detect
  (krakenUsdm + MARKET + reduceOnly, order-based diff, no position lookup)
  but not how to express it in code. Decision: two separate small predicates
  rather than one shared one, because they answer different questions at
  different call sites (one is a bail-skip test on an order already known to
  be `reduceOnly`; the other independently establishes reduceOnly-ness *and*
  the FILLED-with-shortfall shape from a raw response) — collapsing them
  would couple two call sites that may legitimately diverge later (e.g. if a
  second krakenUsdm order type ever needs the bail-skip but not the
  shortfall-shape check).
- **Where the new module lives.** `src/bot/reduceOnlyRemainder.ts` (repo
  root of `src/bot/`, alongside `orderFee.ts`/`retryBackoff.ts`), not under
  `src/bot/dca/` — `partialTp.ts` lives there because it's genuinely
  DCA-scoped (deal-close logic in `dcaHelper.ts`), whereas this fix is
  entirely inside `main.ts`, the class both grid and DCA bots inherit from.

## Blast radius

1. **Other call sites.** `buyRemainder` is `private` to `MainBot`
   (`main.ts`) and reachable only through `fillPartiallyFilledOrder`
   (`main.ts:5183`), which itself has exactly two callers, both in
   `main.ts`: the WS-driven order-status consumer (`:5348`, unconditional,
   untouched by this change) and the `sendOrderToExchange` hook (`:7445`,
   the one being widened). Grepped and confirmed — no other file calls
   either function. `dcaHelper.ts:6016-6018`'s direct
   `processFilledOrder(result)` call is *not* being touched directly; it is
   covered because `result` (from `sendGridToExchange` →
   `sendOrderToExchange`) will already reflect the recovery by the time it
   gets there.
2. **`core/` submodule.** N/A — this repo (`app-sh`) has no `core/`
   submodule; `main.ts`/`dcaHelper.ts` are local, deployed-from-here files.
3. **Cross-service contracts.** None. No API/queue/event shape changes —
   this only changes when an existing internal method (`buyRemainder`)
   recurses and when an existing internal hook fires. No new fields on
   `Order`/`Grid`.
4. **Other tests that must stay green.**
   - `src/bot/dca/partialTp.spec.ts` — unrelated predicate, but exercises
     adjacent domain logic (underfilled TPs); must not regress.
   - Every other `*.spec.ts` under `src/bot/` (`orderFee`, `retryBackoff`-
     adjacent, `dealRefPrice`, `dealOutcome`, `baseOrderQty`, `tpFees`,
     `quantRulesRetry`) — none reference `buyRemainder` or
     `sendOrderToExchange`, so they are a regression check on the suite
     runner, not on this change's logic.
   - No test exists today that exercises `buyRemainder`/`sendOrderToExchange`
     end-to-end (they are deep inside a stateful class with DB/exchange
     dependencies) — this is why the fix is expressed as two pure,
     independently-tested predicates rather than a class-level integration
     test. This is a Tier 1 JIT extraction (pulled into its own tested
     module, still infra-adjacent by name/purpose) — not Tier 2/3, because
     going further (e.g. actually injecting the venue call as a port) is a
     bigger modernization than this bug fix's causal path justifies.
