# Plan 209 — refresh confirms unchanged balances

Spec: `specs/209.refresh-leaves-unchanged-balances-unconfirmed.md`.

## Solution
Tier 0 on the surrounding legacy code: one `balanceDb.updateManyData(
{ userId, exchangeUUID }, { $set: { updated: new Date() } })` at the end of the
successful branch of `refreshExchange` in `updateUserBalance`. `updateUserBalance`
is exported (named) so the test can drive it with a fake `ExchangeChooser`.

## Blast Radius
1. Callers: on-demand `updateBalance` mutation (via `userSnapshots`), the daily
   snapshot cron, `connectUserBalance`, the Coinbase/Hyperliquid/Bitget timers,
   the shared-wallet leg refresh and the hold refresh. All gain the stamp; none
   reads `updated` back.
2. Under `core/` (main-app-sh): runs in the API process; bot workers do not run
   this path. Pointer bump needed.
3. Contracts: no schema or GraphQL shape change. `balances.updated` readers:
   `getBalances` (dashboard marker), automations balance source/leaf (30-min
   staleness) — both want "last confirmed". Legacy readers of `balances` read
   amounts only.
4. Cost: one indexed (`userId, exchangeUUID, asset`) `updateMany` per refreshed
   connection; the per-asset loop is unchanged.
5. Tests: `tests/balanceUpdatedOnRefresh.ts`.
