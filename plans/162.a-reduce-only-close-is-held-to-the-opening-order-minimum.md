# 162 — plan: let a reduce-only close under the venue's order-value minimum through

Spec: [162](../specs/162.a-reduce-only-close-is-held-to-the-opening-order-minimum.md).

## Solution

Root cause per spec §3: the four remainder-close checks compare the
remainder's value against `quoteAsset.minAmount` directly. They read it
through one pure function instead,

```ts
closeOrderQuoteMinimum(exchange, hedge, quoteMinAmount): number
```

in `src/bot/closeOrderMinValue.ts`, which answers `0` for the venues and
position modes in spec §1.1 and `quoteMinAmount` unchanged for everything
else (§1.3). The base-quantity checks and the zero/step guards beside them
are not touched.

JIT tier 2: the venue rule is plain data over the exchange and the position
mode, with no I/O, so it goes fully pure, next to its siblings
`remainderFill.ts` (`isBelowVenueMinOrderValue`) and
`reduceOnlyRemainder.ts`, which follow the same shape — an allowlist of
venues established by measurement, documented in the function's comment.
The four call sites stay where they are (tier 0 for the rest of each method).

Contract decisions the spec left open:

- **Keyed on the bot's exchange and `this.hedge`**, not on the order's
  `reduceOnly` flag: every one of the four sends is reduce-only on futures
  (`sellRemainder` sets `reduceOnly: true`, `closeRemainderByLimit` sets
  `!!this.futures`, both `closeDeal` checks send through `sellRemainder`), and
  `hedge` is what decides the order's `positionSide` on the way out.
- **Paper venues follow their live venue** (§1.1), so the predicate lists
  `paperBybitLinear`, `paperBinanceUsdm`, `paperBitgetUsdm`.
- Coin-margined and spot enums are simply absent from the allowlist (§1.3) —
  no `coinm`/`futures` flag is consulted, so the existing coin-M meaning of
  `quoteAsset.minAmount` (contract size) cannot be reached.

## Build order

1. `main-app-sh` (this repo): predicate + call sites + specs, release patch.
2. `main-app` parent: bump the `core/` pointer, release patch.
3. Only after this is deployed: `exchange-connector-sh` spec 036 (Bybit
   linear reports `minNotionalValue`) may merge and ship.

## Blast Radius

1. **Call sites.** `quoteAsset.minAmount` is read in ~60 places; this change
   touches exactly the four close checks of spec §1.2 in `dcaHelper.ts`
   (`closeDeal` ×2, `closeRemainderByLimit`, `sellRemainder`). Combo bots
   inherit them from `DCABotHelper`; grid bots do not use them. Every other
   reader — opening sizing, `getTPOrder`/`prepareTpOrder` (already skip the
   quote minimum on futures), `reduceDealFunds`, the multi-TP/SL fold,
   `checkTpCoverage` — is unchanged.
2. **Under `core/`** — the public `main-app-sh` submodule, deployed in every
   bot worker (DCA, Combo, hedge variants) on cloud and self-hosted.
3. **Contracts.** No GraphQL/REST/socket/queue/collection shape changes. The
   only behaviour change: on the §1.1 venues, a remainder under the
   order-value minimum is now sent to the venue as a reduce-only order
   instead of being left. Bybit linear reports 0 today, so it changes nothing
   there until spec 036 ships; Binance USDⓈ-M and Bitget USDT-M (hedge) report
   their minimum today, so this is live for them on deploy.
4. **Tests** that exercise these paths and must stay green:
   `limitOnlyCloseRemainder.spec.ts` (157), `zeroSizeOrderRefusal.spec.ts`
   (084), `lateEntryFillAfterClose.spec.ts` (112),
   `dca/lostLedgerClose.harness.spec.ts`, `dca/phantomFillLedger.harness.spec.ts`,
   and the full suite.

## Failure mode if a venue rule is wrong

A remainder the venue in fact refuses is reported through the existing
refusal handling of each send (the same path any refused close takes today),
not silently dropped; the remainder is no worse off than when it was never
sent. The opposite error — the status quo — is silent.
