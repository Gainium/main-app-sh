## Decisions left open by the spec

- **Opt-in flag, not a global change.** Other callers of `updateDealBalances`
  (restore without service restart, `addDealFunds`, settings update, combo
  `getTPOrder`) keep today's behaviour. Changing them would alter combo
  take-profit sizing while a fill is in flight, which §4.1 rules out.
- **The delta stays.** `updateDealBalances` does nothing when the deal has no
  base order on record, so the existing delta remains the fallback there.
- JIT tier 0: the fix is two call-site lines and one filter. Nothing on the
  path is extracted.

## Blast Radius

1. Call sites: `updateDealBalances` has six DCA and three combo callers; only
   the add-funds branch passes the new flag. `updateDeal`'s add-funds branch
   is the only path changed.
2. `core/` is the shared `main-app-sh` submodule: the parent's pointer must be
   bumped. The DCA and combo bot workers run this code.
3. No GraphQL, socket, queue or schema shape changes. The deal fields written
   are the same (`initialBalances`, `currentBalances`, `levels`).
4. Tests on the path that must stay green: `lostLedgerClose.harness.spec.ts`
   (ROA ledger at close), `trailingTpRebase.harness.spec.ts` (saveDeal copy
   writes), `baseEntryRemainder.harness.spec.ts` (spec 111),
   `addFundsLadderSlot.harness.spec.ts`; full `npm test`.
