# Plan 046 — The stuck-start sweep cannot reach a deal the worker has forgotten

Implements [`specs/046`](../specs/046.the-stuck-start-sweep-cannot-reach-a-deal-the-worker-has-forgotten.md).

## Solution

Fixes the cause named in spec §3.2: `closeDealById`'s `!findDeal` branch never
consults the database. It gains one narrow, DB-backed escape hatch before the
existing read-only report.

## Build order

1. **`src/bot/dca/strandedStartClose.ts`** (new, pure). `isRetirableStrandedStart`
   — spec §4.1 — plus `STRANDED_START_GRACE_MS`. Reuses `NO_EXCHANGE_ORDER_ID`
   and `executedFillQty` from `dca/executedFill.ts` (spec `029`); no new
   order-shape helper is written.
2. **`src/bot/dca/dealOutcome.ts`** — `strandedStartCancelMessage`, beside
   `unactionedCloseMessage`, which is where the wording for this branch already
   lives.
3. **`src/bot/dcaHelper.ts`** — `retireStrandedStartDeal`, placed immediately
   after `reportUnactionedClose`'s body and before the `processDealClose`
   JSDoc + `@IdMute`, so no decorator rebinds. Called from the `!findDeal`
   branch; on `false` the existing `reportUnactionedClose` runs unchanged.
4. **`src/bot/dca/unactionedClose.harness.spec.ts`** — extended (see §Tests).

## Contract decisions the spec left open

- **Which DAO for the order rows.** `this.ordersDb` (`MainBot#ordersDb =
  orderDb`), the same one `_loadOrders` uses. Projected to the five fields the
  predicate reads.
- **Write shape.** `dealsDb.updateData({_id, status: start}, {$set: …}, true)` —
  `returnDoc: true` so a no-match (`data: null`) is distinguishable, and the bot
  event is written only when a document actually changed.
- **`closeTrigger` when the caller passed none.** `DCACloseTriggerEnum.auto` —
  the sweep is the realistic caller and it is the honest attribution; nothing
  read this field on these deals before, so there is no prior value to preserve.

## Blast Radius

1. **Other call sites.** The changed line is inside `closeDealById`'s `!findDeal`
   branch only; every other path through the method is untouched. 22 call sites
   of `closeDealById` exist, all of which reach this branch only when the deal is
   missing from the map. `retireStrandedStartDeal` and
   `isRetirableStrandedStart` are new and have exactly one caller each.
2. **`core/` submodule.** Yes — this is `main-app-sh`, shared and deployed
   platform-wide. The new module is additive; `dealOutcome.ts` gains an export;
   `dcaHelper.ts` gains a method and one branch. No exported signature changes,
   so no consuming service can break at the type level.
3. **Owned contracts** (root `CLAUDE.md` Danger List). None touched: no GraphQL
   shape, no REST shape, no socket.io event name, no queue name. The change
   writes two existing Mongo collections (`dcadeals`, `botevents`) with fields
   those collections already carry — `saveDeal`/`processDealClose` write the same
   ones on the ordinary close path. Nothing is added to a schema, so the legacy
   `main-dash` and `admin-app` readers see a deal in a state they already handle
   (`canceled`).
4. **Other tests on this path.** `dca/unactionedClose.harness.spec.ts`
   (spec `030`) is the direct neighbour — its `§5.3 the branch never writes`
   case is narrowed by spec `046` §4.3 and must be re-expressed, not deleted.
   `dca/executedFill.spec.ts`, `dca/unbuiltBaseEntry.harness.spec.ts` and
   `dca/dealOutcome.spec.ts` exercise the helpers reused here and must stay
   green.

## Legacy tier (Part 4 of the dev-flow skill)

**Tier 1.** The decision is extracted into its own pure, tested module; the I/O
around it stays in `dcaHelper` beside the sibling `reportUnactionedClose`, in the
same shape spec `030` established three weeks ago. Tier 2/3 would mean pulling
`closeDealById`'s database access behind a port — a 22k-line-class refactor that
this bug does not justify and that would obscure the diff the operator has to
review.
