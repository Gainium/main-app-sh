# Plan 117 — neutral grid TP/SL on the close entry

Spec: `specs/117.a-neutral-grid-tp-sl-values-the-position-against-the-close-entry.md`.

## Solution

1. `closeEntryPrice()` is split: the ledger read + unpaired-fills netting move
   verbatim into `readUnpairedEntry(position, closeOrderId, fill?)`, which
   returns `{ entry }` or `{ fallback: <the same warn text> }`. `closeEntryPrice()`
   keeps its gate, its log lines and its return values exactly (spec 099 is
   unchanged; its suite stays green). The optional `fill` replaces its own
   ledger row, since the triggering fill's FILLED write is not awaited before
   `processFilledOrder` runs.
2. `tpSlEntryPrice(position)` — synchronous, used by `tpSl()` for futures:
   `position.price` when flat or when `closeEntryPrice()` would not depart from
   it (COIN-M / non-neutral); the cached entry when it was computed for this
   exact `(side, qty, price)`; otherwise `position.price` and one refresh is
   started from the tick (deduped while one is pending).
3. `refreshTpSlEntry(fill?)` — only for neutral non-COIN-M futures grids with a
   value-changed TP or SL; chained on one promise so the last to finish is the
   last started; caches `{ ...position, entry }` (entry = `position.price` on
   any fallback, so a non-reconciling ledger is not re-read per tick).
4. `processFilledOrder` chains `refreshTpSlEntry(order)` onto the
   `createTransaction(order)` promise, i.e. after the round trip that decides
   the unpaired set is in the ledger (and `profit.total` updated with it).

JIT tier: Tier 1 — the ledger netting becomes its own named method, still
DB-coupled; going pure would mean moving 099's code further than this bug
needs.

## Blast Radius

1. Call sites: `closeEntryPrice` — `profitAfterPositionClosed`,
   `processLiquidationOrder` (behaviour unchanged). `tpSl` — core
   `closeBotByTp` and the parent `main-app/src/bot/helper.ts` override of
   `closeBotByTp`; both call it synchronously, signature unchanged.
2. `core/` (main-app-sh): shared by cloud and self-hosted main-app; no type,
   schema, event or queue shape changes. Pointer bump in the parent.
3. Contracts: none. One extra ledger read per fill, only for neutral futures
   grids with a value-changed TP/SL.
4. Tests that must stay green: `gridNeutralCloseBasis.spec.ts` (099),
   `gridPositionValue.spec.ts` (064), `gridTransactionProfitRace.spec.ts`
   (073), the whole core mocha suite.
